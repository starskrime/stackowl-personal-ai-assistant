Remember Once

The platform has no similarity check on any memory write. Four stores, four insert sites, and nothing between the agent and the row it is about to duplicate.

The control group

Curated memory — the 37 §-separated facts across 14 .md files — has zero duplicates by either exact or token-set matching. It is the one store a human deliberately curates. Every store the machine writes without a gate is duplicated; the one store with a gate, however manual, is clean. That is the whole thesis in one comparison.

What semantic duplication actually looks like here

Two reflections, cosine 0.945, both stored, both retrieved, both spending context:

A: Reflection on secretary task (stop): The agent's unbounded shell
   execution hung indefinitely, causing a timeout…

B: Reflection on secretary task (stop): The agent stalled because a
   shell command hung for over two minutes during…

No exact matcher will ever catch that pair. No token-set key will either — they share barely half their words. This is the class of duplicate that only a vector can see, and the vectors are already sitting in the rows.

Why it happens

Not one bug. A chain of four, each of which alone would be enough.

  1. 1
    Nothing checks before writing

    Each store has exactly one INSERT site, and not one of them consults an existing row first. The write path is: produce text → embed → insert. There is no step between.

  2. 2
    The deduplicator exists and has never run

    FactReinforcer — "increments reinforcement_count for similar staged facts", cosine threshold 0.75 — has zero callers anywhere in src/. It was built, and never wired to anything.

  3. 3
    And it could not have worked if it had been

    Its query requires embedding IS NOT NULL. Staged facts were embedded 0% of the time — 0 of 5,212. Two independent reasons for the same silence, which is why nothing ever surfaced it.

  4. 4
    So the counter that proves it stayed at zero

    reinforcement_count was 0 on all 5,212 rows. The schema anticipated reinforcement-instead-of-insert; the column has been sitting there recording that it never once happened.

A separate defect, found on the way

85% of staged facts were not facts. The incident RCA pipeline's own sub-agent system prompts — "You are the VERIFIER owl in a fixed-stage incident root-cause analysis…" — were being captured as source_type='conversation' and staged for learning. One of them appeared 1,505 times. Deduplication would have compressed that to one row; it would still have been the wrong row. A similarity gate is not a substitute for not writing rubbish.

The design space

Five mechanisms, ordered by cost. The useful observation is that they are not alternatives — they are a ladder, and the cheap rungs remove most of the volume before the expensive rung is reached.

Candidate gates
Mechanism Catches Cost per write Status here
Normalised hash Byte-identical after case/punctuation folding O(1), one indexed lookup Not built. Would have caught 66% of facts.
Canonical token set Same words, reordered or re-separated O(1), one indexed lookup Already shipped for skills as canonical_key()
SimHash / MinHash Near-identical wording, no model needed O(1) with banded buckets Not built. Useful as a prefilter.
Embedding cosine Same meaning, different words O(n) naive; O(log n) via ANN Vectors already stored on every row
Reinforce, don't insert — An UPDATE instead of an INSERT Columns exist; FactReinforcer unwired

The jump from 9,159 pairs to 87,585 across a 0.05 band is the signal: precision falls off a cliff below 0.90. But 0.90 is a hypothesis, not a finding — it needs a labelled sample before it becomes a constant, and the threshold almost certainly differs per store, because a reflection and a preference are not the same kind of text.

Recommendation

One gate, asked by every store. Not a deduplicator per store — that is four copies of one rule, and this codebase has paid for that shape repeatedly.

async def remember(store, candidate) -> Decision:
    # rung 1 — free, catches the 66% case
    if row := store.by_hash(normalised(candidate.text)):
        return Reinforce(row)

    # rung 2 — free, catches rearrangement. Already exists for skills.
    if row := store.by_canonical(canonical_key(candidate.text)):
        return Reinforce(row)

    # rung 3 — the only rung that needs a vector, reached by the minority
    if row := store.nearest(candidate.embedding, threshold=store.threshold):
        return Reinforce(row)

    return Insert(candidate)
  • It is a ladder, so it is cheap. Two-thirds of the volume never reaches the vector comparison. That is what makes it lightweight without giving up the semantic catch.
  • Reinforce is the action, not reject. A second sighting is evidence the thing matters. Bump the counter, refresh recency, keep the better-worded version — never silently drop. recall_ranker already reads reinforcement_count with a saturating 1 + k·ln(1 + n) boost, so the signal has a consumer waiting.
  • Four call sites. sqlite_bridge, lessons_store, reflection_store, preferences. Skills already have their gate and are the working precedent.
  • The threshold is configuration, per store, derived from a labelled sample — never a constant chosen because it looked reasonable.
  • Use the existing ANN index. LanceDB is already in the stack. A linear scan is fine at 5k rows and quietly stops being fine at 50k.
What this does not fix

Deduplication would have turned 1,505 copies of an RCA system prompt into one copy of an RCA system prompt. The upstream question — why the fact-staging path treats sub-agent conversation as material to learn from — is separate, and worth more than the gate.

Already done

  • All 5,212 staged facts deleted, per instruction, to rebuild from zero. None had ever been promoted (status='staged' on every row), nothing holds a foreign key to the table, and there are no triggers — so nothing downstream lost anything. A gzipped JSON of every deleted row is in the session scratchpad; it is reversible.
  • Skills already have this gate. canonical_key() plus reinforce-instead-of-mint shipped for the skill synthesizer on 2026-08-24, and it is the template the other four stores should follow rather than each inventing one.

Open questions

  • Reinforce or supersede? When the new phrasing is better than the stored one, does the gate keep the old text and bump a counter, or replace the text and keep the counter? These differ, and only one of them can be right.
  • Should the gate span stores? A preference and a fact can say the same thing. A cross-store check is strictly better and strictly more expensive.
  • What happens to the 22% already in lessons? The gate stops accumulation; it does not compact what is there. Compaction is a destructive migration and needs its own decision.
  • Where does the prompt-capture bug get fixed? Above the gate, in whatever decides that a sub-agent turn is worth learning from.
