# D01.6 Baseline — the before-picture

> **Captured:** 2026-07-25, live, after `./start.sh`
> **Provider:** NeraAiRaw (LiteLLM gateway), `neraai-v1-raw`, tiers fast/standard/powerful
> **Method:** Bakir sent 5 real Telegram messages in one conversation. One asked for web research.
> **Purpose:** the measured before-state that `D01.1` must improve on.

Session `72055773` — **5 user messages**:

| Measure | Value |
|---|---|
| LLM calls | **40** |
| Distinct system prompts | **10** |
| Input tokens | **180,712** |
| Cached input tokens | **0**, from **0 of 40** calls reporting |

## Metric 4 — prompt stability (the D01.1 pass/fail)

**FAIL, as expected. 10 distinct prompts in one conversation.**

Sharper than the item assumed: per-trace attribution shows **most single traces contain 2 distinct
prompt hashes**. The prompt does not merely change between turns — it changes **mid-turn, between
consecutive calls answering the same message**. That is the worst case for prefix caching, and it
means `D01.1`'s invariant must be asserted per *trace* as well as per *session*.

A useful control appeared unprompted: the scheduled `goal-owl_lifecycle-headhunter` and
`goal-owl_lifecycle-Brain` sessions show **1 distinct prompt across 10 and 6 calls**. The
machinery *can* produce a stable prompt. The interactive path is what destabilises it.

## Metric 1 — cache hit rate: NOT MEASURABLE on this deployment

`cached_input_tokens = 0` across all 40 calls, with `turns_reporting_cache = 0`.

Invariant I4 exists for exactly this: **0 with 0 reporting means the gateway does not report cache
statistics at all**, not that the cache is cold. NeraAiRaw returns no cache fields in any of the
three shapes the reader accepts.

**Consequence for `D01.1`:** we cannot prove the fix via cache hit rate on this deployment. It must
be proven with **prompt stability, input-token count, and cost per conversation** instead. Had the
report collapsed "0%" and "not reported" into one number, this would have read as "caching is
broken" and sent us chasing the wrong thing.

## Metrics 2 and 3 — TTFT and cost

887 ms average to first token. $2.85 for five messages.

## Attribution — where the 40 calls went, and a correction

First reading was that ~8 round-trips per message was tool-loop overhead. **That was wrong**, twice
over, and the data corrected it both times.

**Correction 1 — the research was real.** `web_fetch` ran 6 times. One message asked for internet
research, and a research turn legitimately needs many round-trips. This does not make `D01.1` less
valuable — it makes it *more* so, because a 9-call tool loop resending a ~10k-char prompt nine times
is precisely the workload prefix caching is designed for.

**Correction 2 — the expensive re-runs are the platform working correctly.** Nine traces appeared
for five messages; four carried a `-fix` suffix and accounted for **$2.05 of the $2.85**:

| trace | calls | prompts | input tokens | cost |
|---|---|---|---|---|
| `0161cbbc…` | 3 | 1 | 3,318 | $0.056 |
| `0161cbbc…-fix` | 9 | 2 | 73,686 | **$1.17** |
| `15760633…` | 3 | 1 | 2,698 | $0.043 |
| `15760633…-fix` | 6 | 2 | 40,890 | **$0.63** |
| `396fdd76…` | 5 | 2 | 31,573 | $0.50 |
| `396fdd76…-fix` | 4 | 2 | 15,991 | $0.24 |

`-fix` is minted by `pipeline/retry_actuator.py:112`. The log gives the trigger verbatim:

> `retry_actuator.run_corrective: entry` — correction: *"it cited sources/URLs but NO source was
> actually retrieved this turn — the citations are fabricated. Retrieve real sources…"*

**This is the grounding gate catching the model fabricating citations and forcing it to go and
retrieve real ones.** It is the trust/honesty machinery doing exactly its job. The 20× cost is the
price of not shipping hallucinated sources, and it is a price worth paying.

The lesson for this program: **an expensive path is not automatically a wasteful one.** A
cost-reduction item that had blindly suppressed the `-fix` path would have removed one of
StackOwl's genuine advantages over the reference platform — Hermes has no equivalent of the
acceptance/grounding veto.

## Two real defects surfaced along the way

Neither is a `D01.1` concern; both are recorded so they are not lost.

1. **Empty completions.** `[openai] complete: empty after think-strip — retrying once with a
   varied prompt`, followed by `still empty after varied retry — returning empty for the downstream
   floor`, occurred repeatedly. A reasoning model is spending its budget on reasoning and emitting
   no visible content. Every occurrence costs a full call and yields nothing.
2. **Dangling budget events.** The boot wiring audit reports `budget_80pct_alert` and
   `budget_exceeded` as subscribed with **no publisher** — so budget alerting can never fire. On a
   conversation that just cost $2.85, that is not academic.

## What D01.1 must achieve against this baseline

| Measure | Baseline | Target |
|---|---|---|
| Distinct prompts per session | 10 | **1** |
| Distinct prompts per trace | 2 | **1** |
| Input tokens, 5 messages | 180,712 | materially lower |
| Cost, 5 messages | $2.85 | materially lower |
| TTFT | 887 ms | lower — the window probe, embedding scoring and DB reads leave the critical path |
| Cache hit rate | not measurable here | unchanged as a proof method |

## Reproduce

```bash
./start.sh                      # restart; wait for "[telegram] adapter.receive: entry"
# send ~5 messages in one Telegram conversation
```

Then `/cost turns`, or:

```bash
uv run python -c "
import sqlite3, os
c = sqlite3.connect(os.path.expanduser('~/.stackowl/workspace/stackowl.db'))
for r in c.execute('''SELECT session_id, COUNT(*) turns, COUNT(DISTINCT prompt_hash) prompts,
                             SUM(input_tokens) inp, SUM(cached_input_tokens) cached,
                             SUM(CASE WHEN cached_input_tokens>0 THEN 1 ELSE 0 END) reporting,
                             ROUND(AVG(ttft_ms)) ttft, ROUND(SUM(cost_usd),4) cost
                      FROM cost_records WHERE session_id != '' GROUP BY session_id
                      ORDER BY turns DESC LIMIT 5'''):
    print(r)
"
```
