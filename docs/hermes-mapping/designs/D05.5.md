> **⚠ THIS ITEM CHANGES A SECURITY BOUNDARY.** It inverts a default-DENY
> allowlist that the package's own docstring called *"the highest-risk component
> in the E11 roadmap"*. That was an operator decision taken with the specific

> only in a commit message.

## The map's question, answered

The map asks: *"Walk the current `_ptc.py` together — is this already 80% there?"*

**The transport is ~100% there. The surface was 6.5%.**

| | StackOwl (before) | Hermes |
|---|---|---|
| Unix-domain socket, per-run | ✅ 0600, unlinked on teardown | ✅ |
| Generated in-sandbox stub | ✅ `import owl` | ✅ `hermes_tools.py` |
| Host-side enforcement | ✅ default-DENY, sandbox never trusted | ✅ |
| Bounds per call | ✅ owl ∩ creation_ceiling | — |
| Write-confinement | ✅ to the run's workspace | — |
| Rate limit + arg/frame caps | ✅ | — |
| Audit, sanitized errors | ✅ | — |
| **Callable tools** | **5 of 77** | **the whole enabled toolset** |

StackOwl's implementation was *stricter* than the reference on every axis except
the one that determines whether the feature does anything.

## Why it mattered — measured

From `task_outcomes`, 1,470 turns that called at least one tool:

| | |
|---|---|
| multi-call chains (2+) | **1,237 — 84%** |
| chains of 5+ calls | 810 |
| longest chain | **46 calls** |
| chains fitting the old 5-name allowlist | **256 — 20%** |

So PTC could collapse **a fifth** of the chains it was built to collapse.

The single largest blocker was **`web_fetch` — 4,102 appearances in chains**,
denied while its read-only sibling `web_search` was allowed. That asymmetry is
what made the narrow allowlist look accidental rather than principled.

## What changed

`PTC_ALLOWLIST` (5 names, default-DENY) → `PTC_DENYLIST` (7 names, default-ALLOW):

```
shell · execute_code · process · claude_code
delegate_task · sessions_spawn · sessions_send
```

**The denylist's meaning changed with it.** It is no longer a capability fence —
it is a **sandbox-escape fence**. Each entry is there because it would let code
break *out*: run host commands, nest another sandbox, control host processes,
launch an agent with host filesystem access, or bypass the delegation-depth
ceiling `E8-S0` enforces for the model's own calls.

The stub gained a generic `__getattr__`, so any non-denied tool is callable as
`owl.<tool>(**kwargs)`. Dunder names still raise `AttributeError` — otherwise
`import owl` and ordinary introspection (`copy`, `pickle`, pytest collection)
would each turn into an RPC call for `__wrapped__`.

## The cost, stated

**Consequential tools are now callable from a sandboxed script, and PTC does not
re-prompt consent per call.** `send_message`, `owl_build`, `tool_build`,
`skill_manage`, `send_file`, `browser_eval_js` — all reachable. `execute_code`'s
own consent is now the *only* consent covering everything a script does.

That is not an oversight in the consent design; it is a consequence of removing
the premise the consent bypass rested on. `dispatch.invoke` skipped the per-call
gate **because** the allowlist was read + sandbox-write only. That sentence was
literally in the code, and after this change it was false.

**Three self-justifying comments were rewritten rather than left standing**, because
a comment asserting a safety that no longer holds is worse than no comment:

| Site | Claimed | Now |
|---|---|---|
| `dispatch.invoke` | consent bypass is safe, "the allowlist is read+workspace-write only" | states that consequential tools are reachable and unprompted, and lists what *does* still constrain a call |
| `sandbox/ptc/__init__` | "Default-DENY allowlist — ONLY the five names" | default-ALLOW minus escape vectors, with the consent consequence named |
| `_ptc.ptc_enabled` | ON by default is "the safer default" because the allowlist is narrow | ON by operator decision; names the guardrails that actually remain |

The **user-facing consent text** changed too — it described a curated five-tool
surface, which would have made the prompt misleading:

> *The code may call ANY of this agent's tools via `import owl` — including ones
> that act on the outside world (send a message, create an owl or tool, write
> files) — WITHOUT asking again. Only sandbox-escape tools are refused. Approving
> this run approves everything the script does.*

## What still constrains a call

Widening the surface did not remove the other layers, and they are why the escape
fence is defensible on its own:

- **Bounds** — `owl.bounds(now) ∩ creation_ceiling`, enforced per call by the invoker
- **Write-confinement** — `PTC_WRITE_TOOLS` re-anchored to the run's sandbox workspace
- **Rate limit** — a per-run call cap (anti-DoS)
- **Arg and frame caps** — oversized payloads refused before allocation
- **Audit** — every call logged with bounded args, never secret values
- **Never-raise** — a PTC failure returns a structured frame; it cannot crash the host

## Invariants

> **I1.** A sandbox-escape vector is refused **before the registry resolves it**.
> Refusal after resolution would mean the tool was constructed, which for
> `execute_code` or `process` is already too late. Asserted on registry lookups,
> not just on invocation.
>
> **I2.** The sandbox is never trusted to self-limit. The stub's own denylist is
> courtesy; the host refuses regardless. Unchanged by this item — what changed is
> the *size* of what may be reached, not *who* enforces it.
>
> **I3.** Bounds still apply per call. Widening presentation-adjacent policy must
> never widen authorization; an owl that may not use a tool still may not use it
> from a script.
>
> **I4.** Approving `execute_code` approves everything the script does, and the
> consent text says so. If the surface ever widens again, this sentence is what
> must be re-checked first.

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| Escape vector reachable | `test_escape_vector_refused_without_invoking` (7 params) | — | — |
| A new escape-class tool is added and not denylisted | **Not detected** | Must be added to `PTC_DENYLIST` by hand | A script could break out |
| Script takes a real-world action the user did not anticipate | — | **Not prevented — accepted** | The consent text warns, once, per run |
| Script spams host tools | per-run rate cap | Refused past the cap | Script sees a budget error |
| Tool not registered | invoker | Structured "not registered" error | — |

Row 2 is the standing liability this design creates: **the fence is a hand-kept
list.** A future tool that can escape the sandbox is callable until someone
remembers. Recorded rather than solved — deriving it (e.g. from
`action_severity`) was considered and rejected, because that field is authored
for consent, and a mislabelled tool would silently open the fence.

### Prior art, and where we deliberately diverge

Hermes generates `hermes_tools.py` exposing the whole enabled toolset over UDS
(local) or file-based RPC (remote), so a multi-step chain collapses into one
inference turn with intermediate calls costing zero context.

**Adopted:** the surface policy, exactly — default-ALLOW minus exclusions.

**Diverged:**

1. **We keep an escape fence they do not need.** Their code execution runs at the
   same trust level as the agent; ours runs in a no-network sandbox that assumes
   the code is hostile. The seven denied names are the difference between "wide
   surface" and "no sandbox".
2. **We keep host-side bounds, confinement, rate limits and audit.** None of these
   exist in their equivalent. Widening the allowlist did not remove them, which is
   why this remains a narrower grant than theirs despite matching its shape.
3. **We did not adopt file-based RPC.** It exists for their remote backends; our
   sandbox is local, and a second transport would be a second attack surface for
   a capability nobody has asked for.

### How the two Laws hold

**Law 1 — per-conversation prompt caching is sacred.** Untouched. PTC changes what
happens *inside* one tool call; no schema, prompt or tools array moves.

**Law 2 — the core is a narrow waist.** This is Law 2's strongest case in the
programme: a chain that would have cost N tool calls, N schema round-trips and N
sets of intermediate results in context now costs **one**. The waist gets
narrower precisely because the script, not the model, does the plumbing.
