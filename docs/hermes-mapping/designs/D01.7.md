# Session Lifecycle — lanes, incarnations, and boundaries

> **Status:** design — approved, no open questions
> **Map item:** `D01.7` (execution order 2 of 111) — discovered during `D01.1` brainstorm, not in the original map
> **Source:** to be created at `src/stackowl/sessions/`; touches `src/stackowl/gateway/turn_registry.py`, `src/stackowl/channels/base.py`, `src/stackowl/memory/sqlite_bridge.py`
> **Config:** `session` in `stackowl.yaml`
> **Last verified:** 2026-07-25, against commit `eb079ea1`

## Why this exists

StackOwl has exactly one session identifier and **it never changes**. `/reset` deletes the
transcript, but nothing ever starts a new session. There is no boundary, so there is no moment at
which anything can be refreshed.

That blocks more than one item. "Build the prompt once per session" (`D01.1`) is meaningless
without a session that begins. "New facts apply next conversation" (Bakir, Q7) never arrives if
there is no next conversation. "Archive yesterday's transcript and summarise it into memory"
(Q17) has no trigger. The background-review fork (`D09.1`) and the skill curator (`D09.3`) both
want an idle moment that we cannot currently detect.

One missing concept is holding up five items.

## Model

The central idea, borrowed directly from Hermes: **split identity in two.**

| | What it is | Format | Changes when |
|---|---|---|---|
| `session_key` | The conversation **lane** — deterministic, derived from where the message came from | `owl:{owl}:{channel}:{chat_type}[:{chat_id}][:{thread_id}][:{participant_id}]` | Never |
| `session_id` | This **incarnation** of the lane | `YYYYMMDD_HHMMSS_<8hex>` | Every reset |

A reset keeps the key and mints a new id. The key is how we find your conversation; the id is
which run of it you are in. Today StackOwl conflates them, which is exactly why it cannot reset.

**We prefix the key with the owl.** Hermes has one agent; we have owls, and switching owl mid-lane
means a different persona and therefore a different prompt. The owl belongs in the key.

### SessionEntry

| Field | Type | Default | Meaning |
|---|---|---|---|
| `session_key` | `str` | — | The lane. Primary key. |
| `session_id` | `str` | — | Current incarnation. |
| `owl_name` | `str` | — | Which owl owns this lane. |
| `channel` | `str` | — | Originating channel, for delivery routing. |
| `created_at` | `datetime` | — | When this incarnation began. |
| `updated_at` | `datetime` | — | Last activity. Drives idle expiry. |
| `turn_count` | `int` | `0` | Turns in this incarnation. |

### State flags

Five booleans forming a state machine, evaluated on every inbound message.

| Flag | Set by | Effect on next access |
|---|---|---|
| `suspended` | `/stop`, or 3 consecutive restart failures on this lane | Hard wipe — force a new `session_id` |
| `resume_pending` | Unclean shutdown, or drain timeout mid-turn | **Preserve** the `session_id`; the transcript continues |
| `was_auto_reset` + `auto_reset_reason` | Policy expiry | Consumed **once** to show a visible notice: "new conversation — previous one ended (idle/daily)" |
| `is_fresh_reset` | Explicit `/new` | Kept distinct from `was_auto_reset` so an intentional reset never produces a misleading "expired" message |
| `expiry_finalized` | Background sweeper, after hooks ran | Prevents redundant finalisation across restarts |

## Lifecycle

```
 inbound message
        │
        ▼
 build session_key from (owl, channel, chat_type, chat_id, thread, participant)
        │
        ▼
 ┌──────────────────────┐
 │ key exists?          │── no ──► create fresh entry
 └──────────┬───────────┘
            │ yes
            ▼
 ┌──────────────────────┐
 │ 1. suspended?        │── yes ─► force reset, new session_id
 └──────────┬───────────┘
            ▼
 ┌──────────────────────┐
 │ 2. resume_pending?   │── yes ─► PRESERVE session_id, continue transcript
 └──────────┬───────────┘          (cleared after the next successful turn)
            ▼
 ┌──────────────────────┐
 │ 3. policy expired?   │── yes ─► auto-reset, reason = idle | daily
 └──────────┬───────────┘          run the rollover hook (see below)
            ▼
 ┌──────────────────────┐
 │ 4. return existing,  │
 │    bump updated_at   │
 └──────────────────────┘
```

**The priority order is behaviour, and it is the thing most likely to regress.** `suspended` beats
`resume_pending` beats policy, always. A hard wipe must never be overridden by a soft recovery.

### The rollover hook

When step 3 fires, before the new incarnation starts:

1. End the old `session_id` in the DB with reason `idle` or `daily`.
2. Archive the transcript — it stays queryable (see `D11.2`).
3. Emit `session.rollover` on the `EventBus`.

Step 3 is the seam. `D09.1` (background review) and `D09.3` (curator) subscribe to it rather than
inventing their own idle detection. Q17's "summary into memory" is a subscriber too. **Three items
converge here instead of building three schedulers** — this is dedup target X3, resolved by
architecture rather than by cleanup.

## Invariants

> **I1.** `session_key` never changes for the life of a lane. Anything that would change it
> creates a different lane.
>
> **I2.** A reset always mints a new `session_id` and never reuses one. Ids are monotonic per lane.
>
> **I3.** Priority order is `suspended` → `resume_pending` → policy → existing. Exactly one branch
> executes per message.
>
> **I4.** A lane with a running background process, an in-flight durable task, or an active
> objective is **never** expired. Borrowed from Hermes, and it matters more for us because
> autonomy is a headline feature: an agent working overnight must not have its session cut.
>
> **I5.** An auto-reset is always visible. `was_auto_reset` produces a user-facing notice exactly
> once. A boundary the user cannot see is a boundary they will experience as amnesia.
>
> **I6.** No transcript is destroyed by a rollover. The old incarnation is ended and archived,
> never deleted. (`/reset` deleting history is a separate, explicit user action.)

## Configuration

```yaml
session:
  reset_mode: both          # none | idle | daily | both      (default: both)
  at_hour: 4                # int 0-23, LOCAL time            (default: 4)
  idle_minutes: 1440        # int, 24h                        (default: 1440)
  notify_on_reset: true     # bool — surface the boundary     (default: true)
  group_sessions_per_user: true    # isolate group chats per user
  thread_sessions_per_user: false  # threads shared by default
  max_age_days: 0           # prune entries older than N days; 0 = never
```

**On `at_hour` — resolved, signed off 2026-07-25.** Bakir chose midnight in Q16; Hermes defaults
to 4 AM on the reasoning that a session running at 1 AM is mid-thought and midnight guillotines it,
whereas at 4 AM nobody is talking. **Bakir accepted 4 AM**, superseding his earlier answer. It
ships configurable, so midnight stays reachable for anyone who wants it — the default is 4.

Per-channel overrides go under `channels.<name>.session`, matching Hermes' per-platform policy.

## Observability

| Point | `msg` | `_fields` |
|---|---|---|
| entry | `session.resolve: entry` | `owl, channel, chat_id, thread_id` |
| decision | `session.resolve: branch taken` | `branch` = `new\|suspended\|resume\|expired\|existing`, `reason` |
| step | `session.rollover: old incarnation ended` | `session_key, old_session_id, new_session_id, reason, turn_count` |
| exit | `session.resolve: exit` | `session_key, session_id, created` |
| sweeper | `session.sweep: finalized` | `count, skipped_active` |

```bash
# Every boundary that has ever fired, and why
cat ~/.stackowl/logs/stackowl.jsonl | jq -c 'select(.msg=="session.rollover: old incarnation ended") | {ts, key: .fields.session_key, reason: .fields.reason, turns: .fields.turn_count}'

# Which branch is being taken — if this is always "existing", no boundary is firing
cat ~/.stackowl/logs/stackowl.jsonl | jq -r 'select(.msg=="session.resolve: branch taken") | .fields.branch' | sort | uniq -c
```

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| Core exec-replaces mid-turn | no clean-shutdown marker at boot | Lanes touched in the last 120s marked `resume_pending`; the transcript continues on next message | Nothing — conversation resumes |
| Same lane interrupted 3× | restart counter per lane | Lane force-`suspended`, clean slate | "Starting a fresh conversation — the previous one could not be recovered" |
| Rollover fires during an active job | `I4` check | Expiry skipped, retried next sweep | Nothing |
| Clock jump / timezone change | policy evaluation | Idle check uses monotonic elapsed where possible; daily uses local wall clock and tolerates a one-off double boundary | At most one extra reset notice |
| Rollover hook subscriber throws | hook wrapper | Logged at `error`; the rollover still completes | Nothing — the boundary is not blocked by a subscriber |

**Divergence worth stating:** Hermes' agent cache is in-memory (LRU 128, 1 h TTL) because their
gateway restarts rarely. **Our core exec-replaces itself on every code change**, so an in-memory
cache would be discarded constantly during development. Session entries are therefore **persisted**,
and the `SessionPrompt` that `D01.1` builds on top is persisted too. We already have drain +
durable recovery to build the resume path on.

## Verification

```bash
# 1 — targeted tests
timeout 300 uv run pytest tests/sessions/ -q
# PASS: green, including one test per invariant I1-I6.

# 2 — priority order is exercised
timeout 120 uv run pytest tests/sessions/test_priority_order.py -q
# PASS: suspended beats resume_pending beats policy beats existing.

# 3 — LIVE: force a daily boundary and confirm the notice
uv run python -m stackowl serve
#   set session.at_hour to the next clock hour, send a message either side of it
cat ~/.stackowl/logs/stackowl.jsonl | jq -c 'select(.msg=="session.rollover: old incarnation ended")'
# PASS: exactly one rollover row, reason "daily", new session_id != old.

# 4 — LIVE: active job blocks expiry (I4)
#   start a long background process, force the boundary
cat ~/.stackowl/logs/stackowl.jsonl | jq -c 'select(.msg=="session.sweep: finalized") | .fields'
# PASS: skipped_active >= 1, the lane keeps its session_id.

# 5 — restart safety
#   kill -9 the core mid-turn, restart, send a message
# PASS: branch taken == "resume", session_id preserved, transcript intact.
```
