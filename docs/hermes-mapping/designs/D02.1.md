# One agent class, all surfaces — an investigation, not a decision

> **Status:** investigation — no code written, no decision taken
> **Map item:** `D02.1` (wave 3) — verdict `DIVERGENT`
> **Subject:** `pipeline/registry.py` (`PIPELINE_STEPS`), `pipeline/backends/`, `pipeline/steps/`
> **Requested by:** Bakir, who asked me to investigate merging the steps into one
> agent object *rather than* accept my recommendation to keep the registry
> **Last verified:** 2026-08-05, against commit `2df150f1`

## Why this document exists

I measured, recommended keeping the pipeline, and was told to investigate the
merge properly instead. That is a fair instruction: I had presented a conclusion,
not a costed alternative. This is the costed alternative.

## What the map claims, and what is measurable

> *"StackOwl's pipeline is more inspectable; Hermes' class is more portable and
> far easier to fork for subagents/background review."*

**The second half is false.** StackOwl forks a subagent in one line:

```python
# owls/a2a_delegation.py:215
return await backend.run(sub_state)
```

Build a `PipelineState`, call `backend.run`. That is the entire fork. Forking a
class with ~60 constructor parameters is not easier than that.

**And the registry buys something a class cannot.** `PIPELINE_STEPS` feeds **two
interchangeable backends**, selected by config (`OrchestratorSettings.backend:
Literal["langgraph", "asyncio"]`):

| backend | status | provides |
|---|---|---|
| `asyncio` | live in production | the known-good default |
| `langgraph` | real, config-selectable | `StateGraph`, `Send` fan-out, and **checkpointing** via `AsyncSqliteSaver` → durable resume |

A single agent object with the steps as private methods cannot offer that seam.

## What a merge would cost — measured

| | measured |
|---|---|
| lines across the 9 steps | **5,597** (`execute.py` alone: 3,045) |
| test files touching pipeline steps | **115** |
| dedicated per-step test files | 9 |
| backends consuming `PIPELINE_STEPS` | 2 |
| **cross-step imports** | **0** |

That last row is the important one. Every step is:

```python
async def run(state: PipelineState) -> PipelineState
```

— uniform, and they communicate **only** through an immutable `PipelineState`
(`frozen=True`, mutated via `evolve()`). There is no hidden coupling to unpick,
because there is no coupling.

A merged object would be a ~5,600-line class whose steps became methods sharing
mutable `self` — replacing a uniform, side-effect-free contract with implicit
state. The reference platform's own class is cited in the map as having ~60
constructor parameters, which is what that shape costs at scale.

## The strongest case FOR merging

Stated properly, because dismissing it was the thing I was told not to do:

1. **One object to hand around.** Callers currently assemble a `PipelineState`
   themselves. An `Agent` would own that.
2. **End-to-end readability.** One class reads as one turn; nine files require
   knowing the order lives in a registry.
3. **Portability.** A self-contained object is easier to lift into another
   process, a test harness, or a subagent — the reference platform's actual claim.
4. **Fewer indirections.** `backend.run` → registry → step function → services is
   four hops to reach the work.

## Why each collapses on measurement

1. **Already solved.** `StepServices` is the injected-dependency object; the
   caller assembles ~6 fields of state, not 60 constructor params.
2. **Real but small.** The order is 8 lines in one file, and every step has the
   same signature. Against that, `execute.py` at 3,045 lines is where the reading
   difficulty actually lives — and merging makes that file *bigger*, not smaller.
3. **Measured false.** One line, above.
4. **The indirection is the feature.** It is exactly what lets `langgraph`
   substitute for `asyncio` and what makes 9 step-level test files possible.

## The middle path, recorded for completeness

A thin `Agent` facade over `backend.run` would deliver benefit (1) and part of
(2) without touching the registry:

```python
class Agent:
    def __init__(self, services): ...
    async def run(self, **state_kwargs) -> PipelineState:
        return await self._backend.run(PipelineState(**state_kwargs))
```

Rejected as *currently* unnecessary rather than wrong: it wraps a one-line call.
It becomes worth doing the day a third caller needs to assemble state.

## Honest conclusion

**The merge costs a great deal and buys something already measured as ours.** The
map's `DIVERGENT` verdict is right; its stated trade-off is not — StackOwl is
both more inspectable *and* easier to fork, and the registry is what makes the
two-backend seam and per-step testing possible.

**This document does not close the item.** It is the investigation that was asked
for. The decision is Bakir's, now with numbers rather than my summary.

### What would change this conclusion

Recorded so the answer is not treated as permanent:

- If the `langgraph` backend were removed, the strongest structural argument for
  the registry goes with it.
- If `execute.py` were decomposed, the "one class is unreadable" objection weakens
  considerably — 2,552 lines across 8 steps is a very different object from 5,597.
- If a third or fourth caller needed to assemble `PipelineState` by hand, the
  facade stops being redundant.
