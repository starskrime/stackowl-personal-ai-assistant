## Why this exists

We are about to rebuild how StackOwl assembles its prompt (`D01.1`) on the claim that the current
design is expensive. **We cannot currently substantiate that claim, and we could not prove a fix
worked.** `assemble.py` logs its per-part sizes at `debug()`, the live log level is `INFO`, and 0
of 17,403 lines in the current log carry them. The provider captures `prompt_tokens` and
`completion_tokens` but not cached tokens, nothing records time-to-first-token, and `cost_records`
has no `session_key`, so cost cannot be grouped by conversation.

Bakir's answer to Q15 was explicit: measure first. Q20 named four metrics, and he chose all four.
This document specifies the smallest change that produces all four.

Without this, `D01.1` ships on faith and we learn nothing from it.

## Model

Four questions, four metrics, one row per LLM call.

| # | Question | Metric | Source |
|---|---|---|---|
| 1 | Is the prefix cache working? | `cached_input_tokens / input_tokens` | provider usage |
| 2 | Does it feel fast? | `ttft_ms` — time to first token | provider stream |
| 3 | What does a conversation cost? | `SUM(cost_usd) GROUP BY session_key` | aggregation |
| 4 | Is the prompt actually stable? | `COUNT(DISTINCT prompt_hash) per session_key` | assemble |

Metric 4 is the load-bearing one. It is a **pass/fail invariant**, not a trend: within one
conversation the system prompt must hash to exactly one value. Today it will be one distinct hash
per turn. After `D01.1` it must be exactly `1`. That single query is how we prove the item worked.

### What already exists

| Component | State |
|---|---|
| `CostTracker` | Per-call token accounting, daily budget enforcement, `EventBus` emission. **Keep.** |
| `TurnCostLedger` | Per-turn accumulation, bounded at `_MAX_TRACKED_TURNS`. **Keep.** |
| `cost_records` table | `provider_name, model, input_tokens, output_tokens, cost_usd, trace_id, recorded_at`. **Extend.** |
| `PricingLoader` | Cost computation from a pricing table. **Keep.** |
| `/cost` | Spend summary + privacy controls. **Extend with a per-conversation view.** |
| openai provider usage capture | `prompt_tokens` / `completion_tokens` captured in both streaming and non-streaming paths. **Extend with cached tokens.** |

This item is a `close_gap`, not a build. Nothing is replaced.

### What is added

Migration `0091_turn_metrics.sql` adds five nullable-with-default columns to `cost_records`:

| Column | Type | Default | Meaning |
|---|---|---|---|
| `session_key` | `TEXT` | `''` | Groups calls into a conversation. Also the seam `D01.7` will build on. |
| `cached_input_tokens` | `INTEGER` | `0` | Provider-reported cache hits. `0` means "none or not reported" — see I4. |
| `prompt_hash` | `TEXT` | `''` | SHA-256 (first 16 hex) of the exact system prompt sent. |
| `system_prompt_chars` | `INTEGER` | `0` | Size of the system prompt, so growth is visible independently of tokens. |
| `ttft_ms` | `INTEGER` | `NULL` | Milliseconds from request start to first content token. `NULL` = not measured (non-streaming). |

Defaults on every column, so the migration is idempotent and every existing row stays valid.

## Lifecycle

```
 turn starts
     │
     ▼
 assemble  ──── builds system_prompt
     │          prompt_metrics.stamp() -> sha256(prompt)[:16] + char count
     │          into a turn-scoped ContextVar (NOT PipelineState — providers
     │          cannot import pipeline, so the carrier lives in infra/)
     ▼
 execute   ──── provider call begins ── t0 = monotonic()
     │
     │          first content token arrives ── ttft_ms = now - t0
     │                                          (streaming only; NULL otherwise)
     ▼
 provider returns usage
     │          input_tokens, output_tokens
     │          cached_input_tokens  ← usage.prompt_tokens_details.cached_tokens
     ▼
 providers/base.py::_record_cost  — the SINGLE recording site
     │          reads session_key off TraceContext (already there)
     │          reads prompt_hash + chars off prompt_metrics.current()
     │          receives cached_input_tokens + ttft_ms as arguments
     ▼
 CostTracker.record(...)
     ▼
 cost_records row written
```

**Priority order for `cached_input_tokens`** (`_cached_input_tokens()` in `openai_provider.py`) —
dispatches on response SHAPE, never on provider name, per `program.constraints.provider_agnostic`:

1. `usage.prompt_tokens_details.cached_tokens` — OpenAI's own field (attribute or dict)
2. `usage.cache_read_input_tokens` — Anthropic naming, which LiteLLM-style gateways pass through
3. `usage.cached_tokens` — flattened variants
4. `0`

Never raises — an unreported field is data we do not have, not an error.

## Invariants

> **I1.** Recording a metric never fails a turn. Every metrics write is wrapped; on failure it logs
> at `error` with the trace id and the turn continues. Measurement must not become an outage.
>
> **I2.** `prompt_hash` is computed over the exact bytes sent to the provider, after all assembly,
> not over an intermediate. A hash of something we did not send proves nothing.
>
> **I3.** `cost_records` remains append-only. This item adds columns; it never rewrites history.
>
> **I4.** `cached_input_tokens = 0` is ambiguous by construction — it means "no cache hit **or**
> the provider did not report one". The report must therefore distinguish *provider reports cache
> stats* from *cache hit rate is zero*, or we will misread a silent provider as a failed fix.
>
> **I5.** No secret, prompt text, user message, or memory content is written to `cost_records`.
> Only the hash and the character count. The hash is not reversible and is not a fingerprint of
> the user.

## Configuration

**None. This was specified and then deliberately dropped during implementation.**

The design originally called for a `system.metrics` block with `enabled` / `capture_ttft` /
`prompt_hash` switches, justified as a rollback path. Building the rest made that look like
over-engineering:

* The feature is **append-only instrumentation that already fails open** by invariant I1 — a
  metrics failure is logged and the turn continues. The risk a kill-switch mitigates is close to
  zero.
* A switch adds a branch to a hot path and creates a dormant-feature mode, which conflicts with
  the standing rule that finished features ship ON rather than behind a flag.
* Rollback already exists and is cheaper: revert the commit. The migration is additive with
  defaults, so old rows and un-threaded callers stay valid either way.

Recorded here rather than silently omitted, per PROCESS.md's rule on implementation diverging
from design.

## Observability

Per the 4-point standard, `CostTracker.record` and the assemble hash step both log entry and exit.

| Point | `msg` | `_fields` |
|---|---|---|
| assemble exit | `[pipeline] assemble: exit` | `trace_id, session_key, base_len, persona_len, banner_len, owls_len, skills_len, memory_len, system_len, prompt_hash` |
| record entry | `[cost_tracker] record: entry` | `provider, model, input_tokens, output_tokens, duration_ms, session_key` |
| record decision | `[cost_tracker] record: cache stats source` | `source` = `reported\|absent_or_zero`, `cached_input_tokens`, `provider` |
| record exit | `[cost] {provider}/{model}: $...` | `session_key, cached_input_tokens, prompt_hash, system_prompt_chars, ttft_ms`, plus tokens and cost |
| failure | `[provider] _record_cost: cost record failed — continuing` | `provider, model`, `exc_info` |

**Done:** the assemble exit log was raised from `debug` to `info`. At debug level it carried 0 of
17,403 live log lines — it was the direct cause of prompt composition being unmeasurable.

```bash
# Is the prompt stable within a conversation? (the D01.1 pass/fail)
SO_DB=~/.stackowl/workspace/stackowl.db   # NOT ~/.stackowl/ — see note below
python3 -c "import sqlite3,sys;[print(r) for r in sqlite3.connect(sys.argv[1]).execute(sys.argv[2])]" "$SO_DB" \
  "SELECT session_key, COUNT(DISTINCT prompt_hash) AS distinct_prompts, COUNT(*) AS turns
   FROM cost_records WHERE session_key != '' GROUP BY session_key ORDER BY turns DESC LIMIT 10;"
# BEFORE D01.1: distinct_prompts == turns.   AFTER: distinct_prompts == 1.

# Cache hit rate, and whether the provider reports at all
SO_DB=~/.stackowl/workspace/stackowl.db   # NOT ~/.stackowl/ — see note below
python3 -c "import sqlite3,sys;[print(r) for r in sqlite3.connect(sys.argv[1]).execute(sys.argv[2])]" "$SO_DB" \
  "SELECT provider_name,
          SUM(cached_input_tokens) * 100.0 / NULLIF(SUM(input_tokens),0) AS cached_pct,
          SUM(CASE WHEN cached_input_tokens > 0 THEN 1 ELSE 0 END) AS rows_reporting,
          COUNT(*) AS rows_total
   FROM cost_records GROUP BY provider_name;"

# Live prompt hashes as they are produced
cat ~/.stackowl/logs/stackowl.jsonl | jq -c 'select(.msg=="[pipeline] assemble: prompt hashed") | {ts, session: .fields.session_key, hash: .fields.prompt_hash, chars: .fields.system_prompt_chars}'
```

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| Provider omits usage entirely | `usage is None` | Row written with `0` tokens; `cache stats source = absent` logged | Nothing |
| Provider omits cached-token fields | fallback chain exhausts | `cached_input_tokens = 0`, source logged as `absent` | Report shows "provider does not report cache stats" (I4) |
| DB write fails | exception in `record` | Logged at `error`, turn continues (I1) | Nothing — the turn completes normally |
| Migration partially applied | migration runner | Runner is idempotent; re-running completes it | Nothing |
| Streaming ends with no content token | `ttft_ms` never stamped | Stored `NULL`, excluded from averages | Nothing |

Nothing here fails closed onto the user's turn. The worst case is missing data, and missing data
is always distinguishable from measured zero.

- **Divergence from Hermes.** Hermes measures with `agent/usage_pricing.py`, `credits_tracker.py`
  and an `/insights` report, and it tracks `cache_read_tokens` / `cache_write_tokens` on the
  session entry itself. We deliberately put the metrics on `cost_records` (the call) rather than
  on the session, because StackOwl has no session object yet — that arrives in `D01.7`. Putting
  `session_key` on the call row now means `D01.7` inherits working per-conversation aggregation
  instead of having to add it. We also add `prompt_hash`, which Hermes has no equivalent of:
  they enforce prompt stability by review discipline, we prefer an assertion.
