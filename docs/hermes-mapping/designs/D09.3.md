## Why this exists

Measured on the live catalog on 2026-08-05: **421 skills, 33 ever executed, 0 ever retired.**
Of 407 learned skills only 142 were distinct base names — **265 were numbered duplicates**, one
of them (`recover_tool_search_unachieved_effect`) present twenty-one times.

The platform is good at creating skills and had no mechanism for noticing which ones earn their
place. Every one of the 421 competed for tool-search ranking and prompt space on every turn.

Two root causes, and they need different fixes:

1. **Nothing retired anything.** A curator (decay) fixes that — shipped 2026-08-05.
2. **Nothing stopped the same lesson being written twice.** `_cluster_already_covered` dedupes on
   `parent_traces` — on the *evidence* — so a lesson re-derived from a new incident carries new
   trace ids, never matches, and the synthesizer appends `-N` and writes it again. Fixed at the
   conclusion level (`DEBT-42`), and prevented structurally by the authoring standard here.

## Model

### The two identifiers a reader will confuse

| | meaning | lives in | changes when |
|---|---|---|---|
| `lifecycle_state` | is this skill offered? `active` / `stale` / `archived` | `skills` table (migration 0107) | the curator moves it, or it is used |
| `_deprecated/` | pre-existing on-disk quarantine for low-quality skills | filesystem | the synthesizer moves it — **zero times ever** |

`X11` is exactly this: two retirement concepts, one of them inert. **Resolution: one mechanism,
two triggers.** `lifecycle_state` is the single truth; `_deprecated/` is absorbed and the
synthesizer's deprecate path is removed.

### Retirement triggers

| trigger | condition | outcome |
|---|---|---|
| unused | no execution for `STALE_AFTER_DAYS` (30) | `stale` |
| unused | no execution for `ARCHIVE_AFTER_DAYS` (**60**, was 90) | `archived` |
| failing | `success_rate < 0.4` with `n_executions >= 5` | `archived` |
| revived | executed, or pinned | `active` |

Priority, in the order `SkillCurator._target_state` applies it: **pinned** (the caller skips the
row entirely) → **failing** → **age, longest window first** → **active**. Failing outranks recent
use deliberately: the trigger only fires at `n_executions >= 5`, so if recent use outranked it the
quality trigger could never fire at all.

### What shipped, and what it cost — implement stage, slice 3

| change | file | note |
|---|---|---|
| quality trigger absorbed | `skills/lifecycle.py` | `FAILING_BELOW` / `MIN_RUNS_FOR_RATE`, values carried over unchanged |
| archive window 90 → 60 | `skills/lifecycle.py` | the reversible transition proved itself: 297 marked stale, none lost |
| built-ins now decay | `skills/store.py` | `rows_for_curation` dropped `AND source = 'learned'` |
| AD-7 owl-drive advisory relocated | `owls/skill_ownership.py` | `owl_drive_thresholds()`, injected as a **provider** so evolution-mutated drives are read per pass, not frozen at assembly |
| synthesizer deprecate path removed | `skills/synthesizer.py` | `deprecate_low_performers` + `_deprecate_one` + the `run_all` phase |
| 7 tests migrated | `tests/skills/test_curator_quality_trigger.py` | rewritten against `lifecycle_state`, not a directory move |

Two things surfaced that the brainstorm had not predicted, both stated because they change the
claim this document can make:

1. **The old path violated I3 outright.** `_deprecate_one` called `store.delete()`. A skill retired
   for *failing* was unrecoverable, while one retired for *disuse* was fully reversible — an
   asymmetry nothing justified, and the strongest argument for one mechanism that the brainstorm
   never reached.
2. **Archival was half-wired.** `list_enabled` and `semantic_recall` both carried the not-archived
   predicate; `_fts_search` — the BM25 leg of hybrid recall — did not. An archived skill vanished
   from two of three read paths and kept competing for ranking on the third. With 297 skills
   already marked stale on the live catalog this was costing real prompt space, silently. Fixed,
   and pinned by a test proven to fail without the fix. ADR-19 I2: an actuator whose effect is
   only partly wired is worse than none — it costs the write and delivers no relief.

Pinning also now protects a failing skill. It never did: the synthesizer path did not consult
`pinned` at all, so a human veto covered exactly half of retirement.

### The authoring standard

Frontmatter — **authored content only**. `success_rate`, `n_executions`, `parent_traces` and
`embedding_model` move out; the database already owns them, and two writers to one field is how
they drift.

| field | required | rule |
|---|---|---|
| `name` | yes | no `-N` suffix, ever |
| `description` | yes | **≤ 60 chars**, one sentence |
| `when_to_use` | yes | 1–3 sentences — carries retrieval |
| `version` | derived | bumps on every content change |
| `source`, `enabled` | derived | not authored |
| `category`, `tags`, `author`, `license` | no | `author` = the human operator |

Body — **seven sections, fixed order**: When to Use → Prerequisites → How to Run →
Quick Reference → Procedure → Pitfalls → Verification. Tool names in backticks must resolve
against the live `ToolRegistry`. Support files only in `scripts/` `references/` `templates/`.

`summary` is **removed** — column, `summary_source`, `summary_body_hash`, the FTS entry, and
`assembly._summarize_missing`. It existed to compensate for descriptions being unreadable at a
glance; a 60-char description *is* that glance.

## Lifecycle

```
                    ┌──────────── used / pinned ────────────┐
                    │                                        │
   write ──> [active] ──30d unused──> [stale] ──60d unused──> [archived]
     │          │                                                 │
     │          └── success_rate<0.4 & runs>=5 ───────────────────┘
     │
     └── REJECTED if it violates the standard (nothing non-conforming enters)
```

**Priority order** when several conditions hold on one pass — ordering is behaviour:

1. **`pinned` wins over everything.** A pinned skill is never moved, in any direction.
2. **Revival beats retirement.** A skill used since the last pass is `active` regardless of age.
3. **Failing beats unused.** `success_rate < 0.4` archives directly, without waiting for `stale`.
4. **Age applies last**, longest window first: archive (60d) is tested before stale (30d).
5. **No clock ⇒ no ageing.** A missing timestamp is a data defect, never "infinitely old".

## Invariants

> **I1.** Nothing is ever deleted by an unattended process. Archive is the terminal automatic
> state and it is recoverable.
>
> **I2.** `pinned` outranks every automatic transition.
>
> **I3.** A skill that is used returns to `active` from any state, including `archived`.
>
> **I4.** Archived skills stay in the database and stay searchable; they are ranked out, not
> erased.
>
> **I5.** A skill violating the standard cannot be written. Existing skills are *reported*, never
> rejected at load — rejecting at load would make 408 skills unloadable and empty the catalog.
>
> **I6.** The first curator pass on an uncurated catalog changes nothing; it seeds the clock and
> defers, so an operator has a full interval to pin before anything moves.
>
> **I7.** A `-N` suffixed name is rejected at write. The suffix only ever existed because the
> synthesizer needed a free directory.
>
> **I8.** The standard has exactly one machine-readable source; the document and the authoring
> prompt cite it. Three hand-maintained copies is how a standard rots.
>
> **I9.** The deletion path is dry-run by default, requires `--apply`, copies every affected
> skill outside the catalog first, and is never scheduled.

**I9 is a deliberate exception to I1**, taken by the operator with the irreversibility stated
(`D09.3` R4Q14). It is confined to one explicitly-invoked command precisely so I1 continues to
hold everywhere else.

## Observability

Log lines, with the `_fields` each carries:

| `msg` | level | fields |
|---|---|---|
| `[curator] run: exit — <summary>` | WARNING when anything moved, else INFO | `scanned`, `to_stale`, `to_archived`, `revived`, `skipped_pinned`, `dry_run`, `archived_names` |
| `[curator] first observation — catalog seeded, nothing changed` | WARNING | `scanned` |
| `[skills] standard: write rejected` | WARNING | `name`, `violations[]` |
| `[skills] standard: conformance` | INFO (boot) | `conforming`, `total`, `standard_version` |

A retirement is WARNING, not INFO: it changes what the agent can reach, and a silent change to
capability is indistinguishable from a bug (ADR-19 I6).


## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| Curator archives a skill still wanted | next use of it | `I3` — revived to `active` automatically | nothing; it works |
| Thresholds too aggressive | rising revival count | operator widens the windows | more skills returning |
| Curator raises mid-pass | `knowledge_prune` catches it | logged; the fact prune still succeeds | fact pruning unaffected |
| Standard rejects a legitimate skill | `I5` at write | all violations returned at once; the model retries | one extra authoring round trip |
| Registry unavailable when validating tool names | lookup returns nothing | rule skipped, write proceeds — a missing registry must not block authoring | nothing |
| Dedupe deletes the wrong family member | dry-run inspection before `--apply` | restore from the timestamped copy outside the catalog | nothing, if the dry run was read |
| Migration LLM produces a non-conforming body | the validator, on write-back | that skill is left unmigrated and reported | conformance count stays short |

### Prior art, and where we deliberately diverge

`agent/curator.py` (2,018 lines) and its rubric. **Adopted:** the lifecycle shape
(active → stale → archived), never-auto-delete, pinning as a human veto, usage as the signal,
deterministic pruning always-on with LLM consolidation opt-in, the fixed section order, real tool
names in backticks, and the `scripts/`/`references/`/`templates/` layout.

**Diverged, with reasons:**

| Hermes | Ours | Why |
|---|---|---|
| Usage derived from file mtimes | Usage measured (`n_executions`, `last_used_at`) | We already record it; mtime is a proxy for the thing we have |
| Rubric enforced by reviewers | Enforced by a validator at write | Our author is the agent; a convention it cannot read is not a rule |
| Curator may archive built-ins by default | Same, but only with explicit operator consent (given) | Standing rule: never disable a shipped feature without asking |
| `platforms:` field, audited | Not adopted | Our standing rule is that everything runs on all hardware |
| Test file per skill | Only for `builtin`/`user` | 423 agent-generated test files nobody runs is not verification |
| `≤60` description because humans browse | `≤60` **adopted against our own evidence** | Operator decision. Our retrieval reads `when_to_use` too, so the signal was moved there rather than lost |

### How the two Laws hold

**Law 1 — per-conversation prompt caching is sacred.** The curator runs in a scheduled background
job, never inside a turn. Archiving changes which skills are *candidates* for a later prompt; it
never rewrites the prompt of a conversation in flight. The one risk is a skill vanishing between
two turns of one session — bounded because retrieval already varies per turn by query, and the
cached prefix does not contain the skill catalog.

**Law 2 — the core is a narrow waist.** No new model-facing tool. Retirement is invisible to the
model: it sees a shorter candidate list, not a new capability. The dedupe is a CLI command
(rung 2), deliberately not a tool, because an irreversible bulk delete belongs to the operator.
