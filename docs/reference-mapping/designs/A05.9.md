## Why this exists

The operator asked, in his own words: *"What happened with agentic os dashboard?
Where we are in progress?"* The honest answer was that nothing rendered.

**A05.1's gap reads "there is no surface through which a customer can see or
steer the platform. Everything is a terminal command." Every one of its stages
reads `done`.** What it shipped is a JSON API behind a bearer token — still a
terminal command, typed into `curl` instead of into `stackowl`. The item built
the DOOR and its gap claimed the SURFACE, and nothing compared the two.

MEASURED before building: `src/stackowl/control_plane/` contained **zero**
`text/html`, `add_static` or template references, and every A05 item is phrased
*make X reachable* — none says *draw it*.

**This is DEBT-307's defect wearing its other face.** There, a gap overstated an
ABSENCE and would have had a loop rebuild something that already worked. Here a
COMPLETION overstates a PRESENCE, and eight later items queued up behind a
surface that cannot be opened. `gap_check.py` files a finished item's gap as
HISTORY — right for the seven it was built for, and blind to this one, because
A05.1's gap is not refuted. It is still true.

## The ladder rung

**Extend what runs.** No new store, no new reader, no new setting, no second
server. One handler returning a constant, on the surface A05.1 built, rendering
the two routes that already answer.

**Law 1 — nothing duplicates logic that already runs work.** The page computes
nothing. Every number on it is whatever `/api/v1/health` and `/api/v1/schedules`
returned, which are themselves reads through the live aggregator and the live
scheduler. A dashboard that re-derived a status would be a third opinion.

**Law 2 — the core stays narrow.** One module, one route, no dependency added.

## Model

`GET /` → `200 text/html`, a self-contained document: inline CSS, inline JS, no
external fetches, no build step.

The viewer pastes the token once; the page holds it in `sessionStorage` and
attaches it as `Authorization: Bearer` on each `fetch`. It renders FIVE tables —
subsystems (status, message, remedy, latency), schedules (job, handler, schedule,
state, next run, failures, last error), settings (key, value, masked), skill
ownership (owl, skills, count) and work in flight (task, owl, status, blocked,
attempts, next run, last error).

**The `blocked` column is not decoration and must not be styled as a fault.**
A05.6 measured five `secretary` rows sitting `pending` ten hours past their
`next_attempt_at` — the silhouette of a wedged loop, and every one correct,
because the loop will not run a child of a terminal parent. `blocked` is what
separates "the loop declines this, rightly" from "the loop is stuck", and it is
rendered as muted text rather than a pill for the same reason: colouring correct
behaviour like a fault is the invented alarm the column exists to prevent.

**This sentence said TWO until A05.8, and the page had three.** A05.2 amended
this document's Status line and its "surfaces not yet rendered" list and left the
Model section alone, so the document stated a table count the page had already
outgrown — the fifth-surface rule failing INSIDE a single document rather than
across files, which no sweep of FILES can see. The count is the thing to watch
here: prose that says "two" is falsified by the page, and prose that says "the
tables it renders" would never have been wrong.

**No framework and no CDN.** The platform is self-hosted by requirement; a page
that pulls a framework from someone else's server is blank on a machine with no
egress, and the operator's own box is the first one it has to work on.

## Lifecycle

Registered in `ControlPlaneServer.run()` beside the API routes, served by the
same `SupervisedTask`, dies with it. Holds no state. The route COUNT is not
written here on purpose: it was "two" while four were registered, and
`test_every_api_route_is_rendered_somewhere_on_the_page` is the thing that
actually keeps the page and the route table in step.

## Invariants

1. **It opens with NO credential.** A browser cannot put an `Authorization`
   header on a top-level navigation. If this route ever needs a token, the
   dashboard is unreachable and we are back to `curl` — which is the state A05.1
   shipped while its record said otherwise.
2. **It carries no platform data, and both halves are enforced.** `INDEX_HTML` is
   a module constant with no interpolation — a test parses the AST and fails on
   an f-string or a concatenation — and `_handle_index` reads **zero** instance
   attributes.
3. **The exemption from the guard is STRUCTURAL, never a name.** A05.4's sweep
   requires every registered handler to reach `_guard`; it now admits an
   unguarded handler only if it touches no `self.` attribute at all. A companion
   assertion fails if NO route is guarded, so the carve-out cannot swallow the
   rule it came from.
4. **The token never becomes a cookie.** A cookie is sent automatically on every
   request to this origin, which is how a dashboard acquires a CSRF problem it
   did not need.
5. **Stored strings reach the DOM as text.** `last_error` is whatever a failing
   job wrote; a test fails on `innerHTML`.
6. **Page and door are a BIJECTION.** Every `/api/…` path the page fetches is a
   route the server registers — a dashboard calling a 404 reads as a broken
   platform rather than an absent feature — **and** every registered `/api/` route
   appears on the page, so the next surface cannot ship invisible. Both sides are
   derived from `run()`, never from a list in a test.

## Configuration

None. It cannot be turned off independently of the control plane.

## Observability

`[control_plane] server.index: exit — page served` at **INFO**. No DEBUG: this
deployment has written zero DEBUG records in 677,108, so a DEBUG line is a claim
nothing can settle.

There is deliberately no `entry` line and no principal field — the handler has no
principal to name, and one INFO line per page load is the whole event.

## Failure modes

| What fails | What happens | What notices |
|---|---|---|
| Wrong or absent token in the browser | Both fetches return 401; the page prints `refused (401)` and renders no tables | The viewer, immediately; and `server.{health,schedules}: exit — refused` at WARNING |
| An API route is down | The page prints the HTTP status rather than an empty table | The viewer; the absent `exit — served` line |
| `sessionStorage` unavailable (private mode) | Caught; the token lives in the form for that page load only | Nothing — it degrades to typing it again, which is correct |
| The page gains an f-string | The tripwire fails by name | `./scripts/tripwires.sh` |

## What this deliberately does not do

**It does not write.** No control on this page changes platform state. That is
ESC-173's question, not a missing feature.

**It does not render the three surfaces that do not exist yet.** Agents, memory
and interactions are A05.3/5/7. **Config, skill ownership and live activity are
no longer on that list**: A05.2's read half shipped `GET /api/v1/config` with its
Settings table, A05.8's shipped `GET /api/v1/skills` with its Skill ownership
table, and A05.6's shipped `GET /api/v1/tasks` with its Work-in-flight table —
each in one change, because the guard below required it. The first was the first
time the rule was tested by a real second endpoint rather than by a mutation; the
second, the first time by an author who had already written the table; and by the
third it was simply how a route ships here.
 **Skill ownership is the OWNERSHIP half only**: which
owl owns which skill, from `read_all_skill_ownership`. The skill CATALOGUE is not
here and cannot be until the store grows a list-all — `skills_list.py` unions
`list_for_source` across sources and says so in its own docstring. Each
remaining surface adds its table here IN THE SAME CHANGE — and that is enforced
rather than asked for: `test_every_api_route_is_rendered_somewhere_on_the_page` fails by name on
any registered `/api/` path the page does not show. Mutation-proven — a third
route with no table fails it. A rule that has to be remembered is the one that
gets skipped, and forgetting this particular one is precisely how A05.1 came to
say its surface was done.

**It does not poll.** The page reads once per load. A refresh loop is a decision
about load on a Jetson, and nobody has measured what it costs.

**And it no longer treats one route's outcome as the page's.** A05.8 found, by
EXECUTING the script rather than reading it, that `Promise.all` made every
endpoint a single point of failure: a 503 from one route rejected the chain, the
`catch` hid every section, and the page showed `HTTP 503` with nothing on it —
one unwired subsystem rendered as a dead platform. The same throw made the
handlers' `wired: false` payload unreachable by any browser, so the
confess-rather-than-return-empty design had no reader at all. And "forget token"
hid two of the four sections, leaving the SETTINGS table on screen after the
operator asked the page to forget.
One cause under all three: the page enumerated its own sections BY HAND in three
places, and A05.2 updated one of them. `PANELS` is the single enumeration now,
and `test_one_dead_route_does_not_blank_the_dashboard.py` runs the real script
under a stub DOM — the first guard here that asks what a VIEWER sees rather than
what the source says.
