# Third-Party Products Stay Out of the Tree

**Item.** D16.4 · Third-party products stay out of tree — `MISSING`
**Last verified.** 2026-09-04, commit `HEAD`

## Why this exists

The Ask is a build instruction: *"adopt — it is the discipline that keeps a fast-moving core
fast-moving."* The reference platform's policy, stated twice there, is that observability
backends, vendor SaaS connectors and analytics ship as **standalone plugin repos**, and its
reason is maintenance load rather than quality. Its in-tree provider set is formally closed.

## The design already agreed, in June

`IntegrationRegistry.register()` is documented *"Open for extension: Epic 10 plugins can call
register() at import time"*, and `/connect` tells the operator, in its own words:

> No integrations registered. **Install an integration plugin first.**

So the policy was not a new idea here. It was the intent, unstated and unenforced.

## And the tree does the opposite

Measured 2026-09-04. Four vendor-specific modules live in `src/stackowl/integrations/`:

| module | |
|---|---|
| `gmail.py` | vendor SaaS connector |
| `gmail_settings.py` | its settings |
| `google_calendar.py` | vendor SaaS connector |
| `google_oauth.py` | its OAuth flow |

Registered from **three core sites** — `cli/app.py`, `commands/assembly.py`,
`startup/orchestrator.py`. **This is live, not dormant:** the Gmail OAuth token on disk was
refreshed 2026-09-02.

The in-tree **memory-provider** set, which the reference formally closes, is already
effectively closed here at one: `BuiltinCuratedProvider`.

## I got both numbers wrong first, and the tests corrected them

Recorded because either error would have understated the finding:

1. I read the package with `ls -la | tail -8`, which **truncated the listing**, and concluded
   the vendor set was the `google_*` pair. It is four — `gmail.py` and `gmail_settings.py`
   were above the cut.
2. I grepped for `register()` only *inside* the integrations package and concluded "nothing
   in `src/` calls it". **Three modules do.** That turned a finding about dormant code into
   one about a live violation.

Both were caught by writing the assertion before believing the measurement — the test failed
with the true set in its message.

A third instrument correction: "`integrations/`: 0 of 10 files log" measured the **named-logger
convention** (`log.<name>.<level>`), not logging. `gmail.py` has 31 log statements through a
plain module logger. The package deviates from the convention; it is not silent.

## What was adopted

The rule is stated in `src/stackowl/integrations/__init__.py` — where the exception lives, so
a reader meets the policy and its outstanding violation together.

## What enforces it

`tests/plugins/test_the_core_tree_does_not_grow_a_vendor_connector.py`, a **tripwire**:

- the integration module set, pinned by **set equality** — a fifth vendor module fails;
- the vendor subset, pinned at four — the count is the policy;
- the **core registrar** set, pinned at three — a fourth fails.

Both directions in each case. This repo has had an allowlist rot the other way (deleting six
modules left three dead entries in the owner-scope list), and here the lists must also
*shrink* when ESC-133 is answered, or they stop being true.

**It pins the set rather than judging membership.** No sound predicate decides whether a
module is "third-party" — that is semantic, and four static screens have already been built
and deleted in this repo for failing that kind of distinction. What a guard can do is notice
the set changing, which is exactly when the question needs asking.

## Failure modes

| Failure | What happens | What notices |
|---|---|---|
| A fifth vendor module lands in-tree | — | The tripwire, quoting the rule |
| A fourth core site registers an integration | — | The registrar assertion |
| The four move out and the list is not updated | — | The stale half of each assertion |
| Someone argues a vendor module is "generic" | It goes in `_GENERIC` with a written reason | The diff |

## Verification

```bash
uv run pytest tests/plugins/test_the_core_tree_does_not_grow_a_vendor_connector.py -q
#    expect: 3 passed
uv run pytest -m tripwire -q
#    expect: 58 passed (was 55)
ls src/stackowl/integrations/*.py | xargs -n1 basename
#    expect: the ten modules named above, four of them vendor-specific
```

All three RUN on 2026-09-04, not trusted. Mutation-proven: dropping a fifth module into the
package fires the assertion by name.
