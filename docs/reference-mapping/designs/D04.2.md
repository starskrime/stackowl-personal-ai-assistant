# The Split Already Exists. The Defect Was Guessing A Vendor From A URL.

**Item.** D04.2 · Transport adapters — `PARTIAL`, wave 10, order 94.
**Ask.** "Do we need more than chat-completions + Anthropic native?"
**Answer.** No, on measured demand — and the map's premise is wrong. What the item was
worth was a vendor sniff that a standing operator constraint bans.

## The Ask, answered with numbers

**Demand is zero, and it is not close.** `cost_records` holds 130,523 rows from
2026-06-01 to 2026-09-05:

| provider | rows | last call |
|---|---|---|
| NeraAiRaw (a LiteLLM gateway) | 96,937 | 2026-09-05 |
| four ollama-family entries | 33,586 | 2026-07-10 |

**Every call for 57 days has gone through the one gateway**, and the `anthropic`,
`gemini` and `grok` protocols have **never carried a single call** despite being
built.

**And none of the reference's four transports is unreachable through a gateway.**
Read against their code rather than their directory listing: their Vertex and Azure
"adapters" are credential providers feeding the OpenAI SDK — Vertex's own docstring
says "OpenAI-compatible endpoint", Azure's returns a token provider for
`OpenAI(api_key=…, base_url=…)`. Only Bedrock genuinely differs (boto3 `converse()`
with SigV4, not HTTP-bearer) and Codex-responses is a real second wire format — both
reachable through LiteLLM, which does the SigV4 itself. Native Bedrock would add
boto3 to a 7.6 GB Jetson for zero configured users.

## The map's premise is wrong: the split exists

"One shape per provider file; no transport/profile split" — but
`setup/provider_catalog.py:28` defines `PROTOCOLS = ("anthropic", "openai", "gemini",
"grok")`, validated per entry, and `providers/registry.py::_build_provider` dispatches
on `config.protocol`, never on a name. The 49 bundled providers map onto those four:
45 openai-shaped, 2 anthropic, 1 gemini, 1 grok. **`protocol` IS the transport
dimension**, and per-vendor classes *inside* `providers/` are the sanctioned shape —
measured: zero imports of a concrete provider class anywhere outside that package.

## What the item was actually worth

The governing constraint is recorded in `progress.yml`: Bakir runs a single LiteLLM
gateway, his users run many backends, therefore **no code may branch on a provider's
name — dispatch on response SHAPE and declared CAPABILITY**. A memory entry records
him enforcing it once already: *"caught `_output_cap` branching on ollama. General
abstractions, config-driven."*

It was being broken, **twice**:

    providers/model_window.py:268     ":11434" in base_url or "ollama" in base_url.lower()
    providers/openai_provider.py:1283 not (":11434" in base) and not ("ollama" in base.lower())

De Morgan-identical and never diverged — but two copies of one rule, and both wrong
the same two ways: a gateway path like `gw.example.com/ollama/v1` matches, and **so
does a vLLM server on port 11434**, which was then sent an `options.num_ctx` body it
may reject.

**The capability is real; the instrument was a vendor sniff.** Some backends expose a
native metadata endpoint reporting a model's true context length, and no other
OpenAI-compatible server does — a genuine capability difference, unlike `_output_cap`,
which branched on vendor for a *policy* choice.

**So: probe, don't guess.** `_probe_ollama` was already a perfect capability test — it
returns an int or `None` and swallows every error — so guessing first bought nothing.
It is now `_probe_native_window_api`, tried for any backend with a `base_url`, and the
result is recorded as a measured fact. `openai_provider` asks that fact instead of
re-deriving the guess. The vendor name is gone from both dispatch paths.

The irony sat fifteen lines away the whole time: the comment at `model_window.py:271`
describes the live incident where a URL-shaped assumption cost a **32× window error**,
and `config/provider.py:152` already names the pattern — *"a hardcoded guess wearing
discovery's clothes."*

## A second memo needs a second line in every reset — or one seam

Adding `_NATIVE_WINDOW_API` immediately produced cross-test pollution: a test seeded
it, the next test inherited it, and the autouse fixture cleared only `_WINDOW_CACHE`.
The cause was not the new dict — it was that **reset knowledge lived in 15 sites
across 8 test files**, each clearing the cache by hand. They now call
`model_window.reset_window_cache()`, which owns both memos. One source; the tests ask
it.

## Tests that encoded the guess

`tests/providers/test_ollama_num_ctx.py` stated the old contract in its own docstring
— *"(a) the base_url is an ollama-family URL (contains ':11434' or 'ollama')"* — and
`test_model_window.py` pinned the ladder by that selection. Both now assert the
measured fact, and the ollama-shaped URL is deliberately kept in the negative case to
show it no longer decides anything.

## The guard, and the three false positives it produced first

A tripwire now fails any module that decides what a backend IS from a substring of its
address. Aiming it took three corrections, each the same lesson one layer down:

1. a line scan flagged this module's own docstring **describing** the deleted guess;
2. an AST scan of string constants flagged `cli/providers_cli.py`, where
   `"Base URL (e.g. http://localhost:11434/v1)"` is a **prompt hint** shown to the
   operator during setup;
3. the rule finally matches only a **membership test** (`ast.In`/`NotIn`) containing
   the literal — which is the actual defect shape.

Prose about a defect is not the defect, and display text is not dispatch. A positive
control proves the guard still catches a reintroduced sniff.
