# Plugins Must Not Touch Core

**Item.** D16.2 · "Plugins must not touch core" rule — `MISSING`
**Last verified.** 2026-09-04, commit `8154897f`

## Why this exists

The Ask is a build instruction: *"adopt verbatim. Costs nothing, prevents a known decay
mode."* The reference platform's rule is that a plugin may not modify core entrypoints, and
that a plugin needing something the framework does not expose is answered by **widening the
generic surface** — never by special-casing the plugin in core. Adopting it there meant
deleting 95 lines of hardcoded plugin argparse from `main.py`.

**The decay mode is not hypothetical here. It has already happened once.**
`local_loader.py` records it: D08.2 added `MemoryProvider` to the ABC table and not to the
registry table, so `_registries.get("MemoryProvider")` returned `None` and registration hit
`continue` — **silently**. A memory-provider plugin would have loaded and registered
nowhere, with every table looking correct.

## What the rule is

> A plugin may not require an edit to a core entrypoint — `cli/app.py`,
> `startup/orchestrator.py`, `runtime/`, `pipeline/`. If a plugin needs something the
> framework does not expose, widen the generic surface. Never special-case the plugin in
> core.

Stated in `src/stackowl/plugins/__init__.py`, which was empty. That is where someone about
to add a ninth extension point actually looks — not in a document they would have to know
exists.

## Half of it was already enforced

The "widen the surface" half is enforced by construction and by two tests that predate this
item:

| guard | what it asserts |
|---|---|
| `test_every_declared_extension_point_can_register.py` | `set(_ABC_NAMES) == set(loader._registries)`, both directions |
| `TestEveryDeclaredSlotIsActuallyWired` | reads the **real construction site** in `orchestrator.py`, because the check above passes even when a slot's *value* is `None` |

The second exists because the first is not sufficient — the D08.2 defect wearing a different
hat. That pair is the reason this item found less to build than its `MISSING` verdict
suggests.

## What this item added

`tests/plugins/test_core_reaches_the_plugin_surface_and_nothing_else.py`, a **tripwire** over
the whole tree. Of **841 modules in `src/stackowl`, exactly seven** outside the plugin
package may import it:

| module | why |
|---|---|
| `tools/base.py`, `sessions/store.py`, `providers/base.py` | the three seams that **dispatch** lifecycle hooks — they name a hook *point*, never a plugin |
| `startup/orchestrator.py` | boot: the one place that constructs the loader and hands it every registry |
| `cli/app.py`, `commands/assembly.py`, `commands/permissions.py`, `commands/plugins_command.py` | plugin **management** — install, list, enable, verify. Generic by construction; none names a plugin |

**Set equality, not subset, and that is the point.** This repo has been bitten by an
allowlist rotting the other way: deleting six modules left three of their entries in the
owner-scope allowlist, and a subset check cannot see that. Both directions fail loudly.

It is marked `@pytest.mark.tripwire` because a guard that protects the whole repo looks
related to nothing, so no targeted path would ever pick it up. The marker is the source: the
gate went from 50 tests to 55 with no path list edited.

## What is NOT enforced, stated rather than implied

**"Core must not special-case a plugin" cannot be screened directly today.** The decay it
forbids looks like `if plugin_name == "foo"`, and with **zero plugins installed** there is no
name to look for. Any such screen would be a zero over a zero denominator — the failure this
repo has refused three times this week, and four static screens have already been built and
deleted here for a similar unsound distinction.

The import-direction tripwire is the closest proxy that has a real denominator, because
reaching into the plugin package is the first move of every special case. When the first
plugin is installed the direct screen becomes possible, and should be written then.

## Configuration

None. A rule and a tripwire; both ship ON.

## Failure modes

| Failure | What happens | What notices |
|---|---|---|
| Core grows a new plugin import | — | The tripwire, naming the module and quoting the rule |
| The allowlist goes stale | — | The same test, other direction |
| A ninth extension point declared, not wired | Plugin registers nowhere, silently | The two pre-existing parity tests |
| Core special-cases a plugin by name | **Nothing today** | Stated openly above; needs a plugin to exist |

## Verification

```bash
# 1. The tripwire, both directions and the denominator check.
uv run pytest tests/plugins/test_core_reaches_the_plugin_surface_and_nothing_else.py -q
#    expect: 5 passed

# 2. The plugin package is unaffected.
uv run pytest tests/plugins -q          # expect: 104 passed

# 3. It joined the gate by its marker, not by a path list.
uv run pytest -m tripwire -q            # expect: 55 passed (was 50)
```

All three RUN on 2026-09-04, not trusted. Mutation-proven in **both** directions: adding a
`stackowl.plugins` import to `infra/turn_model.py` fires the "newly reaching into" assertion;
adding a stale name to `_SURFACE_CALLERS` fires the "no longer imports" assertion.
