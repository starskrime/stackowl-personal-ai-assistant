## Why this exists

The reference platform states it outright: its dashboard **embeds** `hermes --tui` through a
PTY rather than reimplementing the chat in React. Structured UI around it is fine; a second
transcript or composer is not. The Ask: *"Adopt as a written rule before building surface
#4?"*

**Yes — and the value is entirely in the timing.** A rule about surface sprawl is worth
almost nothing once the fourth surface exists and has its own transcript; it is worth a great
deal while there are three and the property still holds by accident. ESC-152 is open on
whether to build a dashboard at all, which makes this the right moment rather than an
awkward one: whatever that answer is, the sprawl is bounded before the work starts.

## Model — the same guarantee, a different mechanism

We cannot copy their mechanism, and the reason is structural rather than stylistic: **our
conversation does not live in the TUI to be embedded.** It lives behind the `ChannelAdapter`
seam.

| | Reference platform | StackOwl |
|---|---|---|
| where the chat lives | in the TUI (Ink/React) | behind `ChannelAdapter` |
| how a second surface reuses it | embeds the TUI over a PTY | implements the adapter |
| what the rule forbids | a second transcript/composer in React | building turn state to run a turn |
| the payoff | anything added to the TUI appears in the dashboard | **anything added to the pipeline appears on every surface** |

A surface's whole job is to turn input into an `IngressMessage` and render `ResponseChunk`s.
Sessions, transcript, tool loop, model calls and slash routing all sit behind that line, and
there is exactly one turn entry point — `_dispatch_turn`, which `pipeline/durable/
agent_task.py` *shares* behind a generic `_IntakeAdapter` rather than opening a second one.

## The rule, and its one exception

**A surface may build the minimal `PipelineState` a slash COMMAND needs**, because commands
dispatch through one `CommandRegistry` every surface shares. **A surface may never build
state to run a TURN** — that is a second conversation, and the second one is where the
transcript, the session and the tool loop quietly fork.

Measured 2026-09-06, the tree already obeys this:

| | count | detail |
|---|---|---|
| modules constructing `IngressMessage` | **10** | 7 under `channels/`, plus 3 intake-path modules |
| turn entry points | **1** | `_dispatch_turn` |
| `channels/` modules constructing `PipelineState` | **2** | both dispatch a command |

The two are `slack/slash_bridge.py` (6 registry references, **0** pipeline-runner
references) and `telegram/command_buttons.py` (5 and **0**). telegram's own comment states
the intent: it replays "through the SAME `CommandRegistry.dispatch` path a typed slash
command uses". For contrast, `objectives/driver.py` builds turn state with **zero** registry
references — an autonomous driver legitimately running a turn, which is not a surface and is
not covered by the rule.

## Invariants

1. **`IngressMessage` is constructed only by a surface or the declared intake path** —
   `gateway/scanner.py` (defines it, scans for signals), `runtime/message_bridge.py` (carries
   it across the process split), `startup/orchestrator.py` (the turn entry point). A fourth
   is a decision someone makes on purpose, not a drift.
2. **A `channels/` module that builds `PipelineState` must dispatch through
   `CommandRegistry`** and must not reference a pipeline runner.
3. **The rule is written where a human reads it** — `PROCESS.md`'s standing rules — not only
   asserted in a test.

## Configuration

None. This is an architectural constraint, not a setting; a flag that turned it off would be
permission to build the thing it forbids.

## Observability

None — it is a static property, checked at test time rather than watched at runtime. That is
the right shape: a violation is a code change, not an event.

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| A new surface builds its own turn | the tripwire (2 assertions fire) | — | eventually: a transcript that disagrees with the other surfaces' |
| A module outside the seam opens a second front door | the ingress tripwire | — | messages entering by a path nothing else guards |
| A third channel module starts building command state | the canary test | it is not necessarily wrong — a human decides | — |
| The rule is deleted from PROCESS.md | the written-rule tripwire | — | — |

The third row is deliberately a canary rather than a rule. Two command bridges are the
narrow legitimate case; a third is worth a human noticing, because each one is a surface
reaching one step past the ingress seam.
