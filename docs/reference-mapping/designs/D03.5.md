## Why this exists

A model's real context window is not knowable from its name, and guessing it wrong is
expensive in both directions. This component was built after finding a model running at
**8,192 tokens when its real window was 262,144** — the platform was throwing away 97% of
the context it had paid for, silently, because a default said so.

The reference platform keeps a hand-maintained catalog of context lengths. We probe the
live endpoint instead, which is why this item is `AHEAD`: a probe cannot go stale.

## Model

`resolve_window` is one `elif` chain and the order IS the order of trust. This section
used to name three sources; the chain has five branches behind a cache, and the counts
beside them are measured across every retained log rather than asserted:

| # | Branch | Emits | Fired |
|---|---|---|---|
| 0 | `_WINDOW_CACHE` hit | — | per process |
| 1 | **Config override** — `context_chars` set | `config override` (DEBUG) | not observable at INFO |
| 2 | **Native metadata probe** — any backend with a `base_url`, asked for the model's real context length | `resolved via native metadata probe` (INFO) | **0** |
| 3 | **Cloud default** — a known protocol with no `base_url` | `cloud default` (DEBUG) | not observable at INFO |
| 4 | **OpenAI-compatible probe** — ask the endpoint what it accepts | `resolved via openai-compatible probe` (INFO) | **264** |
| 5 | **The probe-failure floor** — `DEFAULT_WINDOW_FALLBACK`, provisional | `probe FAILED — …` (**WARNING**) | **27** |
| — | **A rejection that names the window** — not a branch here; `learn_window_from_error` writes the cache out of band | `learned the real context window …` (INFO) | **0** |

**Branch 2 was added on 2026-09-05 by `4cb832ac` and this document did not have it.**
It replaced `_probe_ollama`, which was selected by a substring guess at a vendor from its
URL — a guess that matched a gateway path like `gw.example.com/ollama/v1` and any other
server on port 11434, and missed a backend speaking the endpoint on any other address.
The capability is real (some backends expose a native metadata endpoint stating a model's
true context length; most OpenAI-compatible servers do not), so it is now a capability
TEST rather than a vendor guess: the call returns an int or `None` and swallows every
error, which costs one fast miss and buys the right answer where it exists.

**It has never answered here, and the evidence for that is the NEXT branch firing.** A
miss is logged at DEBUG, so production carries no record of the attempt — but branch 4 is
reachable only when branch 2 returned falsy, so each of those 264 records is itself proof
that the native probe was tried and missed. This deployment's only backend is the LiteLLM
gateway, which does not speak that endpoint. That is NO OPPORTUNITY, not a broken rung.

**Source 2 in the old list — a rejection that names the window — has fired ZERO times**,
ever, across every retained log, and so has its rejection-implausible sibling. It is
still the right design (a provider stating its real limit while refusing a call is free
information) and it is unexercised, which the old wording gave no way to tell.

An entry that came from the floor is marked **provisional** in a process-local map, so it
can be told apart from a measured one later. The floor path is 27 of 291 resolutions —
**9.3%** — and both outcomes are now distinguishable in the log, which they were not
before 2026-09-02, when a failed probe and a successful one emitted the same line.

## Lifecycle

Probe on first need per (provider, model). A failure caches the floor as provisional. When
the provider becomes reachable again, provisional entries for it are dropped so the next
call re-probes — `provider recovered — dropping windows that were the probe-failure floor`.
A measured window is never dropped by that path.

## Invariants

1. **A failed probe is not a measurement.** The floor is cached so the platform keeps
   working, but marked provisional so it is never mistaken for the truth.
2. **The floor is below every window this platform has met.** 100,000, lowered from
   1,000,000 by Bakir on 2026-09-01 after a live incident. Under-estimating costs context;
   over-estimating costs the whole call.
3. **Recovery drops only provisional entries.** A real measurement survives it.

## Configuration

`DEFAULT_WINDOW_FALLBACK = 100_000` — a constant, not a setting, because it is a safety
floor rather than a tuning knob. `STACKOWL_CONTEXT_CEILING` optionally caps the resolved
window; an unparseable value is ignored with a logged warning rather than treated as zero.

## Observability

**"All at INFO" was wrong on two of five, MEASURED 2026-09-07 by walking the module's
`log.*` calls rather than reading this list.** The correction matters because this
programme's own rule is that a claim's evidence must be at INFO — production runs there —
and a document that files WARNING lines under INFO understates what an operator sees while
a document that files INFO lines under DEBUG would overstate it.

| Line | Level | Fired (all retained logs) |
|---|---|---|
| `resolved via openai-compatible probe` (with `probed`, `window`) | INFO | 264 |
| `resolved via native metadata probe` | INFO | 0 |
| `learned the real context window from the provider's own rejection` | INFO | 0 |
| `provider recovered — dropping windows that were the probe-failure floor` | INFO | 1 |
| `fallback window` | INFO | 0 |
| `probe FAILED — using the probe-failure floor` | **WARNING**, not INFO | 27 |
| `a rejection stated an implausible context window — refusing it` | **WARNING**, not INFO | 0 |
| `could not read a window from the rejection` | WARNING | — |
| `invalid STACKOWL_CONTEXT_CEILING — ignoring (no cap)` | WARNING | — |
| `config override`, `cloud default`, `invalidate`, `native metadata probe did not answer`, `openai-compatible probe request failed`, `openai-compatible probe — no context-limit stated` | DEBUG | invisible in production |

WARNING is the right level for both corrected lines — a floor in place of a measurement
is a degraded state, and an implausible stated window is a provider misbehaving — so the
fix is to the document, not to the code.

**The DEBUG row is the one to read twice.** Six of this module's lines never reach a
production log, and one of them is the only direct record that branch 2 was attempted.
That is survivable here for the reason given under *Model* — branch 4 firing proves
branch 2 missed — but it is survivable by DEDUCTION, not by instrumentation, and the
deduction stops working the moment a backend answers the native endpoint and branch 4
stops firing for it.

## Failure modes

| What fails | What happens |
|---|---|
| Endpoint unreachable | Floor cached as provisional; logged at INFO; the turn proceeds with less context |
| Rejection states an implausible window | Rejected as a measurement, logged, floor retained |
| `STACKOWL_CONTEXT_CEILING` unparseable | Ignored, warned, no cap applied |
| Process restarts mid-outage | Provisional entries are lost with the process — harmless, the next call simply re-probes |
