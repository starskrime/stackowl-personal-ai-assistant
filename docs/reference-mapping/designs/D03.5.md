# Context-Window Discovery

> **Status:** live
> **Map item:** D03.5 · Context-window discovery (`AHEAD` — keep ours)
> **Source:** `src/stackowl/providers/model_window.py` (~430 lines)
> **Config:** `STACKOWL_CONTEXT_CEILING` (optional env cap); `DEFAULT_WINDOW_FALLBACK = 100_000`
> **Last verified:** 2026-09-04, against commit `3638470d`

## Why this exists

A model's real context window is not knowable from its name, and guessing it wrong is
expensive in both directions. This component was built after finding a model running at
**8,192 tokens when its real window was 262,144** — the platform was throwing away 97% of
the context it had paid for, silently, because a default said so.

The reference platform keeps a hand-maintained catalog of context lengths. We probe the
live endpoint instead, which is why this item is `AHEAD`: a probe cannot go stale.

## Model

Three sources, in strict order of trust:

1. **The probe** — ask the live endpoint what it accepts (`resolved via openai-compatible
   probe`). This is the only MEASURED value.
2. **A rejection that names the window** — providers often state the real limit while
   refusing an over-long call; that number is learned rather than discarded.
3. **The probe-failure floor** — `DEFAULT_WINDOW_FALLBACK`, used only when the endpoint
   cannot be reached at all.

An entry that came from the floor is marked **provisional** in a process-local map, so it
can be told apart from a measured one later.

## Lifecycle

Probe on first need per (provider, model). A failure caches the floor as provisional. When
the provider becomes reachable again, provisional entries for it are dropped so the next
call re-probes — `provider recovered — dropping windows that were the probe-failure floor`.
A measured window is never dropped by that path.

## Invariants

1. **A failed probe is not a measurement.** The floor is cached so the platform keeps
   working, but marked provisional so it is never mistaken for the truth.
2. **The floor is below every window this platform has met.** 100,000, lowered from
   1,000,000 by Bakir on 2026-09-01 after a live incident. Under-estimating costs context;
   over-estimating costs the whole call.
3. **Recovery drops only provisional entries.** A real measurement survives it.

## Configuration

`DEFAULT_WINDOW_FALLBACK = 100_000` — a constant, not a setting, because it is a safety
floor rather than a tuning knob. `STACKOWL_CONTEXT_CEILING` optionally caps the resolved
window; an unparseable value is ignored with a logged warning rather than treated as zero.

## Observability

All at INFO: `resolved via openai-compatible probe` (with `probed` and `window`), `learned
the real context window from the provider's rejection`, `probe FAILED — using the
probe-failure floor`, `provider recovered — dropping windows that were the...`, and
`a rejection stated an implausible context window`.

## Failure modes

| What fails | What happens |
|---|---|
| Endpoint unreachable | Floor cached as provisional; logged at INFO; the turn proceeds with less context |
| Rejection states an implausible window | Rejected as a measurement, logged, floor retained |
| `STACKOWL_CONTEXT_CEILING` unparseable | Ignored, warned, no cap applied |
| Process restarts mid-outage | Provisional entries are lost with the process — harmless, the next call simply re-probes |
