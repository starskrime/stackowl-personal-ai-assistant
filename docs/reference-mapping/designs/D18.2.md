# The Annotated Example Is Worth Having — Their Way Of Maintaining It Is Not

**Item.** D18.2 · Config surface & loaders — `DIVERGENT`, wave 9, order 85.
**Ask.** "Keep ours. Adopt their annotated example file as a docs artifact?"
**Answer.** Adopt the ARTIFACT. Reject the MAINTENANCE MODEL. Generate it from `Settings`.

## Why this exists

The divergence the map records is real and settled in our favour, and re-measuring
confirmed it rather than assuming it. The reference platform has **three** config loaders
with a documented "know which one you are in" warning — an acknowledged wart. StackOwl has
**one**: `settings_customise_sources` returns `(env_settings, _YamlSource(settings_cls,
config_path))`, and that is the whole story. Nothing to adopt there.

The half worth taking is the annotated example file, and the reason is a number:

    settable fields                      210
    top-level sections                    33   (36 nested models at every depth)
    top-level scalars                     19   → 52 top-level keys
    fields carrying a Field(description)  107   (50%)
    example config in the repo before      0

**An operator's only route to the configuration surface was reading 1,100 lines of
`settings.py`.** That is the gap, and it is a real one.

## But their maintenance model is the shape `CLAUDE.md` names as shape 3

Theirs is **1,616 hand-written lines**. That is a second copy of the configuration surface,
correct only until someone adds a field and forgets — *two copies of one rule*. Hand-writing
210 entries here would be stale inside a week, and a stale config reference is worse than
none, because the one operator who trusts it is misled by it.

So the artifact is **GENERATED**. `scripts/gen_config_example.py` walks `Settings` and emits
every field with its default and its own `Field(description=...)` as a comment.
`tests/test_the_example_config_cannot_go_stale.py` regenerates and compares **bytes**, so
adding a setting without regenerating fails the gate. One source; the other asks it.

Two properties make it documentation rather than decoration, and both are asserted:

- **It round-trips.** `yaml.safe_load` it, `Settings(**data)` accepts it. A "documentation"
  file that would not actually load teaches the one person who tries it that the docs are
  decorative.
- **It invents nothing.** A field with no description emits no comment rather than a guessed
  one, so the file shows honestly where the model's own documentation stops — 107 of 210.

## The defect the guard found, which is the real finding here

The byte comparison failed under pytest and passed everywhere else. Diffed three ways:
generator directly **0 diff**, subprocess outside pytest **0 diff**, subprocess **inside**
pytest **11 diff lines**. `conftest` redirects `STACKOWL_HOME` to a tmpdir, and four browser
defaults resolve against it:

    screenshots_dir: /home/boss/.stackowl/screenshots
    profiles_dir:    /home/boss/.stackowl/browser-profiles
    downloads_dir:   /home/boss/.stackowl/workspace/downloads
    browser_cache_dir: /home/boss/.stackowl/cache/browser

**That is not a test-environment quirk to work around. It is three defects in the artifact,
and the failing guard is how they were found:**

1. The checked-in file carried **absolute paths that are wrong on every other machine** —
   the opposite of what a portable example config is for.
2. It **leaked the operator's home directory name** into a docs artifact intended for
   publication. Same family as D18.1's host-specific finding: a machine's property must not
   be shipped as a user's configuration.
3. It was **not reproducible**, which is what made the guard unenforceable.

One fix answers all three: `_symbolic_home()` renders a home-derived `Path` as
`~/.stackowl/...`. Machine-independent, username-free, byte-stable — and the guard works
*because* the artifact is now correct, not the other way round.

**What else does that cause reach?** Any generator that emits a resolved `Path` default into
a committed artifact. This is the only such generator in the tree today (measured: no other
script writes into `docs/`), so the fix is complete rather than exemplary — but the rule the
guard now enforces is the general one: **a checked-in derived artifact must not embed a value
that only exists on the machine that derived it.**

## What was NOT adopted, recorded so it is not re-proposed

- **Three loaders.** Ours is one, and the reference documents theirs as a wart.
- **A hand-maintained 1,616-line file.** The artifact, not the method.
- **Inventing descriptions for the 103 fields that lack one.** The gaps are the model's, and
  papering over them in a generated file would hide where the documentation actually stops.
  Writing those 103 descriptions is real work; it belongs in `settings.py`, where the
  generator would pick them up for free.

## Verification

```bash
uv run pytest tests/test_the_example_config_cannot_go_stale.py -q   # 4 passed
uv run python scripts/gen_config_example.py | diff - docs/stackowl.yaml.example && echo IN-SYNC
grep -c "/home/" docs/stackowl.yaml.example                        # expect: 0
uv run python - <<'EOF'
import yaml
from stackowl.config.settings import Settings
Settings(**yaml.safe_load(open("docs/stackowl.yaml.example")))
print("round-trips")
EOF
```

All RUN on 2026-09-05, not trusted. **Mutation-proven:** adding a field to `Settings` without
regenerating fails `test_the_checked_in_example_matches_the_model` with the message naming
the command to run. Restored from a file copy and re-run green.
