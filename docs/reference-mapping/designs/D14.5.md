## Why this exists

The reference platform ships skins as **pure data** (`~/.hermes/skins/*.yaml`) customising
banner colours, spinner faces and verbs, tool prefix, response box and branding, switched at
runtime by `/skin`; plus a pet mascot and token-free affection detection over a curated
lexicon (`ily`, `<3`, `good bot`) with no model call. The Ask: *"Personality-as-product.
Matters for 'Jarvis for everyone'?"*

**That is appetite, not measurement, so it is not answered here.** What the measurement does
settle is what the phrase covers, because "theming" turns out to be three separate things
with three different answers.

## Model — their theming is three things, not one

| Their part | Ours | Verdict |
|---|---|---|
| **Skins** — banner colours, spinner faces, tool prefix, response box, branding | nothing | **genuinely absent** |
| **Pet / mascot** (`agent/pet/`, `/hatch`, `/pet`) | nothing | not a capability — already classified in D14.2 |
| **Affection detection** over a curated English lexicon, no model call | `FeedbackClassifier` | **deliberately refused** — see below |

**What we have that looks adjacent but is not theming.** `tui/glyphs.py` and
`tui/color_caps.py` are terminal **capability detection**: the first is a "BMP glyph registry
with ASCII fallbacks for non-Unicode terminals", the second classifies the host terminal into
colour tiers so the TUI can load a matching stylesheet. They adapt the platform *to* the
terminal; they do not let anyone choose a look. `UISettings` carries `language`,
`tui_version`, `reduced_motion`, `command_suggestions`, `semantic_command_search` and
`command_hints` — one accessibility toggle and five behaviour switches, no colour, banner or
branding anywhere.

**And personality-as-BEHAVIOUR is substantial here, which is the part the Ask's phrase
hides.** Owl DNA gives each owl its own persona; `/style` shows the enforced output style per
channel; learned output preferences are written from real feedback. What is missing is
visual chrome, not character.

## The third part is not a gap — it is a decision already made

Their affection detection matches a curated list of English tokens. `FeedbackClassifier`'s
own docstring refuses exactly that, and names the reason:

> **LLM-semantic, multilingual, no keyword lists.** Per `[[feedback_no_hardcoded_english]]`
> the platform is multilingual, so we do NOT match English words against the user's MESSAGE.
> The fast-tier model does the semantic classification (in any language) and emits JSON whose
> VALUES are enum tokens WE define … A short non-English praise classifies purely by the
> model's verdict.

Measured: **no praise or affection lexicon exists anywhere in `src/`.** Adopting their
approach would mean a user who writes "gracias" or "спасибо" is not heard, which is the
failure the standing rule exists to prevent. Their version is cheaper — no model call — and
that is the trade they took; ours costs a fast-tier classification and works in any language.

This is the same shape as D14.2's `/blueprint`: a reference feature that is absent here
because a recorded decision refuses it, not because nobody got to it.

## Invariants

1. **Capability detection is not theming.** `glyphs.py` and `color_caps.py` respond to what
   the terminal can render; neither takes a user preference.
2. **No English lexicon may decide what a user's message means.** Enum tokens the platform
   defines are parsed; the user's free text never is.

## Configuration

`ui.language` and `ui.reduced_motion` are the only settings that touch presentation, and
`reduced_motion` is accessibility rather than taste. There is no skin, palette or banner key,
and this item adds none.

## Observability

None added — nothing was built.

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| A terminal cannot render Unicode | `glyphs.py` probe | ASCII fallbacks | a plainer TUI, automatically |
| A terminal is colour-poor | `color_caps.py` tier detection | a matching stylesheet | fewer colours, automatically |
| A user wants a different look | — | none; no skin system exists | the one look there is |
