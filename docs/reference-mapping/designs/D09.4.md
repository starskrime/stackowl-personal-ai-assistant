# Turn Nudges

> **Status:** live
> **Map item:** D09.4 (the mechanism is shared with D08.3's memory nudge)
> **Source:** `src/stackowl/infra/nudge.py` (90 lines), `src/stackowl/skills/nudge.py`
> (73 lines); wired in `src/stackowl/pipeline/steps/execute.py::_turn_context_prefix`
> **Config:** none user-facing — two module constants (see Configuration)
> **Last verified:** 2026-09-02, against commit `e782e6b4`

## Why this exists

The agent will not volunteer meta-work. Measured all-time: `evolve_now` **0**
invocations, `synthesize_skills` **0**, `reflect_now` **11** since June — against
`note_applied_lesson` at **791**. A tool that records something as a *byproduct* of
answering is used constantly; a tool that asks the model to stop and do housekeeping
instead of finishing the user's request is never chosen. That is an incentive shape, not
a discoverability problem, and presenting those tools harder would not change it.

**But "it will not volunteer" does not mean "asking cannot work", and that distinction is
the whole item.** Measured 2026-09-02 across five days of rotated logs, on the memory
nudge — the same mechanism with different words:

| | |
|---|---|
| `[curated] nudge: due` fired | **96** |
| followed by a write within 10 minutes | **27 (28%)** |
| share of *all* 35 writes that followed a nudge | **77%** |

Asked at the right moment the model complies about a quarter of the time, and that
quarter is where nearly all the writes come from. Building this on the "never chosen"
finding alone would have been the wrong call; measuring the existing nudge's conversion
is what made it the right one.

## Model

| Concept | Meaning |
|---|---|
| **lane** | The conversation the counter belongs to (`session_key`). Counted separately, so one chat's turns never trigger another's nudge. |
| **interval** | Turns between nudges. Memory **4**, skills **10**. |
| **action reset** | Doing the thing zeroes the counter — nudging immediately after a write is the fastest way to teach the model to ignore the nudge. |
| **gate** | Names the model can actually call this turn. The skill nudge is silent unless `skill_manage` is among them, and silent when the set is unknown. |

## Lifecycle

```
_turn_context_prefix(state, presented_tools)
  ├─ curated.note_turn(lane)              interval 4,  ungated
  │     └─ TurnNudge.note_turn → text or None
  └─ skills.nudge.note_turn(lane, presented)
        ├─ presented is None            ──► silent   (fails closed)
        ├─ skill_manage not presented   ──► silent
        └─ else TurnNudge.note_turn     ──► text or None

memory tool writes  → curated.note_write(lane)      → counter = 0
skill written       → skills.nudge.note_skill_written(lane)
```

The nudge rides the **volatile per-turn context**, never the system prompt. The prompt is
frozen per incarnation, so a nudge placed there would be present for an entire
conversation or absent from all of it.

## Invariants

> **I1.** A nudge fires on the interval and not before.
> **I2.** The skill nudge is silent unless `skill_manage` is in the presented set.
> **I3.** An unknown presented set yields no nudge — fails closed.
> **I4.** Doing the action resets that lane's counter.
> **I5.** Lanes are counted independently.
> **I6.** The skill interval is strictly longer than the memory interval.
> **I7.** The counter never raises; a reminder may not cost a turn its answer.
> **I8.** Memory and skills share one counter implementation — no inline copy.

All eight map to tests in
`tests/skills/test_the_platform_asks_whether_this_was_a_skill.py` (9 tests).

**I2 is the one this project already paid for.** `skills_list` showed zero invocations for
eight days, and the cause was not that the model ignored it — on those turns it was **not
in the presented set** to call. Nudging toward a tool the model cannot reach would
manufacture that failure on purpose.

## Configuration

| Constant | Value | Why |
|---|---|---|
| `NUDGE_INTERVAL_TURNS` (memory) | 4 | Lowered from a larger value in 2026-08-17 after boots were found to dominate the counter |
| `SKILL_NUDGE_INTERVAL_TURNS` | 10 | A durable fact appears in most conversations; a reusable procedure does not. A nudge that fires with nothing to record trains the model to ignore it. Same value the reference platform uses. |
| `SKILL_TOOL` | `skill_manage` | The tool the nudge points at, and the gate |

No settings key, no toggle. Both nudges are unconditional given their gate.

## Observability

- `[curated] nudge: due` — INFO. `_fields`: `session_key`, `turns`.
- `[skills] nudge: due` — INFO, same fields.
- `[pipeline] execute: skill nudge FAILED — continuing without it` — ERROR.

```bash
cat ~/.stackowl/logs/stackowl.jsonl \
  | jq -c 'select(.msg | endswith("nudge: due")) | {ts, msg, lane: .fields.session_key}'
```

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| Counter raises | `except Exception` in `TurnNudge` | WARNING, no nudge this turn | Nothing |
| Presented set unreadable | `_presented_names` returns None | Skill nudge stays silent | Nothing |
| `skill_manage` not presented | gate in `skills.nudge.note_turn` | Silent | Nothing |
| Import/wiring failure | `except Exception` at the call site | ERROR, turn continues without the nudge | Nothing |

Nothing here can fail a turn. The worst case is a missing reminder.

## Related

- Map items: `D08.3` is the memory nudge this shares its mechanism with; `D09.1` supplied
  the "never volunteers" measurement whose obvious reading this item refutes.
- **Why validate is `partial`, with the number.** Across the retained window — 1,941
  turns with a lane, 180 shutdowns, 82 windows containing turns — the maximum turns on a
  *single* lane per restart window reaches ≥4 in **13 of 82 (16%)** and ≥10 in **5 of 82
  (6%)**. So this nudge can fire and will, at roughly an eighth the memory nudge's rate;
  the dominant limiter is restart frequency, which is the development loop's cadence
  rather than production behaviour. It has fired **0** times so far.
- **Prior art and where we diverged.** The reference platform uses `_iters_since_skill`
  with `skills.creation_nudge_interval` (default 10), gated on `skill_manage` being in the
  tool set. We took the interval, the gate and the idea. We did **not** copy its counter:
  ours was already implemented for memory, so the mechanism was extracted to
  `infra/nudge.TurnNudge` and both callers share it — two copies of a per-lane counter is
  the duplication shape this codebase keeps paying for.
