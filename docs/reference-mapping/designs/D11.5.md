# Trajectory Capture — the Corpus Already Exists, and It Is Labelled

**Item.** D11.5 · Trajectory capture for training — `MISSING`
**Last verified.** 2026-09-04, commit `7953dab6`

## Why this exists

The Ask — *"Out of scope, or does the 'agentic OS' vision want its own training data?"* — is
strategy, and stays the operator's (**ESC-131**). Nothing was built. What this item did was
correct the entry and make the question decidable.

**The map says "StackOwl. Nothing." That is wrong**, in the same way D10.4's "no install
path" was wrong. There is no batch trajectory generator and no compressor. But the
*trajectories themselves* are captured, in quantity, and already carry a label.

## What is actually captured

`task_outcomes` — **20,276 rows**, one per turn, keyed by `trace_id`:

| field | fill rate | what it is for training |
|---|---|---|
| `input_text` | **100%** | the prompt |
| `tool_sequence` | **100%** | the tool calls, normalised, in order |
| `tool_call_count` | 100% | trajectory length |
| `success` | 100% | the label |
| `dna_snapshot` | 100% | the agent configuration that produced it |
| `response_text` | 99% | the completion |
| `failure_class` | 52% | *why* it failed, where it did |
| `quality_score` | 47% | a graded label |
| `model` | see below | which model produced it |
| `approach_rating` | 0.3% | 56 rows |

A real `tool_sequence` row looks like
`["browser_navigate","browser_extract","browser_extract","browser_navigate",…]`.

Six further tables join on the same `trace_id` and hold rows: `cost_records` (130,420),
`reflections` (6,427), `messages` (3,841), `approach_rating_pending` (1,427),
`turn_decisions` (766), `message_ledger` (498).

## The 11% that was not a defect

`task_outcomes.model` is populated in 2,346 of 20,276 rows — **11%**. Read alone, that is a
column wired on only some paths, which is shape 1 in `CLAUDE.md` and the exact thing this
programme keeps finding.

It is not. **Check what the denominator is made of.**

| era | stamped |
|---|---|
| 2026-05-27 → 07-15 | 0 of 5,069 |
| 07-15 → 08-01 | 0 of 5,069 |
| 08-01 → 08-17 | 0 of 5,069 |
| **08-17 → 09-04** | **2,346 of 5,069** |

Three quarters of the denominator predate the feature. ESC-47/50 shipped it, and the first
stamped outcome is 2026-08-24 21:57. **Since then: 2,346 of 2,599 — 90%.**

And the missing 10% is not a gap either:

| slice, since the feature shipped | stamped |
|---|---|
| turns with 1+ tool calls | **1,353 / 1,354 — 99%** |
| zero-tool turns that succeeded | **770 / 770 — 100%** |
| zero-tool turns that failed | 223 / 475 — 46% |

Every one of the 253 unstamped outcomes carries a failure class, and **246 of them are
`AllProvidersUnavailableError`** — no provider was reachable, so no model ran. The remaining
seven are `feedback_rejected` (6) and `stop` (1).

**An empty stamp on a turn where no model ran is the correct value**, not a missing one.
`turn_model.set_model` is called once, after the provider plan resolves, deliberately
covering both the tool-loop and plain-stream paths; a turn that never resolved a plan has
nothing to name. The stamp is honest.

This also settles, from the other side, the drop of `messages.model` in D11.1: model
attribution is covered by `cost_records` at 100% and by `task_outcomes` on effectively every
turn where a model ran.

## What is genuinely missing

The reference platform's three pieces — batch trajectory *generation*, a *compressor*, and
the training-oriented export around them. We have the corpus and no way to get it out in a
training shape. That is the same shape as D11.4: the data exists, the export does not.

## Verification

```bash
# 1. The corpus and its fill rates.
sqlite3 ~/.stackowl/workspace/stackowl.db "
  SELECT COUNT(*),
         SUM(input_text IS NOT NULL AND input_text <> ''),
         SUM(tool_sequence IS NOT NULL AND tool_sequence <> ''),
         SUM(success IS NOT NULL)
  FROM task_outcomes;"
#    expect: 20276, 20276, 20276, 20276

# 2. The 11% is history, not a broken path.
sqlite3 ~/.stackowl/workspace/stackowl.db "
  SELECT COUNT(*), SUM(model IS NOT NULL AND model <> '') FROM task_outcomes
  WHERE captured_at >= (SELECT MIN(captured_at) FROM task_outcomes
                        WHERE model IS NOT NULL AND model <> '');"
#    expect: 2599 and 2346 — 90%

# 3. The unstamped remainder had no model to name.
sqlite3 ~/.stackowl/workspace/stackowl.db "
  SELECT failure_class, COUNT(*) FROM task_outcomes
  WHERE (model IS NULL OR model = '')
    AND captured_at >= (SELECT MIN(captured_at) FROM task_outcomes
                        WHERE model IS NOT NULL AND model <> '')
  GROUP BY 1 ORDER BY 2 DESC;"
#    expect: AllProvidersUnavailableError 246, feedback_rejected 6, stop 1
```

All three RUN on 2026-09-04, not trusted.
