# MCP — the Doctrine Was Already Adopted; the Evidence Line Was Not

**Item.** D16.5 · MCP — `PARITY`
**Last verified.** 2026-09-04, commit `cb2b9d6f`

## Why this exists

The Ask is narrow and deliberate: *"adopt the **doctrine** (MCP before core tool), not the
code."* The reference platform treats MCP as **rung 5** of its footprint ladder, above adding
a new core tool.

**It is already adopted.** `PROCESS.md` states the Footprint Ladder — *take the highest rung
that solves it*:

> extend existing code → CLI command + skill → service-gated tool → plugin → **MCP server** →
> new core tool (last resort)

MCP is rung 5 and a new core tool is the last resort. That is the doctrine, in the file every
architect stage must cite. Nothing needed adopting.

**And the code is there, both directions.** `client.py` consumes MCP servers (with
`allowlist.py`, `probe.py`, `cache.py`); `server.py`, `tool_exposure.py` and `sse_encoder.py`
expose StackOwl as one. The map's claim holds.

## What measurement found

**MCP has never run.** Zero `mcp.*` messages across all nine daily logs, against a control of
**1,521** `transcript.record_turn: exit` lines in the same files — the instrument reads, and
no MCP server is configured.

**And if one were, the operator could not see it.** Of 117 log calls in the package, **two
were INFO** and 82 were DEBUG. Production runs at INFO, so the two questions an operator asks
after configuring a server —

- *did it connect, and how many tools did it expose?* → `discover_tools: exit`, **DEBUG**
- *which of them reached the tool registry?* → `register_server_tools: exit`, **DEBUG**

— were both invisible. That is the D08.1 failure at package scale: an acceptance check whose
only evidence line is DEBUG cannot be closed by any volume of traffic.

## What changed

Those two exit lines are now INFO. Entry lines stay DEBUG, and a test pins that too — 117
lines at INFO would be a different failure from 2, not a fix for it.

The two counts are the point. `discover_tools` reports what the server offered;
`register_server_tools` reports what was accepted. **Them differing is the interesting case**
— an allowlist rejection, or a name collision — and neither number was readable.

## Compliance note, measured but not acted on

`PROCESS.md` requires the architect stage to name the ladder rung. **24 of 47 design documents
mention a rung or the ladder.** That is a process-compliance gap about the ladder as a whole,
not about MCP, and it is recorded here rather than fixed because retrofitting a rung
declaration onto 23 closed documents would be filling in a form, not making a decision.

## Configuration

`settings.mcp_client` (`McpClientSettings`). No server is configured; the client is
constructed at boot only when one is.

## Observability

| line | level | what it answers |
|---|---|---|
| `mcp.client.discover_tools: exit` | **INFO** | server, `count` — what it offered |
| `mcp.client.register_server_tools: exit` | **INFO** | server, `registered` — what was accepted |
| `mcp.client.call_tool: exit` | INFO | server, tool, `execution_ms` |
| `*: entry` | DEBUG | unchanged |

```bash
# Did my MCP server connect, and what did it contribute?
grep -E '"msg": "mcp\.client\.(discover_tools|register_server_tools): exit' \
  ~/.stackowl/logs/stackowl*.jsonl | tail
```

## Failure modes

| Failure | What happens | What notices |
|---|---|---|
| A lifecycle exit slides back to DEBUG | Operator blind again | The guard (mutation-proven) |
| Every line raised to INFO | Noise, not observability | `test_the_entry_lines_stay_debug` |
| A message is renamed | — | The guard asserts presence before level |
| MCP server configured but silent | — | Now visible: the two counts |

## Verification

```bash
uv run pytest tests/mcp/test_a_configured_server_is_visible_at_info.py -q   # expect: 4 passed
uv run pytest tests/mcp -q                                                  # expect: 105 passed
grep -rhoE "log\.(info|debug)\(" src/stackowl/mcp/*.py | sort | uniq -c
#    expect: 4 info (was 2), 80 debug
```

All three RUN on 2026-09-04, not trusted. Mutation-proven: sliding `discover_tools: exit`
back to DEBUG fails the guard by name.

**OPEN — no MCP server has ever connected.** The lines fire on the first one configured. The
closing query is the jq above; it will stay empty until then, and that is honest rather than
a gap.
