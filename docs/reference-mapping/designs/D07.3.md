# What Survives a Restart

> **Status:** live
> **Map item:** D07.3 · Background delegation & durability
> **Source:** `src/stackowl/pipeline/durable/` (recovery, ledger, `delegation_link.py`),
> `src/stackowl/tools/agents/delegate_task.py`, `src/stackowl/owls/a2a_delegation.py`
> **Config:** none — durability follows from whether the parent turn is a durable task
> **Last verified:** 2026-09-04, against commit `416f3934`

## Why this exists

The reference platform states its boundary plainly: background delegation is
process-local, and work that must survive a restart belongs in a cron job instead.
Ours is stronger — durable tasks with recovery — and the boundary was **never written
down**, so "will this survive a restart?" could only be answered by reading code.

## Model

**One rule.** A delegation is durable **if and only if its parent turn is a durable
task**. `delegate_task` checks three things — an active `task_id`, a react context, and
a db pool — and falls open to an in-process await when any is missing.

A durable child is not merely restarted, it is *re-attached*: `derive_child_task_id`
makes the child id a deterministic function of the parent's resume-stable ledger
idempotency key, so a re-sampled parent re-emitting the same delegation at the same
iteration computes the same child id and rejoins the existing row instead of forking.

## Lifecycle

| Path | Survives a core restart? | How |
|---|---|---|
| Durable tasks | **yes** | `recover_durable_tasks` claims orphaned rows at boot |
| Delegated child of a durable parent | **yes** | deterministic child id re-attaches; `ancestor_depth` rebuilds its true depth from the `parent_task_id` chain |
| Pending outbound messages | **yes** | `recover_pending_messages` redrives at boot |
| Scheduler jobs and owl schedules | **yes** | scheduler `recover` + `reconcile_owl_schedules` |
| Processes | **yes** | process registry/checkpoint reconcile |
| **Delegation from a non-durable turn** | **no** | an in-process `await`; the parent coroutine dies with the process |
| Named persistent sessions (`sessions_spawn`) | **the handle no, the conversation yes** | `SessionRegistry` holds `label → handle` in a process-local dict with a 1800s idle TTL, so the live handle dies with the process. Continuity is deliberately NOT on the handle: turns run under `session_key="session:{label}"` and are read back from the history store, so re-spawning a label recovers its conversation. **Measured 2026-09-04: zero rows are keyed `session:` in either store, so this path is designed-durable and never exercised** — 1 `sessions_spawn` and 0 `sessions_send` in 4,154 tool-bearing turns. |
| In-flight turn state, progress views, provisional model windows | **no** | process-local by construction |

## Invariants

1. **Durability is inherited, never declared.** No flag makes a delegation durable; it
   is durable because its parent is. One rule, no second switch to drift.
2. **A resumed interior node keeps its depth.** `ancestor_depth` walks
   `parent_task_id`, so a recovered child does not restart the fork-bomb counter at 0.
3. **Falling open is loud.** The non-durable branch logs at INFO (see Observability) —
   it was DEBUG until 2026-09-04, which made the losing case the invisible one.

## Configuration

None. Durability follows structurally from the parent. That is deliberate: a
`durable=true` argument would be a second source of truth for a property the parent
already determines.

## Observability

* `delegate_task: durable child scope resolved` (INFO) — with parent and child ids.
* `delegate_task: non-durable parent — this delegation is PROCESS-LOCAL and will not
  survive a restart` (INFO) — **raised from DEBUG on 2026-09-04.** The two outcomes
  were asymmetric: the safe one was visible and the lossy one was not, so the only
  outcome an operator needs warning about was the one they could not see.
* At boot: `recovery.recover: exit — launched background drives` and
  `message_recovery.recover: exit`, each carrying its count.

## Failure modes

| What fails | What happens |
|---|---|
| Parent is not a durable task | Delegation runs in-process; lost on restart; now logged at INFO |
| Core restarts mid-delegation | A durable child is re-claimed at boot; a process-local one is not, and the parent's turn is gone with it |
| Parent re-samples the same delegation | Same `delegate_key` → same child id → re-attach, not a fork |
| Parent chain malformed | `ancestor_depth` stops at a hard ceiling rather than walking a cycle |
