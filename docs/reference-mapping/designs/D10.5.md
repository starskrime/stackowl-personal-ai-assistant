> **Status:** design
> **Map item:** D10.5 (extends the turn-prompt seam documented in `D09.5.md`)
> **Source:** `src/stackowl/commands/skill_command.py` (873 lines), `src/stackowl/commands/base.py`,
> `src/stackowl/startup/orchestrator.py` (the seam at ~L2263-2320)
> **Config:** none — ships enabled, no operator switch
> **Last verified:** 2026-08-29, against commit `61b3f40f`

## Why this exists

**Not for the reason the map gives.** D10.5's gap line reads "Direct Law 1 violation, and it
also means the model cannot be pointed at a skill on demand." Both halves were measured false
on 2026-08-29 and the map has been corrected in place:

| claim | measured verdict |
|---|---|
| Law 1 violation | **FALSE.** `skills_len` varies in **0 of 403 lanes** over four days (only 4159 or 0) while **304 of those same lanes** vary `prompt_hash` — the instrument detects variation, skills never cause it. Independently: **0 `prompt_hash` changes across 54 multi-turn conversations.** Fixed by D01.1 slices 4b+5 and ESC-10. |
| Model cannot reach a skill | **FALSE.** `skill_view` is in the guaranteed tool base with a reachability probe, and ran **391 times in 7 days**. |
| Reference never puts skills in the system prompt | **FALSE.** It carries a name + 57-char-description index there. Only **bodies** stay out — exactly our posture. |

What survives is narrower and real: **`/skill` has twelve verbs that MANAGE skills and not one
that USES one.** `/skill show X` renders the body *to the operator's screen*; the model never
sees it. The operator's only working route today is to type "follow the X skill and do T" and
hope the model chooses to call `skill_view`.

It matters because of the corpus. The catalogue is capped at 4,000 chars
(`skills/instruction_injector.py:12`), so of **180 enabled skills, 16 are presented and 163 are
dropped on every turn** — 2,604 `catalog truncated by budget` WARNINGs in the retained logs.
Over seven days the model loaded **five distinct skills**, all from the visible head; 174 were
never loaded once. A human naming a skill needs no catalogue, which makes this the only route
that reaches the other 163.

**Stated plainly, because the panel split on it and averaging would hide the finding: this is
an ERGONOMICS item wearing a capability item's gap line.** It is worth twenty lines because it
costs twenty lines. It is not the capability work, and it must not be counted as such — the
corpus item (why 174 skills are unreachable and `skills_list` has never once been called) is
tracked separately in `ESC-58`.

## Model

| concept | meaning |
|---|---|
| **skill catalogue** | names + descriptions in the frozen system prompt. Unchanged by this item. |
| **skill body** | the SKILL.md procedure. Enters the **message stream**, never the system prompt. |
| **turn prompt** | `SlashCommand.build_turn_prompt(args) -> str \| None`. Returning a string makes the gateway re-run the message as though the operator had typed that text. |
| **activation note** | a short prefix stating the operator invoked this skill. Load-bearing — see Invariants I4. |

### Why a registered verb and not `/<skill-name>`

The obvious design — route an unknown `/word` to a skill — was proposed, and **rejected on
measurement**:

- `gateway/scanner.py:31` is `_SLASH_CMD_RE = re.compile(r"^\s*/(\w+)")`. **`\w+` stops at the
  first hyphen, and 108 of 180 skill names (60%) contain one.** `/channel-fallback` arrives as
  `target="channel"`. It would ship broken for 60% of its own corpus, and the error would name
  a command the operator never typed. Qualified names (`/builtin:brainstorming`) die the same way.
- "Unknown slash command" is a **detector**, not just an error.
  `tests/journeys/commands/test_reachability_guard.py:7-8` exists because an unregistered
  command "would silently become 'Unknown slash command' in production". A skill fallback turns
  a closed, loud failure into an open one meaning "no such command AND no such skill AND the
  store was reachable AND the name survived `\w+`".
- Registering one command per skill (the reference platform's design) is worse still:
  `test_reachability_guard.py:34` asserts the registry equals `SHIPPED_COMMANDS` **exactly**,
  the Telegram menu rejects >100 commands, and `/help` rung 1 would render 213 entries.

Making the name a **parameter** dissolves all three problems at once: hyphens and
`source:name` survive untouched, the registry stays the single source of truth for what
`/word` means, and unknown commands stay loud.

## Lifecycle

```
/skill use <name> [instruction]
        │
        ├─ scanner.scan → route="command", target="skill"   (a REGISTERED command; no new namespace)
        │
        ├─ _dispatch_turn: CommandRegistry.get("skill") → SkillCommand
        │      └─ build_turn_prompt("use <name> [instruction]")
        │             ├─ verb != "use"  → None ......... the other twelve verbs reply as before
        │             ├─ name unresolved → None ........ falls through to ordinary dispatch, which
        │             │                                   answers with the existing not-found text
        │             ├─ skill disabled/archived → None . same, with a reason (see I3)
        │             └─ resolved → activation note + body [+ instruction]
        │
        └─ text non-empty → msg rewritten, re-scanned, dispatched as an ORDINARY turn
               same pipeline · same routing · same consent · same tools · _prompt_depth+1
```

**Priority order, stated because two conditions can fire on one event:** an explicit verb match
wins over everything; a resolution failure NEVER silently becomes a normal turn — it returns
`None` so the operator gets the existing, loud command reply.

## Invariants

> **I1.** The system prompt is byte-identical before and after a `/skill use`. The body enters
> as turn input only. (Law 1 holds by construction — `assemble` is not on this path.)
> **I2.** A skill body is never staged as a durable **user fact**.
> **I3.** A disabled or archived skill never runs. `enabled` is enforcement, not annotation.
> **I4.** The rewritten text never begins with `/` or `@`, so the re-scan cannot re-route it.
> **I5.** `/skill use` with an unknown name leaves today's not-found behaviour unchanged.
> **I6.** The other twelve `/skill` verbs behave byte-for-byte as before.

## The three defects that must ship with it

Found by the stability lens; each would make the feature decoration or worse.

**1. The skill body would be filed as a durable USER FACT (I2).**
`pipeline/turn_persist.py:236` stages `"User: {state.input_text}\n\nAssistant: ..."`, and under
the rewrite `state.input_text` **is** the skill body (median 3,193 chars over 181 SKILL.md). The
2026-08-25 guard is `is_machine_lane(state.session_key)` — a **prefix check** on
`("goal-", "incident-")` (`sessions/models.py:220-233`) — and a Telegram lane is not one; a test
asserts that. So this reopens the 4,480-of-5,212 machine-prompt defect on a lane the guard
cannot see. **Fix:** a `PipelineState` flag (`input_is_synthetic`) honoured by `turn_persist`
**alongside** `is_machine_lane` — one predicate, one home, not a second prefix hack.
`_record_transcript` runs *before* the guard, so the transcript is kept either way; that is
correct and stays.

**2. `enabled` is decoration on this path (I3).**
`SkillIndexStore.get` is `WHERE owner_id = ? AND source = ? AND name = ?` (`store.py:412-419`)
— no `enabled`, no `lifecycle_state <> 'archived'`; `get_many_by_name:983` omits them too. So
`skill_view` **returns disabled skills** and merely appends `"(disabled)"` to a header
(`skill_view.py:233`). The catalogue path enforces both (`list_enabled`, `store.py:376`). Two
answers to "is this skill available", and the operator-facing one is permissive. A header is no
defence: a turn prompt has no reader who can refuse. **Fix:** one shared resolver that both
`skill_view` and this verb ask. *Stated honestly: 0-over-0 today (180 enabled, 0 disabled, 1
archived) — real in code, no live instance.*

**3. `/skill use X ??` would execute rather than preview.**
The turn-prompt seam runs **before** dispatch, so `registry.py:66-73`'s `??` dry-run is
bypassed. That is a hole in the honesty spine and is handled here, not discovered in validate.

## Observability

Production runs at INFO; a DEBUG line is not evidence.

| point | `msg` | level | fields |
|---|---|---|---|
| decision | `[commands] skill.use: resolved a skill — running it as this turn's input` | **info** | `name, source, enabled, lifecycle_state, body_chars, has_instruction` |
| decision | `[commands] skill.use: NOT resolved — replying as an ordinary command` | **info** | `name, store_present, reason` |
| effect | `[pipeline] assemble: exit` gains `synthetic_input_chars` | **info** | ties the body length to the turn that carried it |

The second line's `store_present` exists because `services.skill_store` is
`SkillIndexStore | None` (`services.py:126`) — a `None` store would make the feature silently
never fire, indistinguishable from a typo.

```bash
grep '"msg": "\[commands\] skill.use' ~/.stackowl/logs/stackowl.jsonl \
  | python3 -c 'import sys,json;[print(json.loads(l)["fields"]) for l in sys.stdin]'
```

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| Unknown skill name | `skill.use: NOT resolved` (INFO) | none needed — falls through | today's not-found reply, unchanged |
| Skill disabled/archived | same line, `reason=disabled` | none | an explicit refusal naming `enabled=0` |
| `skill_store` is `None` | `store_present=false` on the same line | none | the ordinary command reply |
| Body would misroute the re-scan | activation-note prefix (I4) | prefix is unconditional | nothing |
| Body staged as a user fact | `input_is_synthetic` + an INFO refusal | refused at `turn_persist` | nothing; transcript still kept |

## Verification

Live evidence, after `./start.sh`, core boot time post-dating the commit. **`skills_len` is
NOT the evidence** — it is already proven inert across 1,572 lines / 403 lanes and will not move.

1. **The body reached the model.** Invoke a skill whose body contains a nonce. One
   `assemble: exit` at INFO whose `synthetic_input_chars` equals the body length, and the nonce
   appears in the reply.
2. **Nothing was filed.** `SELECT count(*) FROM staged_facts WHERE content LIKE '%<nonce>%'`
   returns **0**, an INFO line records the refusal, **and** the transcript row for that
   `trace_id` exists — proving the fact was suppressed and not the record.
3. **Disable is enforcement.** `/skill disable <name>`, invoke it, see an INFO refusal naming
   `enabled=0`. If it runs, the item is not done.
4. **Denominator check.** Before claiming "0 misroutes", show the invocation set was non-empty
   and included **a hyphenated name and a `source:name`**. A 0-over-0 pass is not a pass.
5. **The unknown path is still loud.** `/definitelynotaskill` still returns
   `Unknown slash command` with its "Did you mean" lines, and `test_reachability_guard.py` green.
