# The Fence Reached Three of the Four Tools Its Own Evidence Names

**Item.** D17.2 · Prompt-injection pattern library — `PARTIAL`
**Last verified.** 2026-09-05, commit `c69b8462`

## Why this exists

The Ask: *"extend ours to tool results and context files with the same scoping idea?"* The
reference platform answers prompt injection with `threat_patterns.py` — a library of
`(regex, id, scope)` tuples organised by attack class.

**We do not copy that, and the map already says why:** ours is structural, "no keyword lists,
per your standing rule". A regex library is a keyword list wearing a different hat, and it is
monolingual by construction. What is portable is the **scoping idea** — knowing which content
enters where — not the patterns.

## What was already there, and what the map missed

The map names one module, `infra/prompt_safety.py` (a header neutraliser). There is a second:
**`infra/untrusted.py`**, the fence, built by D12.8 with `wrap(text, source=…)` and
`contains_untrusted(text)`. Its module docstring carries the measurement that justified it —
974 turns over seven days, 66 of which fetched external content and used a powerful tool in
the same turn:

```
web_fetch        + write_file  35      web_fetch        + shell  24
web_search       + write_file  31      browser_navigate + shell  23
browser_navigate + write_file  27      browser_extract  + shell  13
```

**Four tools are named in that table. Measured 2026-09-05, two of them fenced.**

| tool | fenced |
|---|---|
| `web_fetch` | ✓ |
| `browser_extract` | ✓ |
| `web_search` | **✗** |
| `browser_navigate` | **✗** |

`web_search` serialises the whole payload — third-party titles and descriptions — into
`output`. `browser_navigate` returns `await page.title()`, a string the visited site chooses,
and a `<title>` is a classic injection carrier.

**Same rule, one tool short — twice, in the module written to fix that exact shape, with its
own docstring naming the tools it had not reached.** That is the root cause: the fence was
applied tool-by-tool at the sites someone remembered, and nothing tied the set of fenced
tools to the set of tools the evidence named.

## What shipped

Both are fenced, and the set is now tied to the evidence: a tripwire asserts every tool named
in `untrusted.py`'s table fences with a source naming it, **and** that every tool in the guard
is still named in that docstring. Add a fifth tool to the measurement and it must be fenced;
remove one and the guard must shrink.

### The fence is per FIELD in web_search, and the first attempt was wrong

Wrapping the whole JSON payload made it unparseable and broke seven tests. The `_render`
docstring states the shape exists *"matching how other read tools return structured JSON,
keeping the canonical shape available to downstream consumers"* — stated intent. **No `src`
module parses it today, and routing around stated intent because nothing consumes it *yet* is
how a contract dies quietly.**

So the fence marks `title` and `description` — the attacker-authored prose — and leaves `url`
and `position` clean. ADR-7 freezes field names and order, not values, so both hold. `wrap()`
is idempotent, so a re-render cannot double-fence.

`browser_navigate` fences the `title` value alone, for the same reason.

## Invariants

- Every tool named in `untrusted.py`'s measurement table fences, with a source naming it.
- The guard's tool list and that docstring name the same tools — both directions.
- The fence acquires **no pattern library**: a test asserts `untrusted.py` contains no
  `re.compile`, no "ignore previous", no "jailbreak".
- `web_search` output remains valid JSON with ADR-7 field order.

## It is a marker, not a control

Inherited deliberately from D12.8: narrowing the toolset after a fetch would break the same 66
turns that are legitimate work. Which capabilities may survive contact with untrusted input
is the operator's call (**ESC-110**, already open). This ships the visibility that any later
policy needs, over four entry points instead of two.

## Verification

```bash
uv run pytest tests/infra/test_the_fence_reaches_every_tool_its_own_table_names.py -q
#    expect: 7 passed
uv run pytest tests/tools/search tests/infra -q      # expect: 228 passed
uv run pytest tests/tools tests/owls -k "browser or search" -q   # expect: 351 passed
```

All three RUN on 2026-09-05, not trusted. Mutation-proven both ways: removing either fence
fails the guard by tool name.
