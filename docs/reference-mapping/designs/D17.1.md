# Dangerous-Command Approval — the Fatigue the Ask Assumes Is Not There

**Item.** D17.1 · Dangerous-command approval — `PARTIAL`
**Last verified.** 2026-09-05, commit `1b4ca53f`

## Why this exists

The Ask: *"Add smart-approve? It is the difference between 'approve everything' fatigue and
usable autonomy."* The reference platform has an auxiliary LLM that auto-approves low-risk
commands, plus a permanent allowlist persisted to config. Ours has trust tiers, session
batches, time-window grants, always-ask exclusions, audit, and fails closed.

**Nothing was built.** Both gaps are security-posture decisions (**ESC-134**), and one of them
would contradict a recorded decision. What this item did was measure the premise.

## The premise, measured

Across all nine daily logs, `[consent] policy.request: exit` is INFO — every decision is
visible. **121 decisions in nine days: 83 allow, 38 deny.**

That is not approval fatigue. It is roughly thirteen decisions a day, most of them granted.

**And 27 of the 38 denials were a single defect that has already been fixed.**

| deny | tool |
|---|---|
| **27** | `execute_code` |
| 4 | `send_file` |
| 3 | `send_message` |
| 2 | `skill_manage` |
| 1 each | `browser_browse`, `browser_eval_js` |

All 27 `execute_code` denials match, one for one, the 27
`[consent] autonomous grant REFUSED — this is always-ask` lines: same tool, `category: null`,
channel `rca`, spanning 2026-08-28 → 2026-09-02.

**They all predate the fix.** ESC-98 landed as `058e94ee` — *"code execution gated by NAME is
now gated by NOTHING"* — at 2026-09-01 23:51:57 local. The last refusal is 2026-09-02T02:05:16
**UTC**, which is 21:05 local, before it. `execute_code` is no longer in
`_DEFAULT_ALWAYS_ASK_TOOLS` (`{computer_use, ha_call_service, browser_dialog}`), and the
comment above that set states the compensating control: *visibility, not a gate.*

**Since the fix deployed: 319 consent assemblies, 10 decisions, all allow, zero denials.**

The honest phrasing is that the fix is **unrefuted but not yet exercised** — there has been no
`execute_code` consent request at all since, so the zero denials is not by itself proof the
new path works.

## What smart-approve would and would not buy

It targets prompts the operator is tired of answering. Measured, the operator is asked
rarely, and the recent denial rate is zero. **Smart-approve would add an auxiliary-LLM trust
surface for approximately zero measured friction.**

It would also contradict a recorded decision. `_DEFAULT_ALWAYS_ASK_TOOLS` is annotated
"Bakir's decision", and `_DEFAULT_ALWAYS_ASK_CATEGORIES` carries `prompt_surface` with a
written rationale (ESC-1) for why a *reversible* action is still always-ask. An LLM
auto-approving those is precisely the case those decisions exclude. Escalated, not reconciled.

## The other gap is real, and it is not about an LLM

**Grants do not survive a restart.** `_session_batch` and `_windows` are plain in-memory
dicts (`field(default_factory=dict, init=False)`). There is no persisted allowlist — the map's
second gap is accurate.

That matters more here than on most platforms, because CodeWatcher exec-replaces the core on
every code change: the current log window alone holds eight boots. Every one wipes whatever
the operator granted.

**But persisting a grant widens authority across a process boundary the operator never
approved.** A 15-minute trust window that survives three restarts is a different promise from
the one they answered. That is a posture decision, so it is in ESC-134 rather than built.

## What is NOT a defect, checked

`[consent] RoutingPrompter: no channel UX` fires 27 times and reads like a failure. It is the
fallback working: an unknown channel does **not** deny outright, it routes — the contract is
pinned by `tests/channels/test_unwired_channel_consent_fails_closed.py`. The separate
`FailClosedPrompter` is what denies when nothing is wired at all, and it did not fire.

## Verification

```bash
# 1. The decision counts, from the INFO line.
grep -h '"\[consent\] policy.request: exit' ~/.stackowl/logs/stackowl*.jsonl \
  | python3 -c 'import sys,json,collections; print(collections.Counter(
      json.loads(l)["fields"]["decision"] for l in sys.stdin))'
#    expect: allow 83, deny 38

# 2. Every execute_code refusal predates 058e94ee (2026-09-01 23:51 local).
git show -s --format=%ci 058e94ee
grep -h 'autonomous grant REFUSED' ~/.stackowl/logs/stackowl*.jsonl \
  | python3 -c 'import sys,json; print(max(json.loads(l)["ts"] for l in sys.stdin))'
#    expect: 2026-09-02T02:05:16Z == 21:05 local, before the 23:51 local commit
#
# SORT, do not tail. `tail -1` gave 2026-08-30 here: the shell glob does not order
# these files by the timestamps inside them, and an `ls | head` while exploring had
# already hidden the 09-02 daily entirely. Two truncated listings, one number.

# 3. execute_code is no longer always-ask.
grep -A 2 '_DEFAULT_ALWAYS_ASK_TOOLS = frozenset' src/stackowl/tools/consent.py
#    expect: computer_use, ha_call_service, browser_dialog — no execute_code
```

All three RUN on 2026-09-05, not trusted.
