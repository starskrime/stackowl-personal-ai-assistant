# The Generic Relay — and the Three Channels That Have Never Run

**Item.** D12.3 · Generic relay adapter — `MISSING`
**Last verified.** 2026-09-04, commit `300f7bfa`

## Why this exists

D12.3 is the dedup target: four hand-written channel adapters where the reference platform
has one relay that receives a `CapabilityDescriptor` at handshake. Its Ask — *"highest-ROI
refactor in the channel layer, do it before adding channel #5?"* — is scheduling, and stays
the operator's (**ESC-132**).

**DEBT-114 required this re-measurement before D12.3 could be scheduled.** It deferred the
collapse as "a wave rather than an item", noted the entry named a `memory_callbacks.py` that
no longer exists, and asked that the numbers be re-taken. That is what this item did.
Nothing was refactored.

So **5,175 lines — slack 2,208, whatsapp 1,525, discord 1,442 — have never run**. That is the single most relevant
input to "do the refactor before channel #5", and it cuts both ways — which is why it is a
decision and not a finding. A mechanical collapse would be rewriting three implementations
with no traffic to validate against, which is the worst possible input to a refactor. And
three unexercised adapters are also the cheapest thing in the tree to retire, if they are not
wanted.

Zero traffic is **not** evidence they are unwanted. Slack was built deliberately as a
first-class channel at Telegram parity. Unconfigured and unwanted look identical from here.

## Two sub-findings

**Only telegram has a `notifications.py`.** `TelegramNotificationDispatcher` routes proactive
heartbeat events — morning briefs, parliament syntheses, evolution badges, memory nudges —
and is constructed from `pipeline/steps/deliver.py`. It sits beside the channel-agnostic
`NotificationRouter` + `ProactiveDeliverer`, which D15.6 measured as heavily exercised (6,909
routing decisions, 5,553 delivery attempts). Two paths to one job.

**The other three channels' brief formatters are reached by nothing.**
`format_morning_brief` and `format_parliament_synthesis` are defined in slack, whatsapp and
discord `helpers.py`. The only caller of a per-channel formatter is
`telegram/notifications.py:118`, which calls telegram's own. The agnostic deliverer formats
through the shared `channels/_format` instead. Their only callers are tests.

## What was not done, and why

Nothing was deleted. Three registered, user-facing channels are the operator's to keep or
retire, and "retired means deleted" applies to what has been retired — not to what nobody has
decided about yet.

Nothing was refactored. The collapse remains a wave, exactly as DEBT-114 concluded, and this
measurement strengthens that: the duplication is near-miss rather than literal, so a
mechanical collapse would change behaviour on paths with no traffic to catch it.

## A detector that did not work, recorded so it is not rebuilt

Finding "which channel's copy is dead" was attempted twice and cannot be done this way.

1. `grep -rl <name> src/` counts **another channel's definition of the same name** as a
   reference, so every function looked live. All four channels reported zero dead functions,
   which contradicted a result measured by hand.
2. An AST call-site scan has the same flaw one level down — it counts by name, so a method
   called on telegram reads as called for all four — and it also cannot see properties
   (attribute loads, not calls) or framework callbacks registered by reference. It reported
   34 candidates, most of them `available`, `channel_name`, `handle_callback`.

Distinguishing them needs receiver-type resolution. The one finding above was established by
reading the call sites, not by a screen. **Four static screens have already been built and
deleted in this repo for failing a similar distinction**; this is the fifth, and it is not
being shipped.

```bash
find src/stackowl/channels -name '*.py' | xargs wc -l | tail -1

# 2. Three channels have never run.
sqlite3 ~/.stackowl/workspace/stackowl.db "SELECT channel, COUNT(*) FROM sessions GROUP BY 1;"
for c in slack discord whatsapp; do
  echo "$c: $(grep -h "\[$c\]" ~/.stackowl/logs/stackowl*.jsonl | wc -l)"
done
#    expect: telegram 107 / cli 13 / rca 3, and 0 log lines for all three

# 3. Only telegram has a proactive dispatcher.
ls src/stackowl/channels/*/notifications.py
#    expect: only telegram
```

All three RUN on 2026-09-04, not trusted.
