# A Tier Ladder Whose Rungs Are All The Same Model — And The Bug That Costs

**Item.** D04.4 · Auxiliary-model router — wave 10, order 96.
**Ask.** "This looks like a high-value, low-risk early adopt. Agree?"
**Answer.** No, on both halves — and the framing is worth rejecting explicitly,
because the map wrote its conclusion into the question. The router is declined; the
concrete cost of *not* having one turned out to be correctness, not cents, and that
part is fixed.

## The gap line is half right: the seam exists, there is nothing to route TO

`interaction/classifier_base.py` already provides one resolution chain —
`resolve_fixed_tier`, `resolve_cascade_tier` (circuit-aware, walks
fast→standard→powerful→local, never raises) and `safe_complete`. **Thirteen modules
use it.**

What does not exist is anything cheaper to reach. Measured on the live configuration:
four providers, three `enabled: false` — all pointing at one unreachable host and all
naming **the same model**, differing only in name and tier label. The one enabled
provider declares fast *and* standard *and* powerful, so **every rung resolves to
`NeraAiRaw/neraai-v1-raw`**. Cost records agree: since 2026-08-30, background side
tasks and conversational turns both used that one model for **100%** of calls.

**The root cause is not a missing router. It is that tier routing is a no-op and
nothing said so.** Every caller asking for something cheap was handed the flagship,
silently, and the only way to discover it was to read a week of cost records. That
was shipped as `describe_tier_ladder()`, `tier_ladder_is_degenerate()` and an INFO
line at boot — verified still firing on every boot today, carrying
`{'fast': …, 'standard': …, 'powerful': 'NeraAiRaw/neraai-v1-raw'}, degenerate: True`.

**ESC-111 answered this on 2026-09-03: leave it.** The lane a cheap model would serve
is a small share of tokens; conversation is the rest, and is the work least wanted on
weaker weights.

## The Ask's framing fails both halves

**"High-value"** — the ceiling is arithmetically zero. A router's only product is
choosing between models. Applied to side tasks (**5%** of current spend) where 100%
of choices resolve to the same string, the maximum recoverable benefit is zero
tokens, zero latency, zero quality — and zero *by construction* until a second model
exists.

**"Low-risk"** — inverted. The risk is not in building it but in the first day it
does something: a per-task router changes behaviour across thirteen modules at once,
with no per-task acceptance evidence for any of them.

**And the reference's own default is not to route.** Its `auxiliary_client.py` is
**8,255 lines**, but the config it ships pins exactly **two** tasks — both
`provider: "auto"`, `model: ""`, unpinned — while ~14 distinct task labels appear at
its call sites. Its `auto` resolution is an *availability* fallback, the same kind as
our `get_with_cascade`, not cost or capability routing. Most of those lines are
multi-vendor auth and error-shape normalisation a single-gateway deployment never
executes.

## What bypassing the seam actually costs: correctness

`safe_complete` sets `disable_thinking=True`. **The provider defaults it to `False`**
(`openai_provider.py:1461`). So every call that bypasses the seam runs with reasoning
on — and `classifier_base`'s own docstring records what that does: a reasoning model
spends its **entire output budget on invisible `<think>` tokens** before emitting the
answer.

That docstring also records the reason this matters more than a single patch:

> "This exact bug was independently rediscovered and patched in `owls/router.py`,
> `feedback_classifier.py`, `owls/evolution.py`, `delivery_gate.py`'s apology
> generator, and `schedule_commit_classifier.py` — **five incidents, one root cause,
> never fixed once at a shared layer until now.**"

The shared layer was built. Seven call sites still bypassed it, and **every one
coerces an empty reply into a benign default**, so the failure is invisible:

| site | what an empty reply becomes |
|---|---|
| `owls/shadow_validator.py` | `quality=None` → "fail closed" → **a good DNA proposal silently rejected** |
| `pipeline/planner/proposer.py` | `frozenset()` → "selected: 0" at INFO, reading as a quiet turn |
| `objectives/decomposer.py` ×2 | a capped budget *and* reasoning on — degrades to a single-step fallback |
| `memory/rollover_summary_handler.py` | an empty summary, indistinguishable from nothing to say |
| `pipeline/budget/salvage.py` | degrades to the floor |
| `tools/meta/owl_build_infer.py` | fail-opens to `None` → the operator is asked instead |

Nothing errors. Every one reads as the system deciding something.

**A documented mitigation makes this survivable, not correct**: the provider retries
once when it sees a reasoning-starved reply, so the usual cost is a doubled call —
except where empty is coerced to a benign default, which is exactly the list above.

**So the fix is the guard, not the patches.** Patching seven more sites would be the
sixth rediscovery. `tests/providers/test_a_side_task_never_pays_for_invisible_thinking.py`
now fails any awaited completion that neither disables thinking nor justifies keeping
it, with an allowlist where reasoning genuinely *is* the product — deliberation,
vision and document calls routed by capability rather than tier, the main-work browse
loop, and the gateway itself, which forwards `**kwargs` and must not override its
callers.

## Corrections made along the way

* The first sweep counted `.complete(` textually and reported 14 bypassing modules.
  **`parliament/orchestrator.py` was a false positive** — a frozen-dataclass state
  transition, not an LLM call — and six real ones were missing. The detector now
  requires an *awaited* call with a messages argument.
* **The detector's limit is stated rather than papered over**: it only sees a
  directly-awaited call, so `moa_runner.py`, which passes the coroutine into a
  `wait_for`, is invisible to it. That call legitimately wants reasoning anyway; if it
  is ever rewritten to a plain `await`, the guard flags it and the reason gets written
  down at the moment it becomes relevant.
* `shadow_validator.py`'s comment says its tier "mirrors CriticScorerHandler's
  default". The tiers do agree — but **the comment tracks the wrong field**: the real
  divergences were `disable_thinking` (fixed here) and an unguarded
  `get_with_cascade` where the critic uses the safe wrapper.
