## Why this exists

D04.1 was mapped as **"Providers as plugins"** — make a backend a data record so provider
breadth stops being a core edit. It earned P0 after three live faults in one day, all
provider-shaped, all following a single model upgrade from qwen 3.6 27b to qwen 3.8 27b.

Measurement rejected that framing, and the rejection is the most useful thing this item
produced. None of the three faults is a *declaration* problem:

| Fault | Why a declarative profile does not fix it |
|---|---|
| Leaked tool-call dialect | `_react.py:135-141` — the fourth shape appeared **after a model upgrade inside one backend row**. The dialect belongs to the model's training, not the backend, so a per-backend declaration goes stale at the next `pull`, and goes stale *silently*. |
| Output cap / context overflow | Arithmetic. Fixed in `8c60a3d4` by reserving the margin instead of spending it. The remaining half is a classification question best answered by *using the retry as its own oracle*, not by declaring which status code means "too big". |
| Cache statistics | The disambiguating probe's only writer is on the Anthropic path, which this deployment never runs. Fixed by **measurement** — the opposite of declaration. |

Bakir re-scoped the item on 2026-08-21 (ESC-21): **close the divergences in place, drop
the plugin surface.** What was actually wrong was not that backends could not be
declared. It was that the platform had two implementations of one loop that had drifted,
and nothing that could tell you where.

The counter-argument is recorded rather than deleted: D04.1's stated purpose was
user-facing provider *breadth*, which Bakir has confirmed is a goal. This re-scope ships
correctness and lowers the cost of the next backend, but ships no breadth. If breadth
becomes urgent, the plugin surface is what delivers it, and this decision defers it.

## Model

Three layers, and the item is about which facts live in which.

| Layer | Where | What it owns |
|---|---|---|
| **Ladder** | `llm_gateway.py` | Tier span, escalation, same-tier retry, cascade on fault. Knows nothing about wire format. |
| **Loop** | `complete_with_tools` in each provider (openai from line 560, anthropic from 492) | The ReAct spine: LoopGuard, parse/dispatch, persistence judge, budget, floor. **Written twice.** |
| **Shared spine** | `_react.py` (433 lines) | `LoopGuard`, `parse_react_action`, `looks_like_tool_call`, `synthesize_from_calls`. Already common to both. |

`ModelProvider` (`base.py`) has 24 members. 14 are platform behaviour, and 13 of those 14
are overridden by no subclass — the ABC is fat, which is the observation the plugin
framing was built on. It remains true; it is simply not what was hurting.

## Lifecycle

```
LLMGateway.complete_with_tools(floor..ceiling)
  │
  ├─ for each tier:
  │    resolve_tier_with_fallback(tier) ──▶ (provider, model)
  │    can_escalate = (not last rung) AND (some higher tier resolves ELSEWHERE)   ◀── ESC-22
  │        └─ False ⇒ INFO "running as if at the ceiling", provider floors instead
  │                    of emitting a sentinel that cannot route
  │    provider.complete_with_tools(..., can_escalate)
  │      │
  │      ├─ round ──▶ native tool_use?  ──▶ dispatch ──▶ callback ──▶ next round
  │      ├─ round ──▶ text: parse_react_action FIRST                   ◀── D5-count
  │      │             ├─ action  ⇒ dispatch ──▶ OBSERVATION ──▶ callback
  │      │             └─ none    ⇒ callback (W4.T17) ──▶ give-up judge
  │      ├─ judge rules give-up + can_escalate ⇒ ESCALATE              ◀── D2
  │      └─ budget exhausted     + can_escalate ⇒ ESCALATE             ◀── D1
  │
  └─ sentinel ⇒ discard the attempt, step up (only ever to a DIFFERENT target)
```

**Priority order at the text boundary** — parse before callback. The callback is the
final-answer boundary handler, so it must not fire until the text is known *not* to be a
tool call.

**Priority order for the give-up verdict** — escalate if a genuinely stronger target
exists; otherwise nudge, capped at 3 rounds; otherwise floor. Never empty.

## Invariants

> **I1.** For one scripted transcript, both loops return the same text, record the same

> *(`test_both_tool_loops_conform.py`, all `TestTheyAgree*`.)*

> *(`test_escalation_that_changes_nothing_is_visible.py`.)*

> `test_the_users_answer_is_the_attempts_own_text`.)*

> always-vetoing judge gets exactly 3 rounds on both loops, at any `max_iterations`.
> *(`TestTheyAgreeOnTheJudgeNudgeCap`, parametrised 4/8/16.)*

> **I5.** One backend fact is read one way. `max_output_tokens` resolves through
> `resolve_model_override` in `stream()`, `complete()` **and** `complete_with_tools()`.
> *(`test_anthropic_tool_loop_reads_the_model_override.py`.)*

## Configuration

No key changed shape in this item — deliberately. Two shapes were found that a refactor
must not decide by accident, and both are recorded as ESC-24:

| Key | Type / default | Note |
|---|---|---|
| `max_output_tokens` | int, `250000` | Provider-level. Exceeds real Anthropic ceilings (8192–64000). |
| `models[].max_output_tokens` | int, unset | Per-model. **Cannot** be set for the model named in `default_model` — `_validate_models` rejects the collision, so capping the default model requires the provider-level key. |
| `context_chars` | int, unset | In **characters**, while the runtime reasons in tokens. A rename to `context_tokens` would silently change an operator's value ~4x. Left alone. |
| `supports_vision` | bool, **enabled by default** | Also answers `supports_document`; one resolver, never two. |
| `models:` / `tier` vs `tiers` | — | Mean different things in the 49 catalog YAMLs and in `ProviderConfig`. Unifying them collides in a way YAML will not catch. Left alone. |

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| Ladder resolves to one target | `_can_escalate_meaningfully` | Provider floors on the first attempt instead of discarding it | An answer, one turn sooner |
| Judge rules give-up, stronger tier exists | `persistence_check` | Escalate (both loops) | Answer from the stronger tier |
| Judge rules give-up, at ceiling | same | Nudge, ≤3 rounds, then deliver | The model's own text |
| Tool budget exhausted below ceiling | iteration budget | Escalate (both loops) | Answer from the stronger tier |
| A user YAML shadows a bundled provider | name collision at load | Refused, bundled kept, INFO | Their file is ignored for that name |
| Cooperative stop mid-ReAct | `on_iteration_complete` raises | Propagates — **after** the tool ran | One extra tool executes. **Chosen, ESC-25.** |

## The answer arrived and the document did not hear it

**ESC-25 was answered by Bakir on 2026-08-21** — *dispatch first, on both loops,
deliberately*, his call against my recommendation. I argued a tool that runs after the
user says stop cannot be un-run; his counter-case is the one the code already encodes:
`ReActIterationState` carries `tool_call_records`, so the callback REPORTS a completed
iteration, and firing it before dispatch would have it report an iteration that has not
happened. The consequence is user-visible and is not what "stop" implies — a cooperative
stop, or a budget kill, lets the tool already requested finish — and it is now uniform
across both loops rather than accidental.

It landed in the code and in
`test_dispatch_precedes_the_callback_on_both_BY_DECISION`. **It did not land here**, and
this document went on calling it OPEN in three places for seventeen days. Worse,
`test_both_tool_loops_conform.py` contradicted ITSELF: line 180 said *"the order question
is still open"* thirty lines above the docstring recording the answer. **ESC-26** — "where
does ESC-14 land" — was answered in the same commit (*un-fold it; ESC-14 gets its own
item and is fixed at the fusion site*) and shipped in `735495a3`, and this document called
that open too.

**Why it could not be caught.** An OPEN escalation carries a `premise_check` and
`escalation_check.py` re-runs it every loop. An ANSWERED one is **deleted from the
queue** — so nothing re-reads the sites that cited it, and each of them keeps asking the
operator for a decision he already made. That gap was already diagnosed, in the docstring
of `tests/audit/test_a_settled_decision_is_not_contradicted_by_the_record`: *"an ANSWERED
escalation has no `decision_check` the way an open one has a `premise_check` — recorded in
the item, not built here."* Seventeen days is what recording it cost.

`escalation_check.py` now reports **ANSWERED BUT STILL CALLED OPEN**: a site describing,
in the present tense, an escalation id that is no longer in the queue. 63 dangling ids are
cited across the tree and most are correct — an answer recorded where it changed something
is exactly right — so the detector reads the sentence, not just the id. Ten sites over
eight escalations remain; this item drains D04.1's four.
