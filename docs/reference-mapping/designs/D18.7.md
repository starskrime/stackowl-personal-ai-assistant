# Eight Architectural Checks Existed. None Of Them Ran.

**Item.** D18.7 · Installer & platform reach — `PARTIAL`, wave 9, order 90.
**Ask.** "Distribution is adoption. How far do you want to go?"
**Answer.** That half is the operator's (ESC-139). Measuring it found something else:
the entire boundary-check suite runs nowhere, five of its eight checks exit 1, and
four of them enforce standing operator rules.

## The installer question is genuinely his, and the evidence is one-sided

Measured: **one human** in ~4,037 commits (two emails, same person). **No README** at
the repo root. **One tag**, `v0.1.1`, from the pre-rewrite TypeScript era. No published
package, no pushed image. A project whose Ask is "distribution is adoption" has no
adoption funnel to feed, and an installer built for users who do not exist is
decoration. So the reach question is escalated, not answered.

**Its cost is not small, either.** The reference's installer is `install.sh` (3,127
lines) + `install.ps1` (3,830) + a Tauri/Rust GUI bootstrapper, and most of that bulk
manages Node 22, an npm prefix and a stage-protocol JSON contract — problems a
`uv`-based project does not have. Their Python half just curls the `uv` installer,
which is the one part we would copy, and we already have it.

## What measuring found instead

`scripts/boundaries/` holds the B1–B9 architectural checks. Measured 2026-09-05:

| check | subject | result |
|---|---|---|
| b1 | circular imports | **50 cycles**, exit 1 |
| b2 | files over 300 lines | **196 files**, exit 1 |
| b3 | ASCII-only regex / stopword lists | **4 sites**, exit 1 |
| b4 | cross-platform | exit 1 → **fixed and WIRED here** |
| b5 | silent/bare `except` | **145 sites**, exit 1 |
| b6 | `mypy --strict` | exit 1 |
| b8 | network imports in embeddings | exit 0 → **wired here** |
| b9 | blocking I/O in handlers | exit 0 → **wired here** |

**Not one of the eight was in `scripts/tripwires.sh`,** and their only CI home was a
`.pre-commit-config.yaml` hook still running `cd v2 && …` — the v2→root migration
deleted `v2/` on 2026-06-17. So five checks exited 1 for months and nothing read a
single verdict.

**Four of them enforce standing operator rules**: cross-platform code (b4), "every
`except` logs" (b5), "never hardcode English keyword lists" (b3), and the file-size
discipline (b2). A rule the operator stated, with a checker written to enforce it, and
no path from the checker to anything that runs.

## Root cause, and why b4 in particular was never wired

**The migration moved the tree and left every CI and packaging path pinned to the old
layout, with nothing gating those paths.** That is why the breakage was invisible: a
pre-commit hook that fails takes the whole run with it, including the boundary step in
`ci-v2.yml` behind it, and a workflow nobody triggers never reports anything.

**But b4's own silence has a second cause, and it is not neglect: it was
unwireable.** It reported 23 violations and nearly every one was correct code —

    config_path.py:40   os.path.expandvars(os.path.expanduser(v))   pathlib has NO
                        expandvars; this IS the portable form
    orchestrator:4409   signal.SIGHUP inside `if hasattr(signal, "SIGHUP")`
    kill_platform:132   signal.SIGKILL inside `_terminate_posix`
    skill_validation    r">\s*/tmp/[^\s]*\s*&&\s*(curl|wget|nc)"  — a security REGEX
                        that DETECTS /tmp staging
    audit.py:46         "/audit export --output /tmp/audit.json"  — help text
    docker_argv:115     "--tmpfs", "/tmp:rw,noexec…"  — inside a Linux container

A guard that fires on correct code teaches its reader to ignore it, and ignoring it is
exactly what happened. It was made sound first — carve-outs for docstrings, `hasattr`
feature tests, posix-named functions, and an allowlist of non-host-path literals with
a stated reason each — and only then wired. It now reports **0 across 842 files**, and
a positive control proves it still catches both real classes.

**Its `os.path` rule was deleted deliberately.** `os.path` is cross-platform — that was
a STYLE preference (prefer pathlib) smuggled into a PORTABILITY checker, and it
produced 14 of the 23 findings. `ruff`'s `PTH` ruleset does the job properly: it names
the exact replacement per function and, unlike b4, does not flag `os.path.expandvars`,
because there is nothing to replace it with. Measured: **23 PTH findings** across
`src/`. Enabling it is a separate decision — several sit inside `shell.py`'s
path-safety checks and the ruff baseline may not rise.

## Platform reach, measured

**Windows has exactly one hard blocker.** `runtime.split_process` defaults to `True`,
and the gateway↔core IPC uses `asyncio.start_unix_server` / `open_unix_connection`
(`ipc/server.py:66,82`, `ipc/client.py:44`, `channels/dev_ingress.py:143`) — CPython
exports those only under `hasattr(socket, "AF_UNIX")`, so on Windows it is a boot
crash, not an import error. Four call sites, no alternative transport.

**macOS degrades gracefully.** All `/proc` reads are guarded or inert, systemd is
probed, launchd is handled, and `process/kill_platform.py` is genuinely portable
(`tasklist`/`taskkill`). The real gap is that code execution is unavailable there and
**nothing says so at boot**.

**And the probes exist but are not plugged into presentation.**
`infra/capabilities.py` has exactly ONE registered name — `"browser"` — while
`SandboxCapability.probe()`, `ImageCapability.probe()` and `BrowserProbe.check()` all
exist. So on a host that cannot sandbox, the sandboxed tools are still presented to the
model. That is the built-but-not-wired shape one layer up, and it is ESC-139's second
half rather than this item's, because it changes what the model is offered.

## Deleted, because retired means deleted

* `.github/workflows/release.yml` — runs `npm ci`, `npm run build` and
  `scripts/build-release.sh`; there is no `package.json` and no such script. A
  TypeScript-era artifact. **I pinned commit SHAs onto it yesterday in D17.5 without
  noticing it could never run** — hardening a dead path is the cost of not measuring
  whether a thing executes.
* `deploy/migrate-to-root.sh` and `deploy/ci-post-migration.yml` — helpers for a
  migration completed 2026-06-17, last touched by the migration commit itself, and
  referencing only each other.
* `.pre-commit-config.yaml` — its two `v2/` paths repaired rather than deleted; the
  hooks are wanted, the paths were stale.

## A correction to a panel finding, and to my own instruments

A lens reported `deploy/install-service.ps1` as "shipping a checksum-bypass". **It is
the opposite: fail-CLOSED.** The placeholder can never equal a real SHA-256, so the
comparison always fails and the install refuses — the right direction. What was wrong
was the *message*: it reported a "checksum mismatch" and printed the placeholder as the
expected value, naming a cause that does not exist. It now refuses *before*
downloading and says no hash was ever pinned.

**And my own detectors overcounted repeatedly.** A first sweep reported "12 unguarded
POSIX files"; inspection showed the sandbox is probed as a subsystem, the `/proc` read
is `try/except`-guarded with a docstring saying so, and `cli/app.py`'s signal use
carries an explicit Windows-aware comment. **Portability guards in this codebase take
at least four shapes — a platform branch, a `hasattr` feature test, a `try/except`
fallback, and a documented limitation — so any single-shape detector overstates.** That
is the same lesson D18.6 recorded one item earlier, and it is why b4 needed carve-outs
rather than a bigger pattern list.
