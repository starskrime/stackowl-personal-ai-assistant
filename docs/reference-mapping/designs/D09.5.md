## Why this exists

A user must be able to say "learn this" and get a durable, reusable skill — pointed at a
directory, a URL, pasted notes, or "what we just did".

The map framed the gap as "ours is a tool (rung 6), theirs is a slash command (rung 2) —
move ours and save the schema cost". Measurement says the map compared the wrong pair, and
the record should say so plainly:

* `synthesize_skills` is **not** the counterpart to the reference's `/learn`. Its
  `parameters` are literally `{}`, so it cannot be aimed at anything, and its own
  description carries an ANTI-LANE telling the model to use `skill_manage` instead. The
  reference's learn prompt targets `skill_manage` too — which StackOwl already has, in the
  guaranteed base set, and which authored a skill at 16:29:08 on 2026-08-23.
* So the authoring **capability** is present and used (17 `agent_self:skill_manage` creates
  in `skill_audit`). What is absent is a **front door**: a named, discoverable way to invoke
  it that also carries the authoring standards.

That is what this item builds. It is deliberately NOT a new way to write skills; it is a
prompt that steers the existing writer.

## Model

Three pieces, in ascending order of how much they commit us to:

1. **`build_learn_prompt(user_request: str) -> str`** — a pure function. No I/O, no model
   call, no state. Returns the instruction text a normal turn will execute. This is the
   whole of the ported design; the reference's own file is 150 lines and does exactly this.
2. **`LearnCommand`** — a `SlashCommand` that returns the builder's text from
   `build_turn_prompt()` rather than from `handle()`.
3. **The seam that makes (2) possible**, which did not exist and is the real architectural
   content of this item — see below.

### The seam, and why it is the expensive half

The reference feeds the built prompt straight back into a normal turn:

```
gateway/run.py:11768      event.text = build_learn_prompt(_learn_req)
tui_gateway/server.py     return _ok(rid, {"type": "send", "message": build_learn_prompt(arg)})
```

Every surface replaces the user's message text and lets the ordinary turn do the work. No
new engine, no schema, no second LLM call.

**StackOwl's command contract cannot express that.** `SlashCommand.handle()` returns
`str | CommandResponse` (`commands/base.py:39`), and `CommandResponse` is `{text, actions}`
— display text plus buttons (`commands/response.py`). Dispatch happens at the gateway in
`_deliver_command_stub` (`startup/orchestrator.py:2132`), which streams the reply directly
to the user and **never enters the pipeline**. `Action` replays *commands*, not turns.

So `/learn` needed one new concept meaning **"this text is a PROMPT for the live turn, not a
reply to the user"**.

**AS BUILT** (commit `2379f351`), which differs from this doc's first draft and is recorded
that way rather than quietly rewritten. The draft proposed a `TurnPrompt` *response* honoured
by `_deliver_command_stub`. What shipped is smaller and sits earlier:

```python
class SlashCommand:
    def build_turn_prompt(self, args: str) -> str | None:
        return None          # default: an ordinary command, unchanged
```

`_dispatch_turn` consults it **at the top, before the stream is created**, and when a command
returns text it rewrites the message as though the user had typed it, re-scans, and
dispatches an ordinary turn.

Three reasons the shipped shape is better than the draft:

* **Earlier.** Intercepting at `_deliver_command_stub` would already have created a response
  stream that then had to be abandoned. At the top of `_dispatch_turn` there is nothing to
  unwind.
* **One home.** `_dispatch_turn` has six call sites; the rule lives in the function, not at
  each of them.
* **No new type.** A `TurnPrompt` response would have widened `CommandResponse`'s meaning for
  every renderer on every channel. A defaulted method touches nothing that does not opt in.

It re-scans rather than naming a target, because the scanner's own fallback is `secretary` and
hardcoding that here would be a second copy of a routing rule. A `_prompt_depth` guard bounds
the recursion: the rewritten text cannot begin with a slash today, but the guard does not rely
on that staying true.

This is the one durable commitment in the item, and it is worth making deliberately: it is
reusable by every future command that wants to *steer* the agent rather than answer for it.

### Footprint ladder

Rung 2 — a prompt plus one thin edge over the existing authoring path. It is emphatically
**not** rung 6: no new engine, no new tool schema, no new queue.

## Lifecycle

```
user types  /learn <request>
   -> scanner routes it as route="command"
   -> _dispatch_turn asks LearnCommand.build_turn_prompt(args)  (pure)
   -> the message is rewritten with that text, re-scanned, and dispatched
      as an ORDINARY turn — the command is never dispatched as a command
   -> the ordinary turn runs: the agent gathers sources with the tools it
      already has (read_file / search_files / web_fetch / conversation history)
   -> the agent calls skill_manage(action="create")
   -> gated_skill_write: authoring standard -> security scan -> consent -> write
   -> the agent reports the skill name and a one-line summary
```

Nothing in that chain is new except the rewrite — everything after it is the
ordinary turn path.

## Invariants

* **I1 — no second engine.** `/learn` performs no gathering, no model call, and no write of
  its own. It returns a prompt; the turn does the work, and `skill_manage` remains the sole
  writer it reaches. (Bakir's standing rule, 2026-08-17.)
* **I2 — the builder is pure.** `build_learn_prompt` must be callable in a test with no
  services, no DB and no network, and must be deterministic for a given input.
* **I3 — an empty request still works.** `/learn` with no argument means "what we just
  did"; it must never error or stall.
* **I4 — every part of the request is load-bearing.** Prose following a path or URL is a
  requirement, not decoration. `<url> focus on the auth flow, skip deprecated` means gather
  the URL AND honour the focus. This is the reference's sharpest observation and it ports
  verbatim.
* **I5 — the authoring standards travel with the prompt.** The single genuinely portable
  asset in the reference's file is its standards text, including the operational nag to
  **count** the description characters rather than state the limit declaratively. Two of the
  synthesizer's five nightly refusals on 2026-08-23 were descriptions at 61 and 62
  characters against a 60-char limit — a live demonstration that stating the rule is not
  enough.
* **I6 — the standards have ONE home.** They must be reachable by every writer, not just by
  `/learn`, or this creates the second copy of a rule that failure mode 3 warns about.
  `skills/standard.py::describe_for_prompt()` already exists and is where they belong.
* **I7 — no new tool schema.** The tool count is a scarce resource (ESC-35/36); `/learn`
  must not add to it.

## Configuration

None. Everything ships enabled — `/learn` is registered like any other command, with no
flag and no opt-in.

  empty-request path from a pointed one.
* The resulting skill create is already logged by `skill_manage` and audited in
  `skill_audit` with `actor='agent_self:skill_manage'`, so provenance needs nothing new.

The closing query for validate is therefore: a `/learn` invocation followed, in the same
trace, by a `skill_audit` create row.

## Failure modes

| Failure | What it looks like | Guard |
|---|---|---|
| `/learn` does its own gathering inside `handle()` | a second authoring engine beside the synthesizer, with a second copy of the standards | I1; the command returns a prompt and nothing else |
| The seam is built as "invalidate the prompt cache so the new skill shows up" | one user typing `/learn` cold-rebuilds every conversation's prompt — `_invalidate_prompts` is machine-wide (`skills/store.py:411`) | never call it from this path; the skill appears on the next assembly |
| The authored skill is never seen again | until ESC-44 landed, a new skill had ~7% odds of appearing in a prompt | ESC-44 (value-ordered catalogue) is a **prerequisite**, not a nicety |
| Duplicate skills | `skill_manage._create` checks only `if target_dir.exists()` — a path test that a word-order permutation defeats | out of scope here; tracked separately. `/learn` makes this *more* likely by making authoring easier |
| The description exceeds 60 chars and the write is refused | the synthesizer's own live failure mode | I5 — tell the model to count |

## Verification

Run these; do not trust them.

1. **The builder is pure and deterministic**
   `build_learn_prompt("x") == build_learn_prompt("x")`, with no services constructed.
2. **The empty request is handled**
   `build_learn_prompt("")` contains the "what we just did" fallback and does not raise.
3. **The seam carries the prompt to the turn, not to the user**
   Dispatch `/learn foo` and assert the pipeline received the built text as turn input, and
   that the raw prompt was NOT streamed to the user as a reply.
4. **No new tool schema**
   `ToolRegistry.with_defaults()` tool count is unchanged by this item.
5. **Live** — a real `/learn` on Telegram produces a `skill_audit` create row in the same
   trace, and the created skill appears in a later assembled prompt (which is what ESC-44
   makes possible).

## Rules

* The command returns a prompt. It does not gather, call a model, or write.
* The standards text lives in `standard.py` and is referenced, never copied.
* No new tool, no new queue, no new status column.
* Ship enabled.

## Anti-patterns

**Do not sell `/learn` as new capability.** It is a front door onto authoring that already
works — 17 creates in `skill_audit`, one of them the same day this was written. Framing it
as new invites a second implementation of something that exists.

**Do not ship it before ESC-44 is live.** My recorded objection on ESC-43 was that a
user-authored skill had roughly a 7% chance of ever being visible, because the catalogue was
cut alphabetically at ~12 of 160. Shipping a pleasant front door onto a broken retrieval path
manufactures a promise the platform cannot keep. Bakir's answers dissolve the objection by
fixing both — but only in that order.

**Do not let the seam become a general "commands can do anything" hook.** It has exactly one
meaning: *this text is the turn's input*. Anything broader is a second dispatch path.
