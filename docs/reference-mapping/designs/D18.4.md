# The Answer To The Ask Is No — And Asking It Found Two Defects, One Hiding The Other

**Item.** D18.4 · State-path discipline — `PARITY`, wave 9, order 87.
**Ask.** "Add a display-form helper?"
**Answer.** No, on measured grounds. But the question exposed a live loader defect,
and fixing that unmasked a second one it had been concealing.

## Why the display helper is declined

The reference renders user-facing paths as `~/.stackowl/...` instead of
`/home/boss/.stackowl/...`. Four measurements say copying it would be decoration
at best:

1. **It fixes none of the observed leaks.** The live database holds 20 messages
   containing `/home/boss/`, 14 from the assistant, and every extracted path is
   StackOwl state. But all 14 are **model-authored prose** — runnable instructions
   like ``cd /home/boss/.stackowl/workspace && ./gmail_env/bin/python …``. The model
   emits them because it *sees* absolute paths in tool results, not because a helper
   was missing. A helper wired at the five formatting sites fixes **0 of 14**.
2. **One of those five sites would be made worse.** `tools/system/shell.py:784` is
   inside `ShellTool.description` — the tool schema the *model* reads before writing
   every command. `ShellTool` dispatches through `create_subprocess_exec` as well as
   `_shell`, and `workdir` is passed straight to `cwd=` with no expansion. A `~`
   there is a latent breakage, not a cosmetic.
3. **The reference's own history argues against it.** Their helper caused an
   outage (a stale-module `ImportError`, silently caught, so the gateway was never
   restarted), and the fix reverted their *tool description* to a static string —
   the same model-facing site flagged above. They also carry two re-implementations
   of the helper, so copying it copies a duplicate.
4. **Their motivation does not transfer.** Their display bug was that a hardcoded
   home made the model look in the wrong directory — *because profiles give each
   instance a different home*. D18.3 recorded multi-instance as explicitly
   unsupported (ESC-136) and deliberately committed to no profile name, layout,
   column or flag. **A display helper is profile machinery bought before the profile
   decision it serves.**

## What measuring the question actually found

### Defect 1 — the loader threw away everything you passed it

`settings_customise_sources` accepted `init_settings` as a parameter and never
returned it:

    return (env_settings, _YamlSource(settings_cls, config_path))

pydantic-settings consults only the sources a model **returns**, so every keyword
argument to `Settings(...)` was silently discarded. Measured:

| call | result |
|---|---|
| `BrowserSettings(screenshots_dir="/srv/shots")` | `/srv/shots` — correct |
| `Settings(browser={"screenshots_dir": "/srv/shots"})` | `~/.stackowl/screenshots` — **discarded** |
| `Settings(webhook={"port": 9999})` | `8766` — **discarded** |
| `Settings(**{"no_such_key": 1, "webhook": {"port": "not-a-number"}})` | **accepted** |

The sub-models were never wrong; the composition was, and it failed in the
direction that says nothing. What it reached, measured rather than reasoned:
`tests/test_webhook_receiver_supervisor_contract.py` asserted the supervisor
contract for an **enabled** receiver against a disabled one; `tests/test_story_6_4b.py`
set a 10 MB ceiling that never arrived; and **D18.2's own acceptance check** —
`Settings(**data)`, written to prove the generated example is real configuration —
validated nothing at all, since the same call accepted an unknown key and a
non-numeric port. *A test that passes immediately may be vacuous. That one did.*

### Defect 2 — which the first one was hiding

`docs/stackowl.yaml.example` emits `screenshots_dir: ~/.stackowl/screenshots` on
purpose, so the published artifact carries no machine path and no operator username
(D18.2). A panel lens flagged the tilde as a breakage. **I measured it and reported
the lens wrong**: loading the example returned an absolute path.

It returned an absolute path *because the YAML value was being discarded* and the
default came back. With `init_settings` restored, the same measurement gives
`PosixPath('~/.stackowl/screenshots')` — relative, exactly as the lens predicted.
**One defect was the other's alibi**, and the instrument that "cleared" the tilde
was really measuring the bug that swallowed it.

`Path("~/x")` is a relative directory literally named `~`, created beside the
working directory, with no error. So `~` is now a **supported** form rather than a
trap: `ConfigPath` (a `BeforeValidator` that expands `~` and `$VARS`) is applied to
all five `Path`-typed settings fields, covering config file, environment and
constructor alike, because all three pass through validation.

### Defect 3 — a mistyped section name vanished in silence

`Settings` uses `extra="ignore"` at the root while every sub-model uses
`extra="forbid"`. So a typo *inside* a section raises, and a typo in a **section
name** — `webhok:` — silently discarded that entire section's configuration. The
root is exactly where section names live, so it is the one place a typo cost the
most and said the least.

It now **warns and still boots**. Flipping the root to `forbid` would make a config
that used to work suddenly fail, and locking the operator out of his platform to
catch a typo is a bad trade. (Measured: the live config has 0 unknown top-level
keys, so nothing is warned about today — the line exists for the next typo.)

## And the half worth keeping from the reference

The accessor rule **holds** in Python: no `Path.home() / ".stackowl"` anywhere in
`src/` outside `paths.py`, and the three other `Path.home()` call sites, in two files, are OS-standard
locations that must *not* move with the home. But nothing asked the question when
the next one was added — D18.3 guarded shell scripts because that is where it had
broken, and its guard globs `*.sh`, so the Python case was not one short, it was
**zero**.

**The reference is the argument.** It has the same rule in its contributor guide, a
display helper built on it, and *no automated guard at all* — and its tree now
carries roughly twenty production files that build the home by hand, including a
script reaching the operator's real credential file. They shipped the ergonomics and
skipped the enforcement; the enforcement is the half that decayed. So: guard, no
helper.

## Verification

```bash
uv run pytest tests/test_settings_cannot_silently_discard_what_you_pass_it.py \
              tests/test_a_config_path_expands_like_a_human_wrote_it.py \
              tests/test_no_python_module_reimplements_the_home.py \
              tests/test_the_example_config_cannot_go_stale.py -q      # 15 passed
uv run python -c "
from stackowl.config.settings import Settings
print(Settings(webhook={'port': 9999}).webhook.port)          # 9999, not 8766
print(Settings(browser={'screenshots_dir': '~/shots'}).browser.screenshots_dir)
"                                                              # absolute, expanded
```

All RUN on 2026-09-05, not trusted. **Mutation-proven**, each restored from a file
copy and re-run green: dropping `init_settings` again (4 failures), reverting a
field to a bare `Path` (3), and a module building the home by hand (2).
