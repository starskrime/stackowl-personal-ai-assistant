# URL / Path / Egress Guards — Parity Holds, and One Comment Was Lying

**Item.** D17.4 · URL / path / egress guards — `PARITY`
**Last verified.** 2026-09-05, commit `HEAD`

## Why this exists

`PARITY`, Ask: none. A claim to verify, over three modules the map names.

## All three are wired, with named call sites

| guard | reaches |
|---|---|
| `infra/net/ssrf_guard.py` | `web_fetch` (via `guard_playwright_navigation`), `browser/sessions.py` (`make_route_guard`), `vision/loader.py` |
| `tools/io/path_guard.py` | `search_files`, `pdf`, `write_file`, `edit` |
| `web_search/providers/_egress.py` | `brave.py`, `searxng.py` |

The SSRF guard is **resolve-then-validate**: resolve the host, reject if *any* resolved IP is
loopback, private, link-local, carrier-grade NAT, multicast, reserved or unspecified, plus an
`http(s)`-only scheme allow-list. Cloud metadata at `169.254.169.254` is link-local and the
Alibaba literal `100.100.100.200` is CGNAT, so both are covered by class rather than by a list
of addresses.

`_egress.py` is not an egress *control* — it is egress **logging hygiene**, collapsing a URL to
`scheme://netloc/path` so a log records where a request went and never the query text or an
API key in the params.

## The third provider's zero is correct, and I checked before saying so

`egress_target` is used by two of three providers. `ddg.py` does not use it — and that is
right, not a gap: it drives a library rather than building an HTTP URL, so it has no URL to
strip. Its request line logs `{"egress": "ddgs:text"}`, a literal label, and its entry line
logs `query_len` rather than the query.

Recorded because the shape *looks* exactly like the "one case short" defect this session has
found five times, and it is the one that is not.

## What was actually wrong: a comment claiming to be tracked

The module docstring read:

> Known limitation **(tracked)**: this validates at call time. A TTL-0 rebind between this
> check and the socket connect, **and per-redirect re-validation**, need a pinned resolver /
> proxy egress.

**Two errors.**

**"(tracked)" was false.** `progress.yml` and every document under `docs/reference-mapping`
mentioned rebind, pinned resolver or proxy egress **zero** times. A tracking claim with no
referent is worse than an admitted gap: a reader checks the queue, finds nothing, and
concludes it was handled.

**Redirect hops were already validated.** `guard_playwright_navigation`'s own docstring is
"re-validate every navigation/redirect hop", and
`tests/infra/test_the_ssrf_guard_is_callable_as_a_route_handler.py` pins it. Half of what the
paragraph claimed missing had shipped — the same cost as a superseded finding left in the
present tense.

The paragraph now names **DEBT-118**, which exists, and claims only the residual: a TTL-0
rebind between check and connect, which needs a pinned resolver or proxy egress at the fetch
layer.

## And the guard I wrote for it was wrong first

The test asserted `ident in progress` and **passed** while pointing at `DEBT-117` — an id that
appears in `progress.yml` only inside another item's sentence *"recorded as DEBT-117"*, and
was never written into `known_debt`. Presence of a token is not existence of the thing: the
same weakness as D16.4's co-occurrence predicate, in a guard written one item later.

It now requires a literal `- id: DEBT-nnn` entry. **DEBT-119** records the dangling reference
so it is visible rather than looking tracked.
