# Conversation Compression

> **Status:** live
> **Map item:** D03.2
> **Source:** `src/stackowl/memory/conversation_compressor.py`, wired in
> `src/stackowl/pipeline/steps/classify.py` (`_compress_history`, `_summarize_region`)
> **Config:** `memory.short_term_window` in `stackowl.yaml`; module constants otherwise
> **Last verified:** 2026-09-07, against commit `213c264a` (previously 2026-09-01/`ab8184f7`)

## Why this exists

A conversation older than the last few turns was **gone**. `classify` read exactly
`memory.short_term_window` (default 6) turns and dropped the rest at the database, and no
recall path could reach them: every FTS and semantic route reads `committed_facts`, which
migration 0112 retired to zero rows, while `staged_facts` holds hundreds of rows whose
embeddings nothing searches. Beyond six turns the session had no memory of itself.

**The measurement nearly closed this item wrongly, and that is the useful part.** Across
129,675 recorded calls the largest single request was 162,912 tokens — 62.1% of the 262,144
window — and *zero* reached 90%. That reads as "there is no context pressure". Input never
approaches the window **because history was truncated before it was ever sent**. The
denominator was made of already-truncated history, so it could not show what truncation cost.

**AND THE 262,144 IN THAT SENTENCE WAS AN ASSUMPTION, not a reading — corrected
2026-09-08 (DEBT-244).** `cost_records` has persisted `input_tokens` for every one of
131,644 calls and the context window for NONE of them: the window lives in
`providers/model_window.py`'s in-process cache, which is EMPTY AT REST, so nothing
reading the table afterwards can recover the window that was in force. Every percentage
this document quotes is therefore an inference about a number nobody wrote down. The
literal denominator is now persisted beside the numerator it belongs to
(`cost_records.context_window`, migration 0140), so the figure above becomes a reading
rather than an assumption for every call recorded from here on. Historic rows stay NULL
on purpose: their window is not recoverable, and a DEFAULT would manufacture exactly the
assumption being removed.

**The cause reached one function.** `window_pressure` COMPUTED the fraction and JUDGED it
in the same breath, returning `None` below `_WINDOW_HIGH_WATER` — so the only code in the
tree that computed the ratio DESTROYED it for 131,637 of 131,644 calls, by design. An
exceedance counter can say IF a threshold was crossed and never HOW FULL things generally
run, which is why this item's closing check could only ever report `0`. `window_fraction`
is now the measurement and `window_pressure` ASKS it — one source for the ratio.

## Model

| Concept | Meaning |
|---|---|
| **head** | The opening `HEAD_TURNS` (2) turns. Never compressed — they carry the standing task. |
| **tail** | The most recent `TAIL_TURNS` (6) turns. Never compressed — this is what the current turn is replying to. |
| **middle** | Everything between. The only region that is ever summarized. |
| **prior summary** | A previous compression found in the input, identified by `SUMMARY_MARKER`. Folded into the next summary, never re-summarized as source. |

Two identifiers a reader will confuse:

| Name | Where | Meaning |
|---|---|---|
| `memory.short_term_window` | `stackowl.yaml`, default **6** | The *floor* on how many turns are read. No longer the cap. |
| `_DEEP_HISTORY_TURNS` | `classify.py`, **40** | How far back history is actually READ, so compression has something to work with. |
| `_HISTORY_BUDGET_TOKENS` | `classify.py`, **12,000** | Tokens history may occupy before the middle is compressed. Bounds the prompt's history share; it is **not** a window guard. |

## Lifecycle

```
classify
  └─ _gather_history(max(short_term_window, 40))      read deep, not 6
       └─ _compress_history
            ├─ select(history, budget_tokens=12_000)
            │    ├─ fits, or ≤ HEAD+TAIL turns  ──►  no-op, NO model call
            │    └─ over budget  ──►  Selection(head, middle, tail, prior_summary)
            ├─ build_prompt   preamble → prior summary → region → template
            ├─ _summarize_region   ONE call, floor=ceiling="fast"
            └─ apply(selection, summary, budget_tokens)
                 head + [SUMMARY_MARKER block, clipped] + tail
```

**Priority order, and it is behaviour:** a prior summary is stripped from the input *before*
budgeting, so it is never counted as a turn nor re-fed as source material. Head and tail are
protected *before* the budget is applied — they survive even when they alone exceed it.

## Invariants

> **I1.** Head and tail turns appear in the output verbatim, always — even when they alone
> exceed the budget. Summarizing the turn being replied to would answer a summary.
> **I2.** At most one `SUMMARY_MARKER` block exists in the output. Summaries fold; they never stack.
> **I3.** A prior summary is never included in the region being summarized.
> **I4.** A failed or absent summarization yields head + tail — exactly the old truncation
> behaviour, never worse than the input.
> **I5.** A failed summarization never discards an existing prior summary.
> **I6.** The emitted summary occupies at most `SUMMARY_BUDGET_SHARE` (0.25) of the budget.
> **I7.** When history fits the budget, no model call is made.

All seven map to tests in `tests/memory/test_a_long_conversation_is_compressed_not_forgotten.py`.

with no operator question behind them yet. Promote them when one appears.

## Observability

- `[pipeline] classify: conversation too long for the history budget — compressing the middle
  instead of dropping it` — INFO, `_fields`: `trace_id`, `turns`, `middle_turns`,
  `budget_tokens`, `had_prior_summary`.
- `[pipeline] classify: conversation compressed` — INFO, `_fields`: `trace_id`,
  `turns_before`, `turns_after`, `summarized`.
- `[compressor] summary exceeded its share of the history budget — clipped` — INFO.
- `[compressor] no summary available — the middle is dropped as it was before this existed` — INFO.
- `[pipeline] classify: history summarizer unavailable` — WARNING.
- `[pipeline] classify: compression FAILED — falling back to the untouched history` — ERROR.
- `[context] a single call used N% of the model window — conversation compression (D03.2) is
  coming due` — **WARNING**, `_fields`: `provider`, `model`, `input_tokens`, `window`,
  `fraction_of_window`. The standing watch that stops this item's closure rotting a second
  time: it fired 7 times in 131,644 calls, so it is rare and actionable. WARNING rather than
  INFO deliberately. **This watch shipped in `providers/base.py` and was documented NOWHERE
  until 2026-09-08** — the fifth-surface rule in its mirror, where a document goes stale by
  an ADDITION rather than a deletion.
- `[cost] …` — INFO, and now carries `window` and `fraction_of_window` beside `input_tokens`,
  so the DISTRIBUTION is observable and not merely the exceedances.

All at INFO or above, deliberately: production runs at INFO, and a DEBUG-only evidence line is
a check no volume of traffic can ever close.

```bash
cat ~/.stackowl/logs/stackowl*.jsonl \
  | jq -c 'select(.msg | startswith("[pipeline] classify: conversation")) | {ts, msg, f: .fields}'
```

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| No provider registry wired | `get_services().provider_registry is None` | Return head + tail | Nothing — old truncation behaviour |
| Summarizer call fails/times out | exception in `_summarize_region` | WARNING, return head + tail; any prior summary is kept | Nothing |
| Summary comes back empty | falsy result | Falls back to the prior summary if there is one | Nothing |
| Summary is enormous | `estimate_tokens` > share | Clipped on line boundaries, earliest headings kept | Nothing |
| Anything else in selection/apply | `except Exception` in `_compress_history` | ERROR, return the untouched history | Nothing |

Every path **fails toward the old behaviour**. Compression can never be the thing that costs a
turn — that is the floor the whole design is built on.

## Related

- Map items: `D03.1` (pluggable context engine) and `D03.3` (session splitting) are both
  blocked on this one.
- Prior art: ported from the reference platform's `context_compressor` — cheap-model summary of
  the middle, protected head/tail, **token-budget rather than message-count** selection, a
  structured Resolved/Pending template, iterative folding, and a filter-safe preamble.
- **Where we deliberately diverged.** Their compressor **splits the session** and chains it via
  `parent_session_id`; ours does not, because StackOwl has no session-lineage concept — that is
  `D03.3`, and doing it here would have coupled two items. We also did **not** resurrect the
  retired fact store to solve this: D08.1 retired `committed_facts` on purpose, and re-pointing
  recall at it would have reconciled away a recorded decision. The summary rides in the
  conversation instead, which needs no store at all.
