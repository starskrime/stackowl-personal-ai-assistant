# The Trace Win Is Real. Nothing Would Have Noticed It Regressing.

**Item.** D18.8 · Observability — `AHEAD`, track `keep`, wave 9, order 91.
**Ask.** "Keep — this is a clear StackOwl win and it is what makes debugging the
rewrite tractable."
**Answer.** Verified, and it holds. The gap was not in the tracing; it was that the
tracing had no alarm.

## The claim, verified rather than restated

An `AHEAD`/`keep` item's job is to check the claim, because "we are ahead here" is
exactly the kind of assertion that decays without anyone noticing.

**Propagation is genuinely there.** A real conversational turn produces a nested
tree — one trace carries **56 records across 11 spans**, with `[pipeline] triage`,
`[pipeline] dispatch`, `[memory] recall` and `[pipeline] classify` all parented to
the backend `run` span. Every one of the 21,523 records in the live log carries all
eleven trace fields.

**And the attribution defect that prompted the trace work stayed fixed:**

| day | cost records | blank `trace_id` |
|---|---|---|
| 2026-08-29 *(when it was found)* | 123,648 all-time | **54.5%** |
| 2026-08-30 | 3,003 | 3% |
| 2026-08-31 → 09-04 | 501–2,809/day | 0–2% |
| 2026-09-05 | 103 | **0%** |

The 51% all-time figure is pure history; nothing new is landing unattributed.

**The untraced majority of log lines is not a defect, and checking that mattered.**
80% of records carry no `trace_id`, which looked alarming until the denominator was
read: `[scheduler] registry.register` (1,813), `[skills] loader._load_one` (1,638),
`[skills] store.upsert` (1,638), `stackowl.startup` (3,495) — boot-time registration
and recovery sweeps, which have no request to belong to. Likewise `stackowl.tasks`
at 2 traced of 396: every one of those is a boot recovery sweep, not task execution.

## What was actually missing

`_bind_job_trace` is pinned by **three** test files. They pin the **code** — that a
scheduled job binds a lane. **Nothing watched the effect.**

The original 54.5% was found because a person happened to query for it. A new
background caller reaching a provider outside any `TraceContext` would reappear the
same way: silently, and visible only to whoever thought to look. This repo's standing
question — *if this degrades silently, what notices?* — had the measured answer
**nothing**, asked of its own observability.

So `UnattributedSpendContributor` now rides the health sweep that already runs every
five minutes, rather than adding a second loop. Its thresholds are measured, not
chosen:

* **degraded at ≥10% of a 24h window.** The failure sat at 54.5%; the repaired
  platform has run at 0–3% every day since. Ten per cent cannot cry wolf at the
  healthy rate nor stay quiet through a return of the original defect.
* **a floor of 20 records.** Two blank out of three is 67% and means nothing — the
  same shape as the "0 exemptions over 7 browser calls" reading, where a ratio was
  computed over a denominator that could not carry it.
* **degraded, never down.** Unattributable spend is a bookkeeping failure, not an
  outage. Reporting "down" for something that does not stop the platform is how an
  operator learns to ignore the health surface — a lesson this file's sibling already
  records, at the cost of 25 pages in one day for something that was never down.
* **an instrument failure is not a regression verdict.** "I could not measure it" and
  "it has regressed" are different claims.
* **the OK case carries its denominator**, because `store_cadence`'s own first live
  run returned a clean zero while a date bug had skipped almost every store it
  claimed to cover.

Run against the live database it reports `ok — 1 of 175 unattributed (1%) in 24h`.

## The residual, characterised rather than guessed

142 records since 2026-08-30 remain unattributed — **every one with
`system_prompt_chars = 0`**, no owl, 180–244 input tokens, and falling sharply: 107
on 08-30 to 1 on 09-04. A utility call with no persona.

**It is not attributed to a specific caller here, and that is the honest limit.**
`cost_records` carries no column naming the code path that made the call, so a blank
record cannot say what to fix — which is precisely why the first 54.5% needed a
person to reason it out from the shape of the data. Guessing a caller from a
signature would be exactly the unmeasured claim this programme bans. ESC-140 asks
whether that column is worth a migration for a 1%-and-falling residual, now that the
alarm makes the residual visible either way.

## The tenancy tripwire caught me making a defect this repo has already paid for

The first version of the query read `cost_records` with **no `owner_id` predicate** —
and `cost_records` is owner-governed. That is precisely the defect `CLAUDE.md` records
against `usage_report.py`, and `tests/tenancy/test_no_owner_scope_bypass.py` failed the
gate before the commit, with the right instruction in its own message: *"scope it by
owner_id rather than allowlisting new code"*, because the allowlist is for pre-existing
accessors. Scoped to `DEFAULT_PRINCIPAL_ID`. Every row is `principal-default` today, so
it narrows nothing now and closes the gap for when it does — the idiom several other
modules already record verbatim.

**This is the cross-cutting-guard argument in miniature.** A targeted test run picked by
what the change "looks related to" would have run `tests/health/` and seen five greens;
the guard that caught it lives in `tests/tenancy/` and looks related to nothing.


## Mutation testing caught my own weak guard

The registration test first searched `assembly.py` for the class NAME. Deleting the
`agg.register(...)` line left the **import** behind, so the name was still present
and the test still passed — it was guarding a string, not a wiring. It now walks the
AST for a `register()` call taking that constructor. **A guard for the
built-but-not-wired shape that was itself not wired to anything** would have been a
fitting way to fail this item.

```bash
uv run pytest tests/health/test_unattributed_spend_has_a_voice.py -q      # 5 passed
uv run python - <<'EOF'
import asyncio, os, sqlite3
from stackowl.health.contributors import UnattributedSpendContributor
db = os.path.expanduser("~/.stackowl/workspace/stackowl.db")
class RoDb:
    async def fetch_all(self, sql, params):
        c = sqlite3.connect(f"file:{db}?mode=ro", uri=True); c.row_factory = sqlite3.Row
        return [dict(r) for r in c.execute(sql, params)]
print(asyncio.run(UnattributedSpendContributor(RoDb()).health_check()))
EOF
#   expect: status "ok" with its denominator
```

All RUN on 2026-09-05, not trusted. **Mutation-proven**, each restored from a file
copy and re-run green: removing the registration (caught only after the guard was
sharpened), reporting an instrument failure as a regression, and removing the
small-denominator floor.
