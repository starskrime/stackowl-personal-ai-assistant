# Contextual onboarding — and the disclosure nobody has ever seen

> **Status:** audit; nothing built — the two decisions are escalated as ESC-154
> **Map item:** D14.3 · Contextual onboarding (`MISSING`)
> **Source:** `src/stackowl/setup/`, `src/stackowl/commands/onboarding_command.py`
> **Config:** none for hints; the wizard writes through `/provider add`, `/config set`,
> `/connect`, `/owl create`
> **Last verified:** 2026-09-06, against commit `ee5d1b41` — Verification section RUN

## Why this exists

The reference platform has `agent/onboarding.py`: no blocking questionnaire, just a one-time
hint the **first time the user hits a behaviour fork** — messaging while a turn runs, the
first long-running tool — tracked as `onboarding.seen.<flag>` in config and shown once per
install ever. The Ask: *"Add just-in-time hints alongside the wizard?"*

**Answering it required checking what we have, and the map's own description of our side is
wrong.**

## Model — what the map says, and what is actually there

The map's StackOwl line reads: *"`setup/` is a 3-step wizard + `setup/disclosure.py`
(progressive disclosure)."*

`setup/disclosure.py` is **not** progressive disclosure. Its first line is
`"""AiActDisclosure — EU AI Act disclosure management."""` — a legal notice, localised via
`localize("ai_act_disclosure", lang)`, with per-session show-tracking. It has nothing to do
with revealing features gradually.

| What we actually have | Where | Exercised? |
|---|---|---|
| 3-step setup wizard | `setup/minimal.py`, `setup/channel.py`, `setup/provider_catalog.py` | 1 run in the retained window |
| `/onboarding` button wizard | `commands/onboarding_command.py` | **0 invocations** |
| EU AI Act disclosure | `setup/disclosure.py` | **0 shows, and nothing calls it** |
| Just-in-time hints | — | **absent** |

**There is no once-per-install hint mechanism.** The nearest thing, `infra/nudge.py`, is a
per-lane INTERVAL counter held in process memory — it fires every N turns and resets on
restart, which is the opposite of "once per install, ever".

## The disclosure is built, tested, and unreachable

Measured 2026-09-06 across every module in `setup/`:

| module | importers in `src/` | importers in `tests/` |
|---|---|---|
| `localize` | 5 | 8 |
| `provider_catalog` | 2 | 5 |
| `minimal` | 2 | 5 |
| `onboarding_table` | 2 | 3 |
| `yaml_writer` | 2 | 1 |
| `lang_detect` | 1 | 2 |
| `channel` | 1 | 0 |
| `demo` | 1 | 0 |
| **`disclosure`** | **0** | **1** |

It is the only module in the package that nothing in `src/` imports. Five tests in
`tests/test_story_12_2.py` construct `AiActDisclosure` and assert `get_text()` returns
non-empty text in English and German — so the module has coverage, passes, and **is reached
by nothing but its own tests.** That is CLAUDE.md shape #5 exactly, and the tests are what
make it look alive.

The localisation key it reads (`localize.py:12`) exists, so the text is real. It has simply
never been shown to anyone: `grep` for `disclosure` across every retained log returns **0**.

**This is not filed as dead code to delete.** An EU AI Act disclosure encodes a legal
obligation someone deliberately added, and whether this deployment owes one is not an
engineering question. `/quiet` hit the same fork on 2026-09-05 and was escalated as ESC-126
rather than decided; this follows that precedent as **ESC-154**.

## Invariants

1. **A module with tests is not thereby wired.** The disclosure has five passing tests and
   zero production callers; coverage measures the test, not the reach.
2. **The map is a description, not a source of truth about our own tree.** Its
   "progressive disclosure" line has been wrong since it was written, and only reading the
   file found it.

## Failure modes

| Failure | Detected by | Recovery | User sees |
|---|---|---|---|
| A legal disclosure is owed and never shown | nothing today | — | nothing, which is the problem |
| The wizard is never found | nothing today | — | a first-run user who does not know `/onboarding` exists |
| A hint fires repeatedly because state is in memory | — | n/a; no hint mechanism exists | — |

That last row is the design constraint any future hint must satisfy: `infra/nudge.py`
cannot be reused as-is, because its counter dies with the process and this platform restarts
often — measured across 2026-09-01…06, boots ran 66–181 per day during development.

## Related

* `REFERENCE_MAP.md` — D14.3. **Its StackOwl line should be corrected**: `setup/disclosure.py`
  is an EU AI Act notice, not progressive disclosure.
* **ESC-154** — the two decisions this audit produced: wire or retire the AI Act disclosure,
  and whether just-in-time hints are wanted at all.
* **ESC-126** — the same wire-or-retire fork for `/quiet`'s `notification_overrides`, and the
  precedent for escalating rather than deleting.
* **Prior art and where we diverge.** Their hints are deliberately dependency-free so the CLI
  and gateway can both import them. If hints are ever built here the same constraint applies
  for a different reason: the gateway and core are separate processes, so a hint's
  once-per-install flag must live in config or the database, never in process memory — which
  is exactly why `infra/nudge.py` is not the substrate to reuse.
