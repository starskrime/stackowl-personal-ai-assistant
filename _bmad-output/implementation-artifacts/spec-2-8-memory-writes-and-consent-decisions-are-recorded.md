## Intent

**Problem:** Curated-md memory writes, the SQLite reflections learning store, and consent decisions (the consequential-action gate) leave no durable journal trail — `RecordKind` has no `MEMORY`/`CONSENT` members and none of their real write chokepoints call `journal.record()`.

**Approach:** Add `RecordKind.MEMORY`/`CONSENT`. Wire THREE real, narrow chokepoints: `CuratedMemory._write()` (`memory.written`, `md` `record_ref`, own fresh transaction — no existing DB mutation to piggyback on), `ReflectionWriterHandler.execute()`'s chunk loop (`memory.reflection_recorded`, piggybacks the ALREADY-open `db_pool.transaction()` around `ReflectionStore.write()`), and `ConsentPolicy._finalize()` (`consent.decided`, own fresh transaction into a NEW `consent_decision_records` table — mirrors Story 2.7's `turn_action_records` precedent for "no existing async DB write to join").

## Boundaries & Constraints

**Always:** `CuratedMemory.add/replace/remove/_write` become `async def` (every real caller — `tools/knowledge/memory.py`, `commands/memory_command.py`, `memory/rollover_summary_handler.py` — already runs inside an async function) and journal immediately after the atomic temp-file-replace, inside `_write` itself. `record_md_memory_write` reads a module-level `DbPool` set once via a new `curated.set_db_pool()` (mirrors `shared_memory()`'s existing module-global pattern — writes are already documented stateless) and no-ops (file write still succeeds) when unset. A journal failure there NEVER undoes the completed file write; it degrades `JournalHealthContributor` via `journal.record()`'s own existing failure path (recorder.py) and is swallowed (B5). `record_ref.locator` = `{"path": <StackowlHome-relative path>}`, `+ {"anchor": f"entry-{index}"}` when a specific entry has a stable post-write position (`add`: last index; `replace`: the replaced entry's preserved index) — `remove` omits `anchor` (the entry has no post-write position). `ReflectionWriterHandler`'s per-row `journal.record(tx, ...)` call is wrapped in its OWN `try/except` INSIDE the chunk's `async with self._db.transaction()` loop so a journal-only failure degrades health but never aborts/rolls back the chunk's real reflection rows (the surrounding `except Exception: continue` already treats any escaping exception as "lose this whole chunk" — B5 forbids a journal bug doing that to real learning data). `ConsentPolicy` gains a `db_pool: DbPool | None = None` dataclass field (wired once in `ConsentAssembly.build`/`startup/orchestrator.py`, mirroring `provider_registry.set_db_pool`); `_finalize` becomes `async def` (its 12 call sites in `request()`, already `async def`, gain `await`) and, AFTER the existing untouched sync `audit_logger.append()` call, ADDITIONALLY opens its own `db_pool.transaction()`, inserts one `consent_decision_records` row, and calls `journal.record()` inside that same commit — never blocking the `allowed` return value on failure (B5). All three new/changed record helpers read `trace_id` from `TraceContext.get()` ambiently (never a new required param); consent's `trace_id` is optional (`None` when absent — unlike Story 2.7's turn-scoped events, a consent decision is always recorded regardless of trace presence, since owl_build.py's direct `gate.policy.request()` call site may have none).

**Never:** Do not touch `AuditLogger.append()`/`chain_append_via_pool()` or migrate the consent audit write off its existing synchronous path — a live production consent gate with 11+ passing tests is not the place for that broader migration (logged as deferred). Do not instrument `BatchAuditor.grant/reject/action` (`tools/interaction/_batch_support.py`) — a structurally distinct, lower-severity (`write`), explicitly-non-consent-gate flow; logged as deferred, not silently dropped. Do not instrument `SqliteMemoryBridge.stage()` (`staged_facts` — a short-term buffer, not curated knowledge) or `SqliteLessonsStore.publish()` (an explicitly best-effort, non-gating derived search index) as "the SQLite memory write" — `ReflectionStore.write()` is the one that is durable, gating, and already `conn`-joinable. Do not invent a per-entry heading/anchor scheme inside `curated.py`'s md files themselves (out of scope, unrequested) — the anchor is a locator-only convention the journal record carries, never written into the `.md` file's own bytes. Do not restart the live production core/gateway process.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| `add` succeeds | `CuratedMemory.add(target, text, durability)` | File written, then `memory.written` recorded, `attrs.op="add"`, `record_ref.locator.anchor="entry-{last_index}"` | n/a |
| `replace` succeeds | `.replace(...)` | `memory.written`, `op="replace"`, anchor = the replaced entry's preserved index | n/a |
| `remove` succeeds | `.remove(...)` | `memory.written`, `op="remove"`, locator has no `anchor` | n/a |
| journal write fails after a curated file write | `record_md_memory_write` raises internally | File write stands; `JournalHealthContributor` degrades; `MemoryResult` returned to the caller is unaffected | Logged ERROR, swallowed |
| no `DbPool` wired (test / standalone construction) | `set_db_pool` never called | File write succeeds; nothing journaled, no error | n/a |
| a reflection chunk commits | `ReflectionWriterHandler.execute()` chunk loop | Each row: `reflections` INSERT + `memory.reflection_recorded` in the SAME commit | n/a |
| journal write fails for one reflection row | `journal.record()` raises inside the per-row try | That reflection row still commits (chunk NOT rolled back); health degrades | Logged ERROR, swallowed |
| consent decision: allowed | `ConsentPolicy._finalize(True, ...)` | Existing sync audit row (unchanged) + `consent.decided` row, `outcome=ok` | n/a |
| consent decision: denied | `_finalize(False, ...)` | `outcome=failed`, `attrs.decision="deny"` | n/a |
| consent decision with no `db_pool` wired | fallback `ConsentPolicy()` (no db_pool, e.g. `registry.py`'s bare fallback) | Decision unaffected; nothing journaled | n/a |
| consent journal insert fails | new transaction raises | `allowed` return value unaffected; health degrades | Logged ERROR, swallowed |

## Tasks & Acceptance

**Execution:** `journal/enums.py` (RecordKind.MEMORY/CONSENT) → migration `0147` → `journal/memory_events.py` → `journal/consent_events.py` → `journal/__init__.py` → `health/store_cadence.py` → `memory/curated.py` (db_pool global + async signatures) → its 3 external call sites (`tools/knowledge/memory.py`, `commands/memory_command.py`, `memory/rollover_summary_handler.py`) → `memory/reflection_writer_handler.py` → `tools/consent.py` (db_pool field + async `_finalize`) → `tools/consent_assembly.py` → `startup/orchestrator.py` (both wirings) → `deferred-work.md` → mechanical test `await` updates → all new tests.

**Acceptance Criteria:**
- Given a curated md write (add/replace/remove) completes, when `_write` returns, then a `memory.written` event is recorded with an `md` `record_ref` (`path` always, `anchor` for add/replace), and a failed record degrades `JournalHealthContributor`.
- Given a reflection write commits inside `ReflectionWriterHandler`'s chunk transaction, when the chunk commits, then `memory.reflection_recorded` is in `journal_events` with the same `trace_id`, in the SAME commit as the `reflections` row.
- Given a consent decision is finalized (allowed or denied) with a `db_pool` wired, when `_finalize` returns, then `consent.decided` is recorded with `outcome` ok/failed and its own `consent_decision_records` row, never blocking the returned `bool`.
- Given `memory.written`, `memory.reflection_recorded` and `consent.decided`, when the tripwires run, then each has an `attrs` model, `RecordKind.MEMORY`/`CONSENT`, `AttentionClass.AMBIENT`, and a narration.
- Given canary secret strings driven through each of the three real recording paths, when the row is inserted, then no canary appears unredacted (NFR33).

## Design Notes

**Why `consent_decision_records` (a new table) instead of migrating onto `chain_append_via_pool`.** `chain_append_via_pool` (audit/logger.py) already exists for exactly "join a caller's open `db_pool.transaction()` so an audit row and a journal event commit atomically" (Story 2.6's own precedent, its docstring). It would be the more DRY choice — but doing so here means converting `ConsentPolicy._finalize`'s CURRENT synchronous `audit_logger.append()` (the one 11+ existing tests exercise) into the async path, on a live production consent gate. Story 2.7 already established the fallback for "no existing async DB mutation to piggyback on": open a fresh, self-contained transaction and a small dedicated table as the `record_ref` target (`turn_action_records`). This story follows that same, more recent, more directly analogous precedent rather than the older `chain_append_via_pool` — deliberately trading one small duplicated table for a materially smaller, lower-risk diff on a production-critical path. Logged as deferred (a real, reasoned alternative, not a gap).

**Why curated md's `add`/`replace`/`remove` become `async def`** even though this touches 6 production call sites and ~9 test files: every real production caller already runs inside an `async def`; the alternative (fire-and-forget `asyncio.create_task` from a sync method) makes "immediately after" nondeterministic and untestable, and silently drops the event entirely from any hypothetical sync caller. The test-file churn is mechanical (`def test_x` → `async def test_x`, `mem.add(...)` → `await mem.add(...)`), not a logic change.

**Why `remove` has no `anchor`.** A removed entry has no post-write position — the file's remaining entries all shift. `record_ref.locator` for a `remove` therefore carries `path` only; the file itself is still the correct, honest pointer to "what changed."
