## Intent

**Problem:** A turn's model calls, tool calls and delegation hops leave no durable, queryable record — the journal (2.1–2.6) has no `model.*`/`tool.*`/`delegation.*` event types, and this is the highest-volume consumer the journal will ever have (fires on every provider round, every tool dispatch, every A2A hop, across the whole platform).

**Approach:** Register `model.called`, `tool.called`, `delegation.hopped` (new `RecordKind.TURN`) at the THREE existing narrow chokepoints every one of these actions already funnels through — `ModelProvider._dispatch_post_llm` (providers/base.py, every remote round of every provider), `_guarded_dispatch` (pipeline/steps/execute.py, every real tool execution), `A2ADelegator.delegate` (owls/a2a_delegation.py, every specialist hop) — instead of the ~20 scattered `provider.complete()`/`complete_with_tools()` call sites the `LLMGateway` docstring warns bypass it. A new `turn_action_records` table (migration, AD-4's "target with no owning store") is each event's `record_ref` (named `turn_action_records`, not `turn_decisions` — a table of that name already exists, migration 0071, backing the unrelated ADR-7 `/explain` surface; see Design Notes). A provisional per-`trace_id` write-budget (AD-38, Story 2.12 finalises the number) logs a WARNING and degrades journal health on overflow — it NEVER drops an event.

## Boundaries & Constraints

**Always:** Each of the three recording helpers (`journal/turn_events.py`) opens its OWN `DbPool.transaction()` (no existing state mutation to piggyback on for these three actions) and inserts the `turn_action_records` row + calls `journal.record()` inside it — same commit, AD-24. The helper NEVER lets a journal failure propagate into the turn: wrap in `try/except Exception`, log at ERROR with `exc_info`, degrade journal health, and return — mirrors `providers/base.py::_record_cost`'s existing B5 contract ("cost accounting can NEVER break or block a completion that already happened") applied to these three sites too. Recording fires ONLY when `TraceContext.get()["trace_id"]` is set (i.e., inside a real turn) — a health-probe `complete()` call or other backgroundless call is skipped, never journaled with an empty trace. `ActorKind.OWL` (new, additive) + `actor_id=TraceContext.get()["owl_name"]` on every event (AD-2's "the owl as actor"); `target_kind=ActorKind.OWNER` for `model.called`/`tool.called` (no better-fitting existing member — same fallback 2.1–2.6 already use for every domain without its own kind) and `target_kind=ActorKind.OWL` for `delegation.hopped` (the target genuinely is another owl, and the vocabulary now has the member). `target_id` (envelope-level, mirrors the heal/health precedent of a specific bounded label distinct from the coarse `target_kind`) is `provider` for `model.called`, `tool_name` for `tool.called`, `to_owl` for `delegation.hopped` — the same value also carried in `attrs` so narration never needs a DB lookup. All three types are `AttentionClass.AMBIENT` (a single call/hop failing mid-turn is not a give-up — AD-5 names only explicit exhaustion events as `needs_you`). `tool.called`'s error code is a NEW small closed `ToolCallErrorCode` enum (`TIMEOUT`, `UNVERIFIED_EFFECT`, `TOOL_FAILED`) derived from branch shape at the call site — never `ToolResult.error` text (that is free-form tool-author prose, not classifiable safely). `model.called`'s error code REUSES `HealthErrorCode`/`classify_health_error` (2.6, `journal/enums.py`) against the caught provider exception — no new exception-classification logic. `delegation.hopped` carries the full `DelegationStatus` value (already a closed, bounded-label enum) in `attrs.status`; `outcome` collapses it to `Outcome.OK` (ok/empty) or `Outcome.FAILED` (timeout/child_error) — attrs keeps the detail the closed envelope field cannot. The per-turn budget (`journal/turn_budget.py`) is a provisional constant (mirrors `journal/retention.py`'s Story 2.6 precedent) backed by a bounded, evictable per-`trace_id` counter (reuse `infra/bounded_mru.py`'s shape, not a fresh cache) — exceeding it logs one WARNING per trace and calls a new `journal/health.py::note_budget_exceeded()` (additive field alongside the existing consecutive-failure state, both readable by the one `JournalHealthContributor`).

**Never:** Do not journal a PRE-EXECUTION refusal (`_dispatch`'s `denied_this_run`/`deterministic_dead`/circuit-open/missing-param branches, or a delegation refused before `A2ADelegator.delegate()` is even called) — these already "record nothing" by the P0 honesty-invariant convention `execute.py` documents inline; only a REAL dispatch (`_guarded_dispatch`) or a REAL hop (inside `delegate()`) is journaled. Do not put the journal write on the plugin `hooks.dispatch(PRE_LLM_CALL/POST_LLM_CALL/...)` path (`plugins/hooks.py`) — that seam is explicitly best-effort/droppable/auto-disarming after 3 consecutive failures, which violates AD-38's "never drop events". Do not carry `ToolResult.error`, tool `args`, provider messages, or delegation `sub_task`/response content into `attrs` — metadata only (AD-4). Do not build a real `journal/retention.py` prune job or change its provisional constant (2.6/2.11 own that). Do not build a Bridge-facing `record_ref` reader UI (AD-4's aspirational "registered reader" is not built by any story through 2.6 either — verified by grep; out of scope here too). Do not restart the live production core/gateway process.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Model round succeeds | `_resilient_round` returns | `model.called` recorded, `outcome=ok`, `record_ref`→new `turn_action_records` row, `attrs.provider` bounded label | n/a |
| Model round raises a classified provider fault | `_dispatch_post_llm(started, ok=False, exc=...)` | `model.called` recorded, `outcome=failed`, `attrs.error_code` from `classify_health_error(exc)` | n/a |
| Real tool dispatch times out | `_guarded_dispatch` hits `_TOOL_DEADLINE_S` | `tool.called` recorded, `outcome=failed`, `error_code=TIMEOUT` | n/a |
| Real tool dispatch succeeds but unverified | `r.success=True, r.verified=False` | `tool.called` recorded, `outcome=ok`, `error_code=UNVERIFIED_EFFECT` | n/a |
| Tool call pre-execution refused | `denied_this_run`/`deterministic_dead`/circuit-open branch in `_dispatch` | No `tool.called` recorded | n/a |
| Delegation hop times out | `A2ATimeoutError` in `delegate()` | `delegation.hopped` recorded, `outcome=failed`, `attrs.status="timeout"` | n/a |
| Delegation hop succeeds | fall-through return | `delegation.hopped` recorded, `outcome=ok`, `attrs.status` mirrors the governor-decided status | n/a |
| No trace_id in context (health probe) | `TraceContext.get()["trace_id"]` is `None` | Nothing recorded at any of the three sites | n/a |
| Per-turn write budget exceeded | same `trace_id` crosses `PROVISIONAL_TURN_EVENT_BUDGET` | WARNING logged once per trace, journal health degrades, the event is STILL recorded | n/a |
| The recording transaction itself fails | `journal.record()` raises inside the helper's `db.transaction()` | Caught, logged at ERROR, journal health degrades via existing `note_failure`; the turn's own model/tool/delegation outcome is UNAFFECTED | n/a |
| A real turn end-to-end (dev-ingress-equivalent slice) | mock provider issues one tool call + one delegation | `journal_events` holds `model.called`, `tool.called`, `delegation.hopped` rows in cursor order, all one `trace_id`; canary secrets never appear | n/a |

## Tasks & Acceptance

**Execution:** `journal/enums.py` (ActorKind.OWL, RecordKind.TURN, ToolCallErrorCode) → migration `0146` → `journal/turn_budget.py` → `journal/health.py` (budget field) → `journal/turn_events.py` (attrs + register + 3 helpers) → `journal/__init__.py` → `health/store_cadence.py` → `providers/base.py` (db_pool field/setter, `_dispatch_post_llm` exc param + model.called call) → `providers/registry.py` (`set_db_pool`) → `startup/orchestrator.py` (wiring) → `pipeline/steps/execute.py` (`tool.called` at both `_guarded_dispatch` branches) → `owls/a2a_delegation.py` (`delegation.hopped` at 3 return points) → `deferred-work.md` → all tests.

**Acceptance Criteria:**
- Given a turn makes a model call, a tool call or a delegation hop, when the action completes, then the matching event is recorded with `trace_id`, `duration_ms`, `outcome`, an error code (when failed), a bounded provider/tool/owl identifier, and `ActorKind.OWL` as actor.
- Given canary secret strings driven through each of the three real recording helpers, when the row is inserted, then no canary appears unredacted in `journal_events.attrs` (NFR33).
- Given a `turn_action_records` row backing any of the three event types, when its `record_ref` is opened, then the row is present.
- Given the "smallest real slice" integration test drives one turn with only the provider mocked, when the turn completes, then `journal_events` holds its model, tool and delegation events in cursor order under one `trace_id`.
- Given the per-turn write budget is exceeded, when the next event for that `trace_id` is recorded, then a WARNING is logged, journal health degrades, and the event is still recorded.
