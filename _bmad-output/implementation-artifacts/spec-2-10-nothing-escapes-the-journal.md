## Intent

**Problem:** The journal (Stories 2.1-2.9) has no proof that it covers everything: `EventTypeSpec` (`journal/registry.py`) declares no table, so nothing can diff "every migration-created table" against "what the registry covers" (AD-3); event types can never gain a second `schema_version` safely because no upcaster mechanism exists at all (DW-16); and `record_ref` (AD-4) has zero registered readers anywhere — nothing can open a `{kind, locator}` target back into typed content, and a pruned/missing target has no defined "expired" behavior.

**Approach:** Give `EventTypeSpec` an optional `table` field (populated at each of the 9 existing `*_events.py` registration call sites), build `journal/coverage.py`'s `UNJOURNALED_TABLES` (every currently-live non-journal table, reasoned and explicit) plus a coverage tripwire that diffs the real migrated schema against registry-covered ∪ excused tables. Add a minimal versioned-model/upcaster registry to `EventRegistry` (`register_upcaster`, `versions_for`) plus a tripwire proving no version with live rows lost its model. Build `journal/records.py`'s reader registry keyed by `(RecordKind, carrier)` and wire one typed, authority-checked, never-raising reader per already-registered event domain, returning `ExpiredRecord` for a missing target.

## Boundaries & Constraints

**Always:** `table=` is added to every existing registration call for a sqlite-backed type (`tasks`/`jobs`/`heal_attempts`/`health_status_changes`/`turn_action_records`/`reflections`/`consent_decision_records`/`delivery_records`/`channel_ingress_records`); `memory.written` (md-backed) keeps `table=None`. `UNJOURNALED_TABLES` reasons are explicit and reviewable: a shared categorical reason for pre-epic-2 legacy tables (mirrors `health/store_cadence.py`'s own bucketed-`Cadence` precedent), a specific DW-25-citing reason for `audit_log`, and one for `journal_events` itself (the ledger, not a target). Readers are per-`(RecordKind, carrier)` functions supplied by their owning `*_events.py` module (mirrors `narrator.py::register_name_resolver`'s module-dict+`RLock`+duplicate-refusing-register+test-reset shape exactly), take `owner_id: str` and refuse (raise, never silently pass) a mismatch against `tenancy.DEFAULT_PRINCIPAL_ID` — this platform's real, single-owner authority model (same reasoning DW-25/DW-26 already used). A reader whose row is gone returns `ExpiredRecord`, never raises, never returns `None`. `md` readers only ever open a file for read (`StackowlHome`-relative path from the locator), never write. The coverage/upcaster tripwires get `@pytest.mark.tripwire` (`scripts/tripwires.sh`'s only selection mechanism) and each ships a "control" test proving it can genuinely fail (matches `test_retention_tripwire.py`'s established convention). The live "migrated table set" comes from actually running all migrations and querying `sqlite_master` (mirrors `tests/health/test_every_store_declares_its_cadence.py::_schema_tables`), never from hand-parsing `.sql` files.

**Never:** Do not wire the upcaster framework into `journal/fanout.py::read_since` or `narrator.py`'s real read path — DW-16's own text assigns that to whichever future story first bumps a `schema_version` past 1; this story ships only the registration API + the completeness tripwire. Do not build a `bridge/` package or a graph-carrier reader — `bridge/` does not exist yet (confirmed); ship a grep/AST tripwire (`bridge/` never reads a table generically) that vacuously passes today and fires the moment `bridge/` is added without complying, mirroring `test_EventTypeSpec_is_constructed_only_inside_journal`'s convention. Do not touch `DurableTaskStore.create()` or its 4 direct callers (`react_runner.py:131`, `executor.py:150`, `task_runner.py:178-211`, `rollover_summary_handler.py:400-404`, DW-7) — `tasks` is already registry-covered at the table level (the only granularity AD-3's coverage tripwire operates at per its literal epics.md text), so the table-diff tripwire correctly reports it covered; the real gap is call-site-level and `enqueue()`'s transaction does an additional loop-contract UPDATE these 4 direct-`create()` callers' already-running tasks never populate, so blindly switching them to `enqueue()` would misrepresent their lifecycle — update DW-7's ledger entry with this precise finding instead of patching a live task-execution hot path under this story's literal AC scope. Do not touch `BatchAuditor`/`AuditLogger`/`audit_log` (DW-25) — mark `audit_log` `unjournaled` with the stated reason instead; resolve DW-25's status accordingly. Do not build full md section-anchor extraction — the md reader returns the whole file's text plus the locator's anchor as metadata. Do not restart the live production core/gateway process. Do not edit `sprint-status.yaml`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Coverage tripwire, real schema | freshly-migrated scratch DB | every live table in `registry.tables_covered()` ∪ `UNJOURNALED_TABLES` | fails, names any gap table |
| Coverage tripwire, injected new table | scratch DB + one extra ad-hoc `CREATE TABLE` after migrating | that table is in the computed gap | assertion names it (AC4) |
| Upcaster tripwire, real data | every registered type is v1-only | trivially satisfied — no version lacks a model | n/a |
| Upcaster tripwire, control case | throwaway registry: type registered only at v2, a v1 row simulated | `_missing_versions` reports `(type, 1)` | proves the check can fail |
| Reader opens an existing row | valid locator, matching `owner_id` | typed view model returned | n/a |
| Reader opens a pruned/missing row | locator's row absent | `ExpiredRecord` returned | never raises |
| Reader called with wrong owner | `owner_id != DEFAULT_PRINCIPAL_ID` | refused | raises loudly, never silent |
| md reader opens memory.written's target | valid `StackowlHome`-relative path | file text + anchor metadata returned | missing file → `ExpiredRecord` |
| Duplicate reader registration | same `(RecordKind, carrier)` registered twice | second call refused | raises `ValueError` |

## Tasks & Acceptance

**Execution:** `registry.py` (`table` field + `tables_covered`/upcaster API) → the 9 `*_events.py` files' `table=` kwargs → `coverage.py` → `records.py` → the 9 `*_events.py` files' reader additions → all new tests → `deferred-work.md` updates.

**Acceptance Criteria:**
- Given the migrated table set, when the coverage tripwire runs, then every table is `registry.tables_covered()` or `UNJOURNALED_TABLES` with a written reason, diffed against the real schema (AD-3).
- Given an event type with >1 `schema_version`, when the upcaster tripwire runs, then it fails if any version with live rows (by `MIN(cursor)`) lost its model/upcaster; proven via a control case since no real type has >1 version yet.
- Given each `(RecordKind, carrier)` pair with a registered reader, when it runs, then it is typed, authority-checked (`owner_id`), and a missing target opens `ExpiredRecord`, never an error.
- Given a new migration adds an uncovered table, when the tripwires run, then the coverage tripwire fails and names it.

## Design Notes

**Why `EventTypeSpec.table` instead of a hand-maintained type→table dict:** a parallel dict can drift from the real registration call sites exactly the way `health/store_cadence.py`'s own docstring warns against ("a hand-maintained list rots the first time someone adds a table and forgets") — putting `table` on the spec itself, set at the same call site as the type's other metadata, removes that drift class entirely.

**Why `(RecordKind, carrier)` instead of `RecordKind` alone:** AD-4's "each record kind has one registered reader" reads naturally as the `RecordRef.kind` carrier (`sqlite`/`md`/`graph`), but "supplied by the owning subsystem" (task/job/heal/...) is `journal.enums.RecordKind`. `memory` is the one domain that needs both (`memory.written` is `md`, `memory.reflection_recorded` is `sqlite`) — keying by the pair resolves the ambiguity without inventing two competing registries.

**Why `owner_id == DEFAULT_PRINCIPAL_ID` is the authority check:** no generic `authz.may()` exists; the established idiom (`tenancy.OwnedRepository`) is row-level `owner_id` scoping, but none of the journal record-ref tables carry an `owner_id` column (confirmed: `turn_action_records`, etc.) — this is a single-owner platform (the same reasoning DW-25/DW-26's review threads already used), so the honest, minimal "authority check" a reader can make today is refusing any caller that isn't the one owner, loudly.
