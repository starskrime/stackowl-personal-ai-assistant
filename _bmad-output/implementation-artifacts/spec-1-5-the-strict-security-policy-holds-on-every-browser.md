## Intent

**Problem:** The Bridge spike kit (`spikes/bridge/`) has no front end built on the pinned stack (Svelte 5.57.0, three 0.186.0, Vite 8.3.0, TypeScript 6.0.3/svelte-check 4.7.6, Node ≥22.12.0) and serves no security headers at all today (`server.py` has no headers middleware; `static/index.html` and `static/offline-summary.html` use inline `<style>`/`<script>` and raw `innerHTML` assignments), so nothing proves the real Bridge can ship under AD-36's strict CSP/Trusted Types policy without ever relaxing it.

**Approach:** Add a minimal pinned-stack front-end build (`spikes/bridge/frontend/`) that renders the AD-40 owl mark both as a DOM `<img>` and inside a `three/webgpu` `WebGPURenderer` scene (auto-fallback to WebGL2), with its build output committed and served by the kit at `/csp-check/`; add a global aiohttp middleware in `server.py` that stamps the exact AD-36 header set (verbatim below) on every response, including error responses; retrofit the two existing static pages so they keep working under that policy (external CSS/JS, no `innerHTML`); and extend `check.py`'s automated Chromium check to prove zero `securitypolicyviolation` events, the exact header set, and the WebGL2 fallback path, writing `results/B5-desktop-chrome-automated.json`.

## Boundaries & Constraints

**Always:**
- Every response from the kit's one `BridgeServer` (success and error alike) carries exactly this `Content-Security-Policy` (AD-36, verbatim, one line, semicolon-separated, no other directives added or removed): `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; media-src 'self' blob:; worker-src 'self'; manifest-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'; require-trusted-types-for 'script'` plus `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, and `Permissions-Policy: microphone=(self)`. Define this set once (e.g. `SECURITY_HEADERS` in `server.py`) and import it into `check.py` rather than duplicating the literal strings.
- Exactly one named `trustedTypes.createPolicy(...)` call exists across the kit's front-end code (NFR22); it must be genuinely exercised (something real goes through it), not dead code.
- Existing Story 1.1-1.4 automated-check steps (`_check_certificate_chain_and_redirect`, `_check_passkey_and_device_approval`, `_check_push_and_mic`, `_check_webtransport_and_sse`) must still pass unmodified in behavior once the header set is global — fix the pages, never weaken the policy or skip a route.
- `frontend/` declares its own `package.json`/`package-lock.json` and pins the exact versions named above; nothing from it enters the platform's own `pyproject.toml`/`uv.lock`, mirroring the kit's existing PEP 723 isolation for Python deps.
- The front-end build output that the server actually serves is committed to the repo (a fresh clone needs neither Node nor a network to run the kit) — use a build output directory name that is NOT `dist/` (root `.gitignore:12` ignores `dist/` repo-wide); e.g. `frontend/build/`. Add a scoped `spikes/bridge/frontend/.gitignore` for `node_modules/`.
- Owl mark geometry, in both the DOM view and the Three.js scene, is sourced from `logo/stackowl-mark.svg` (AD-40) — never hand-redrawn or duplicated as literal path data.

**Never:**
- Never relax, shrink, or make conditional the CSP/Trusted-Types header set to get a page working — fix the offending markup/script instead (this is the AC's own explicit non-negotiable).
- Never reintroduce `{@html}`, `.innerHTML =`, or `.insertAdjacentHTML(` anywhere the lint check covers.
- Never touch `src/stackowl/` (real platform code) — this remains throwaway spike work under `spikes/bridge/`.
- Never add a real-device (non-Chromium, non-build-host) run here — that is Story 1.6's job per the epic context.

## Design Notes

- **Why a separate `/csp-check/` route instead of replacing `/`:** the epic context states Story 1.5 is independent of 1.1-1.4; `/` is the shared trust-ceremony/passkey/push/mic/stream harness those stories' own automated checks drive. Replacing it would conflate two stories' completion bars. The header set still applies kit-wide (the AC's own "any kit response"), so `/` must also be fixed to comply -- it just doesn't need to host the new Svelte/Three build.
- **Why `eval()` for the detector self-test:** every other "prove the detector isn't vacuous" step in this kit (subnet refusal, endpoint refusal) patches a real guard and re-proves it fires; CSP has no code-level guard to patch, so the closest equivalent is genuinely tripping the browser's own enforcement (`script-src 'self'` has no `'unsafe-eval'`) and confirming the listener captures it.
- **Trusted Types policy's genuine use:** rather than a policy that is registered but never called (which would be dead code, and arguably not "exist" in the load-bearing sense NFR22 intends), use it for one real sink -- e.g. `policy.createHTML(...)` feeding the renderer-backend status label -- so removing the policy would break something the check observes.
- **SVGLoader for the Three.js scene:** `three`'s `examples/jsm/loaders/SVGLoader.js` parses raw SVG path data into `THREE.Shape`s at runtime; fetching `logo/stackowl-mark.svg` at runtime (rather than hand-copying its path string) is what makes the AC's "imported from logo/stackowl-mark.svg" literally true for the 3D view, matching how the DOM `<img>` also references the same file.
