## Intent

**Problem:** `HelloFrame` today travels core→gateway only, carries just `protocol_version` (never compared to anything), and an unknown/undecodable frame is silently `continue`d past in `FrameConnection._iter()` — a half-upgraded install (mismatched code, migrations, or event registry between gateway and core) can corrupt data or drop messages with no signal.

**Approach:** Exchange `HelloFrame` in both directions (gateway sends on accept, core sends after its DB pool opens), each carrying `protocol_version`, the highest applied migration number, and an event-registry digest (type+schema_version pairs plus an attention-policy version). A pure `evaluate_hello()` both sides run identically refuses any mismatch with an ERROR naming both sides' values; whichever side is provably older reacts (core restarts via the existing `restart_event`/execv path; gateway is never provably older by this determination alone — see Boundaries). Gateway pauses its own journal writes on any link loss/mismatch until a matching Hello is confirmed. Repeated mismatches stop the core respawn loop and surface the link as `degraded` with a remedy. Unknown frames log a WARNING naming the type instead of vanishing. `SteerFrame`/`StopFrame`/`QueryRunningFrame`/`RunningStateFrame` (dead: zero production references) are deleted and `protocol_version` bumps.

## Boundaries & Constraints

**Always:** `evaluate_hello(local, remote, local_is_core)` is pure/sync, called identically on both sides from the SAME two Hello payloads so they agree independently. Ordering: lower `protocol_version` is older; if equal, lower `highest_migration` is older; if both equal but `registry_digest` differs (no inherent ordering for a hash), the **gateway** is treated as the older side — core is always freshly spawned from current on-disk code at connect time, so it is the canonical reference on a digest-only split. Every mismatch logs one ERROR naming both full Hello payloads (never just one side). Gateway recomputes its own Hello fresh (new DB query for `highest_migration`) on every accepted connection — never cached across core restarts (AD-33's "re-checks `schema_head`... before its first write after any link loss"). `journal.record()` raises `JournalWritesPausedError` (with `.remedy`) while the gateway's write-gate is paused; the gate pauses on every `GatewayLink.drop_connection()` and every incompatible Hello, and resumes only on a confirmed-compatible one. `ipc/connection.py`'s frame loop logs a WARNING naming the frame's `type` (best-effort JSON extraction) on every undecodable/unknown-type line — never a silent `continue`. New/changed `HelloFrame` fields keep `extra="forbid"`; `protocol_version` bumps.

**Never:** The gateway does not self-restart (os.execv) in this story. `CoreLink`/`_core_frame_loop` today treat any dropped gateway connection as terminal (core tears itself down) — teaching core to wait-and-reconnect across a gateway restart is a separate, larger change this story does not make. When the gateway determines *it* is the older side, it refuses new links, pauses writes, and (once `_supervise_core`'s respawn attempts exhaust `_MAX_CONSECUTIVE_HELLO_MISMATCHES`) reports the link `degraded` with a remedy telling the operator to restart the gateway process — full automatic gateway self-restart is logged to `deferred-work.md` as DW-11, not built here. Never register the new link-health contributor into the liveness/self-kill aggregator (`_build_liveness_aggregator`) — only the general sweep (mirrors `JournalHealthContributor`, status `degraded`, never `down`). Never touch `CoreLink` (`runtime/core_link.py`, confirmed dead code, zero instantiations) — out of scope. Never open an `incident` journal event (Epic 3's territory per epic-2-context.md).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Matching Hello both ways | Fresh core connects, both sides compute identical (protocol_version, highest_migration, registry_digest) | Gateway stops buffering, flushes pending; write-gate resumes | n/a |
| protocol_version mismatch | Core's is lower | `evaluate_hello` returns `older="local"` on core's own evaluation | Core sets `restart_event` (quiesce→teardown→execv) |
| highest_migration mismatch, protocol_version equal | Gateway's migration count is lower (stale) | Both sides log ERROR naming both payloads | Gateway pauses writes, stays buffering; does not flush |
| registry_digest-only mismatch | protocol_version and highest_migration equal, digest differs | Gateway is deemed older by convention | Gateway pauses writes, refuses; core does NOT restart itself |
| Repeated mismatches | Gateway is the older side across N consecutive core (re)connections | `_supervise_core` stops respawning at the limit | CRITICAL log; `GatewayCoreLinkHealthContributor` reports `degraded` with a remedy |
| Link lost mid-session | `GatewayLink.drop_connection()` fires (core crash or clean disconnect) | Journal write-gate pauses immediately | Resumes only after the next compatible Hello |
| Unknown frame type on the wire | A line JSON-decodes but `type` isn't in the `Frame` union | WARNING naming the type; connection stays alive | Never a silent `continue` |
| Malformed (non-JSON) line | Garbage bytes | WARNING with no type (best-effort extraction failed) | Never a silent `continue` |

## Tasks & Acceptance

**Execution:** see Code Map (every entry above is one task; execute DB/registry/exceptions/write-gate pieces first, then `runtime/hello.py` + `link_health.py`, then the `GatewayLink`/`_supervise_core`/orchestrator wiring, then the frame deletions + unknown-frame-type fix last since they touch the shared `Frame` union every other piece's tests construct).

**Acceptance Criteria:**
- Given gateway and core connecting, when Hello is exchanged, then it travels in both directions carrying `protocol_version`, the highest applied migration number, and the registry digest (types, versions, attention policy version), and every new/changed frame stays `extra="forbid"` in `ipc/frames.py`.
- Given any mismatch in those three values, when the link is evaluated, then it is refused with an ERROR log naming both sides' values, and — per this story's scoped ordering rule (gateway is never self-restarting; see Boundaries) — a genuinely older core restarts via the existing `restart_event` path; a genuinely older gateway pauses its own journal writes, refuses to activate the link, and (after `_MAX_CONSECUTIVE_HELLO_MISMATCHES` consecutive failed matches across core respawns) `_supervise_core` stops respawning and the health sweep reports the link `degraded` with a remedy.
- Given a frame of unknown type or an undecodable line, when either side receives it, then a WARNING names the type (best-effort) and the connection is never silently skipped/dead.
- Given `SteerFrame`, `StopFrame`, `QueryRunningFrame`, `RunningStateFrame`, when this story lands, then they are deleted with every reference and test, and `protocol_version` is bumped.

## Design Notes

**Why the gateway doesn't self-restart here (the largest scope decision in this story):** `review-adversary.md` M11/C3's adopted fix text says the gateway "pauses its own journal and identity writes until its code matches `schema_head`, then re-execs." Implementing that literally requires the gateway to survive its own `os.execv` (which drops its listening UDS socket and the current core's connection to it, both non-inheritable by Python's PEP 446 default) AND requires teaching `core`'s frame loop to treat "gateway connection dropped" as "wait and reconnect" rather than its current, universal "gateway hung up → tear myself down" assumption (`_core_frame_loop`'s own docstring: "Ends when the gateway hangs up (clean EOF) — that drives the core's graceful teardown"). That second half is an architectural inversion this story does not make. Instead: the gateway (the only side that, in this codebase, is *provably* older by the tiebreak rule whenever protocol_version/migration match but the digest doesn't, since core is definitionally freshly spawned from current on-disk code) refuses, pauses, and — after repeated pointless core respawns confirm the problem is the gateway's own staleness — reports `degraded` with a remedy telling the operator to restart the gateway process. This is logged as `deferred-work.md` DW-11 (full automatic gateway self-restart) for a future story once core's reconnect-tolerance exists.

**Why `_supervise_core` (not `GatewayLink`) owns the retry-limit decision:** `GatewayLink` already tracks `consecutive_hello_mismatches` (needed for the health contributor regardless); `_supervise_core` is the ONLY place that decides whether to keep calling `spawn_core` at all, so it is the natural, minimal place to consult that same counter and stop — no new coordination primitive needed between the two.

**Why the digest-only tiebreak favors "gateway is older":** protocol_version and migration-number mismatches have a real, symmetric ordering (either side can genuinely be behind). A registry-digest-only mismatch (same protocol_version, same migration level, different registered event types) has no such ordering — a hash isn't comparable. But this codebase's process model breaks the symmetry: `core` is *always* a fresh subprocess exec'd from current on-disk code (at initial spawn, at every crash-respawn, and at every `CodeWatcher`-triggered self-restart — `orchestrator.py:4686`'s own comment: "Gateway/mono never arm" the self-restart triggers `core` has). `gateway` is the one process that runs for arbitrarily long stretches without ever reloading its own code. So on a digest-only split, gateway is the one holding stale in-memory registrations — never core.
