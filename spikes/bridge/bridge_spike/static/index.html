Bridge TLS Spike — Trust Ceremony

This device is talking to the Bridge spike over HTTPS using a per-install ephemeral CA that signed exactly one certificate for this install's .local host name. The CA's private key was destroyed the moment that certificate was signed — it is never written to disk and never kept around.

If your browser showed a certificate warning, trust the CA first using the steps below, then reload this page.

iOS

  1. Open the CA certificate file the terminal printed a path for when the kit started (AirDrop it to this device).
  2. Settings → General → VPN & Device Management → select the profile → Install.
  3. Settings → General → About → Certificate Trust Settings → enable full trust for the new CA.
  4. Reload this page.

Android

  1. Copy the CA certificate file the terminal printed a path for when the kit started onto the device.
  2. Settings → Security → Encryption & credentials → Install a certificate → CA certificate.
  3. Confirm the install-time warning (installing a CA certificate is intentional here).
  4. Reload this page.

Desktop Chrome

  1. macOS: open the CA cert in Keychain Access, set it to "Always Trust".
  2. Linux: copy it into /usr/local/share/ca-certificates/ and run update-ca-certificates, or import it via certutil into ~/.pki/nssdb for Chrome/Chromium's own NSS store.
  3. Restart the browser, then reload this page.

Renewal

If the owner runs the kit's renewal command, a new CA fingerprint is printed. Remove the old CA from this device's trust store and repeat the steps above for the new one — the old certificate keeps working only until you do.
